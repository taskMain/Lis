# 命令出参整改矩阵

> 用途：记录 UML 命令契约中同步出参的审查结果，作为后续 UML 和 DTO 参考图修改清单。
>
> 当前状态：参考草稿/设计登记；代码、OpenAPI、API Client 和运行验证尚未开始，本文不是正式业务契约，也不作为源码完成证据。

## 统一判断原则

| 原则 | 当前结论 | 状态 |
| --- | --- | --- |
| 领域事件不能替代同步接口出参 | 外部调用方需要的即时结果必须在命令出参或响应 DTO 中表达 | 已确认 |
| 匹配查询返回业务数据 | RequestRecognitionMatchesCommand 必须返回匹配记录、匹配项及匹配内容；成功无匹配时返回空集合 | 已确认 |
| 写入/提交类命令的成功结果 | 成功或幂等成功返回 Boolean=true，失败抛业务异常，不以 false 表示失败 | DesignConfirmed |
| 内部实体命令 | 不是医院接入契约，可由 Facade 内部使用 ID、数量或 Ack；不要求对外响应 DTO | 建议 |
| 空成功与 Boolean=true 的取舍 | 当前版本统一采用 Boolean=true，暂不引入 OperationSuccessResponse | DesignConfirmed |

## C. 聚合内部实体命令

这些命令由 Facade 协调或属于聚合内部操作，不直接作为医院接入契约。它们仍需在实现设计中约定内部返回值，但不必为每个命令创建对外 Response DTO。
