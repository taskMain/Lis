# 阶段 3 前端测试矩阵

本文件只记录测试前计划，不记录通过结果。实际执行命令、结果、证据与残余风险写入 [阶段测试报告](../testReport.md)。环境值引用项目环境规范，不在此复制。

两个页面分别为平台管理员页「互认项目金额维护」（路由 `recognition-amounts`）与医院管理员页「本院区互认项目金额」（路由 `branch-recognition-amounts`）；两条宿主链路都必须从宿主登录页与宿主菜单进入。

| 编号 | 页面或能力 | 身份与前置数据 | 操作及边界 | 预期页面、请求和业务状态 | 层级 |
|---|---|---|---|---|---|
| C1 | 平台管理员页范围选择 | 平台管理员身份；组织下有医院与院区 | 进入页面并依次切换组织、医院、院区 | 三级均可选；每次变化按新范围重载列表；不自动发起写请求 | Component/Host |
| C2 | 平台管理员页请求内容 | 同上 | 单击刷新或切换范围 | 查询请求携带组织、医院、院区三个值；保存请求同样携带三个值 | Component |
| C3 | 医院管理员页范围选择 | 医院管理员身份；可信组织与医院非空；另备一份**可信院区缺失**的身份上下文 | 进入页面；再以可信院区缺失的上下文重复一次 | 组织与医院以只读方式展示；只渲染院区下拉；院区默认取可信院区；**可信院区缺失时不下拉默认选中，须显式选择后才允许提交，且不发出空值参数** | Component/Host |
| C4 | 医院管理员页请求内容 | 同上 | 单击刷新或切换院区 | 查询与保存请求只携带院区与标准项目编码，不含组织与医院 | Component |
| C5 | 列表字段集合 | 已保存与未保存金额各一行 | 观察表头与行数据 | 展示标准项目编码、标准项目名称、组织名称、医院名称、院区名称、当前金额、金额状态、配置状态、当前不可用原因；不展示组织/医院/院区编码，不展示最后修改时间与最后修改人 | Component/Host |
| C6 | 未配置呈现 | 该行从未保存金额 | 观察该行金额列 | 显示"未配置"标记，金额无数值 | Component/Host |
| C7 | 零元与未配置区分 | 一行金额为 `0.00`，另一行未配置 | 同屏观察两行 | 零元按已配置金额呈现（`0.00`），与"未配置"标记明显不同 | Component/Host |
| C8 | 金额输入校验 | 任意行 | 输入负数、三位小数、空值后提交 | 行内提示且 `invalid`；零写请求；弹窗与输入保留 | Component/Host |
| C9 | 金额保存成功 | 互认配置存在；合法金额 | 提交合法金额 | 保存请求 `200`；弹窗关闭；列表重载并显示新金额 | Component/Host |
| C10 | 金额保存失败 | 服务端拒绝的场景（下一行列出具体两类） | 提交后观察 | 显示业务拒绝文案；弹窗与输入保留；不刷新列表、不误报成功 | Component/Host |
| C11 | 保存被拒绝的两类前置 | ①当前组织无该标准项目互认配置；②请求院区不属于可信医院 | 分别在两个页面提交 | 均收到业务拒绝；页面呈现一致，零脏写 | Host |
| C12 | 同值重复保存 | 已有金额 | 回填当前值后不改直接提交 | 仍发送请求并按成功处理；列表重载后值不变 | Host |
| C13 | 写成功但刷新失败 | 已有金额；受控注入只让列表请求失败 | 提交修改 | 显示"写入已成功，数据待刷新"与重试入口；不出现保存失败提示；写入结果未丢失 | Host |
| C14 | 读取失败 | 受控注入让列表请求失败 | 单击刷新 | 保留已有数据；显示待刷新提示；写入入口禁用；重试后恢复 | Host |
| C15 | 组织不可用 | 可信上下文缺少组织或医院 | 进入医院管理员页 | 显示阻断提示；全程零业务请求；不伪造组织、不发写请求 | Host |
| C16 | 排序 | 同一组织多个互认配置 | 观察列表顺序 | 按标准项目编码升序 | Component/Host |
| C17 | 空态 | 该组织无互认配置 | 进入页面 | 显示空态文案；列表请求成功返回空集合 | Component/Host |
| C18 | 当前不可用原因 | 分别仅停用分类、仅停用分组、仅停用标准项目 | 每次刷新后观察 | 分别显示"所属分类已停用""所属分组已停用""标准项目已停用"；三层启用时显示空 | Host |
| C19 | 配置自身停用 | 互认配置停用、目录全启用 | 观察该行 | 配置状态显示停用；原因列为空，不被配置停用占用 | Host |
| C20 | 停用状态下仍可维护金额 | 目录或配置停用 | 提交金额 | 保存成功；状态与原因列不因此改变 | Host |
| C21 | 范围切换与未保存输入 | 已打开金额弹窗并输入未提交 | 切换医院或院区 | 未保存输入被清空；不带着旧范围输入提交 | Component |
| C22 | 范围真实数据量与不分页 | 实际业务规模数据 | 连续操作 | 未出现卡顿、请求超时或内存问题；未新增分页 | Host |
| C23 | 组件加载失败提示 | 受控注入让组织服务选项请求失败 | 进入页面 | 组件显示自身错误提示；页面不重复提示、不新增错误拦截器；不进入可写状态 | Host/Component |
| C24 | 累计 API Client 契约 | 后端契约稳定 | 执行生成并核对 | 净增四个本阶段端点；阶段 1 与阶段 2 已交付端点保留；`/auth/login` 保持排除；`src/index.ts` 未被覆盖；包 typecheck 与 build 通过 | Component |
| C25 | 运行时配置 | 开发配置含 `baseApiBaseUrl` | 启动子应用 | 组织与医院院区选项从平台 Base 服务取得；`config.json` 未被改动；生产地址未在本阶段引入 | Component |
| C26 | 宿主链路 | 真实宿主身份；两个菜单子项已授权 | 从宿主登录页登录后分别从菜单进入两个页面 | 两个页面在新标签载入并完成首屏加载；劫持生效（资源来自本地开发地址）；Console 无业务错误 | Host |

C13、C14 与 C23 需要受控构造手段（只让目标请求失败并向子应用 `window` 注入一次性钩子，验证后立即还原），构造方式与恢复步骤必须在测试报告中逐条记录；不得为此新增生产测试入口或修改生产代码。C22 与 C26 依赖负责人已配置菜单与角色授权；菜单未授权时记 `Blocked`，不以本地直达替代。
