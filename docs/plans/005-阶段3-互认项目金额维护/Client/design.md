# 阶段 3 前端设计

## 页面与交互

本阶段交付两个页面，名称与路由由本项目提供，菜单子项与授权由负责人在权限系统配置；页面不实现角色判断，也不做权限二次确认。两个页面与「互认项目」页统一（S3-D22～S3-D28）：页头三级范围、筛选区与地址栏参数、四栏层级列视图、行内金额编辑与状态机制（平台管理员页院区恒定单值与两道防线，医院管理员页院区恒为登录院区）。

| 页面 | 菜单名称 | 路由 | 数据范围 |
|---|---|---|---|
| 平台管理员页 | 互认项目金额维护 | `recognition-amounts` | 组织、医院可切换，院区恒定单值，取值随请求提交 |
| 医院管理员页 | 本院区互认项目金额 | `branch-recognition-amounts` | 组织与医院取可信上下文并固定展示，院区恒定单值 |

两个页面都从宿主登录页与宿主菜单进入，不提供本地直达入口。

**页头。** 标题右侧展示当前登录范围的三级名称（组织、医院、院区），单行纯文字「组织名 / 医院名 / 院区名」，不展示编码：名称超长单行省略、悬停经 Tooltip 展示全文；某级名称缺失或反查失败时该级显示「未知」，不回退编码；名称尾部自带「（编码）」后缀时剔除。组织名称取自可信范围查询返回的组织名称；医院、院区名称按登录上下文编码经基础目录接口反查（与 `@dy/auth` 同源认证适配器自动携带宿主登录令牌），反查失败属接口错误、由宿主统一提示，页面不自行提示。页头范围固定展示登录范围，不随筛选区选定范围变化——选定范围由筛选区选择器表达（平台管理员页）。页头不设纯图标刷新按钮，刷新能力由筛选区的空条件提交承担（S3-D25）。

**范围选择（S3-D22）。** 平台管理员页的分级范围用 `@dy/components-base` 的 `BaseScopeSelector`：组织、医院可切换，院区恒定单值——院区始终恰好一个值、控件不可清空、永不为空发请求：可信院区（`getBranchID()`）存在且属于当前组织、医院 → 院区选中它；可信院区缺失 → 院区取当前组织、医院下的第一项；切换组织或医院 → 院区自动重取（可信院区属于新范围则选中它，否则选新范围第一项），随即按新范围重载列表。医院管理员页**不提供院区选择**（2026-10-10 修订，原「本侧院区可选、三档解析」口径作废）：组织、医院、院区恒取可信上下文（`LoginUserManager` 的 `orgId`/`hosId`/`getBranchID()`），查询与保存的院区参数恒为登录院区；登录院区变化（宿主重新签发 token）视为范围变化，直接整表重读、不弹确认框。院区为空属权限配置错误：页面不伪造院区、不回退默认院区、不进入整页阻断；受适配层「空院区拒绝构造请求」的既有契约约束，登录院区缺失时页面零业务请求并以空态说明，不做全院查询。
- 可信组织或医院缺失（登录凭证缺失，或组织、医院编码任一空白）→ **两个页面都整页阻断**：只渲染标题与一条错误 Alert（带图标，文案说明无法读取当前登录组织或医院、已阻断本页查询与操作），不渲染筛选区与列表、不发出任何业务请求（C15），不伪造组织、不降级为空值；院区缺失不进入该阻断，由接口报错经宿主提示（原「可信组织或医院缺失时逐级取第一项仅适用平台管理员页」的回退规则作废）。
- 可信组织与医院齐备时，页面进入即按默认规则完成范围解析并自动加载列表，不存在「范围未选全」的空态。

**筛选区（S3-D25）。** 查询区为 `Form layout="inline"` 行内表单（超宽自动换行），由「关键字输入框 + 金额状态与互认配置状态两个 `Segmented` + 行尾按钮组」构成，查询与重置按钮在行内最后一个 `Form.Item` 内并排。关键字以输入原文为草稿，点击查询按钮或在输入框内回车时按该关键字向服务端查询（S3-D26），返回值即匹配集合，本地不再按关键字判定；输入框的清空动作同时清空输入原文与已生效关键字并触发一次空条件读取（空条件提交等价于刷新）。「重置」恢复默认条件（清空关键字草稿、两个状态回默认档）并按默认条件重新读取一次，路由参数按默认值回写。两个状态 Segmented 切换即生效、只在服务端结果上本地裁剪、不触发读取、不下推服务端：金额状态（全部/已配置/未配置）取读模型 `IsAmountConfigured`，互认配置状态（全部/启用/停用）取 `ConfigurationStatusText` 对应的状态值。不设独立刷新控件；查询按钮为逐字规格主按钮（`type="primary"`、`SearchOutlined` 图标、`autoInsertSpace={false}`、`htmlType="submit"`、文字「查询」），读取在途时进入 `loading` 形态，行内操作一并禁用。已生效的关键字与两个状态回写本页路由地址的查询参数（`keyword`、`amountStatus`、`configurationStatus`）：进入页面按参数初始化，条件变化后用替换当前历史项的方式回写，输入原文不写入；页面嵌在宿主工作区里时参数落在子应用路由地址上。

**列表（S3-D23、S3-D24）。** 横向四栏层级列视图全平铺（类型｜分类｜分组｜项目），无折叠控件，款式同「互认项目」页（S2-D16）：类型格与分类格纵向跨其名下全部行以表达从属关系；层级格按 `content-visibility: auto` 声明离屏跳过渲染。行集是当前范围已建立互认配置的标准项目；行的类型、分类、分组由列表查询实时关联标准目录交付（读模型字段不变），层级归类与跨行在适配层完成，服务端仍按标准项目编码升序（S3-D18），视图内组间按类型、分类、分组归类排序、组内按编码升序。项目行字段：标准项目编码＋名称、当前金额、金额状态徽标、互认配置状态、当前不可用原因；互认配置状态中文取服务端返回值（`ConfigurationStatusText`），本地兜底只用于契约字段缺失；行内不展示组织名称、医院名称、院区名称（页头已展示），不展示组织编码、医院编码、院区编码，不展示项目类型，不展示最后修改时间与最后修改人。

**未配置与零元必须可区分。** 未配置行金额位置显示"未配置"标记（`IsAmountConfigured=false`、金额无值）；`0.00` 按已配置的正常金额展示。两者不得用同一呈现。

**金额行内编辑（S3-D27）。** 每行的金额是行内就地编辑入口，款式同「互认项目」页可互认时间行内编辑：点击当前金额值（含"未配置"标记）进入编辑，回车保存、Esc 取消；金额使用数字输入且限制为不小于零、最多两位小数；校验不通过时以页面消息提示（`message.useMessage()` 实例的 `message.error`，holder 挂页面根部），表格单元格内不渲染校验红字，零写请求、输入保留；同值照常提交；编辑器以当前行的金额值为键重新挂载，后台刷新交付新值后回填当前值；目标行离开当前行集时不渲染编辑态；提交成功后给出保存成功消息（`message.success`）、收起编辑态并整表重载；提交失败保留编辑态与输入，拒绝文案由宿主统一展示，页面不自行捕获写失败。目录或互认配置停用不影响行内编辑入口，只影响"当前不可用原因"与配置状态列的显示。

**加载、失败与状态机制（S3-D28）。** 页面首次进入按默认范围自动加载。加载期间禁用写入。读取失败时保留已有数据、结束加载态并进入不可写状态，页面**不渲染错误横幅**，错误由宿主统一提示，重试经查询区的查询按钮（2026-10-10 修订，原读取失败横幅作废）；写成功但随后的刷新失败时，仍按写成功呈现并保留"写入已成功，数据待刷新"门禁横幅（承载维护操作暂不可用状态与恢复入口），允许重试刷新，不显示为保存失败。范围切换时清空未保存输入与旧范围数据，目标范围读取失败不得进入其可操作状态。

状态机制按页面分两式（2026-10-10 修订，医院管理员页原「确认框 + 三层比对」两道防线随院区选择移除作废）：平台管理员页保留两道防线——可信范围变化（宿主重新签发 token）且存在未保存内容时弹组织变化确认框：「放弃并切换」清空并加载新范围，「取消」保留内容并进入待切换提示态（再次确认或未保存内容消失后自动切换），未保存内容判定口径为行内编辑正在编辑的行仍在当前行集；保存发起前现读可信组织、医院、院区与页面应用范围比对，已变化或现读不到即零写请求并在行内就地给出可见原因；用户主动切换范围维持静默清空未保存输入（C21），不弹确认。医院管理员页无选定范围可滞留：可信范围（含登录院区）变化时直接清空未保存输入并按新范围整表重读，不弹确认框；保存发起前现读可信组织或医院，读不到即零写请求并以页面消息给出可见原因，保存请求以提交时生效的院区发出，随后渲染按现登录院区切换重读。组织未对齐期间两页都不回退展示旧范围结果、也不允许对旧范围发起写入。

**排序与分页。** 服务端按标准项目编码升序；本阶段不分页（S3-D8）。

**空态与计数口径。** 该范围零互认配置时显示空态文案；有条件但未命中时显示未命中空态文案；页脚报当前显示条数（「共 N 项」，按生效筛选后的可见行计数）。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。保存使用 `SaveOrganizationHospitalBranchRecognitionAmount`（平台管理员页）与 `SaveBranchRecognitionAmount`（医院管理员页）；查询使用 `QueryRecognitionAmountList` 与 `QueryBranchRecognitionAmountList`，两个查询各带可选 `keyword`（S3-D26，页面条件为空时不携带）。适配层负责把生成的 Request/ReadModel 转换为稳定视图模型：列表侧交付列视图模型（层级归类、跨行计算、行字段），页面不直接扩散生成的 Kiota 类型，也不经手第二套契约来源。两个金额查询的既有 `standardProjectCode` 入参保留、新页面不再使用。

**新增运行时配置与依赖。** 子应用新增 `@dy/components-base@0.1.4` 与 `@dy/api-client-base@0.1.39` 两个依赖（不使用会与现有 `@dy/auth@0.1.39` 形成双实例的 `0.1.28` 组合），新增 `src/runtimeConfig.ts` 承载 `RuntimeConfig`（`apiBaseUrl`、`baseApiBaseUrl`），在入口调用一次 `configureBaseComponents({ baseUrl: baseApiBaseUrl })`；`public/config.development.json` 增加 `baseApiBaseUrl`，开发值取 `http://183.224.180.166:35001`。生产配置文件本阶段不改（S3-D13）。`client/pnpm-workspace.yaml` 增加 kiota overrides，统一到 `1.0.0-preview.103`；`pnpm-lock.yaml` 现存 kiota `.102` 与 `.103` 并存，overrides 落地后须实测 `typecheck`/`build` 确认依赖树不冲突，若冲突则回退 overrides 并登记为已知依赖形态。

开发值 `http://183.224.180.166:35001` 与后端 `IOrganizationAppService` 代理的 Host 同值，也与环境规范第 1 节「外部系统地址」行登记的"用户信息 / 组织信息 / 系统参数 / 字典 → `http://183.224.180.166:35001`"一致；环境规范第 1 节把"对外依赖的平台 Base API"列为待配置项。**本阶段不判定该地址的可用性**，只登记其取值来源；批次 1 必须以真实调用确认，确认前范围下拉不得视为已验证。

**组件既有行为与本页的应对。** `BaseScopeSelector` 的 `selectFirstOption` 默认为 `false`：仅为非受控（或显式传 `selectFirstOption=true`）时才会为对应级自动选中第一项并触发变更回调，受控时不回调。本页仍把范围值受控保存、只在用户明确提交时发送写请求，因此不因自动选中而自动写入；范围变化时清空未保存的金额输入。该组件在加载失败时调用 antd 静态 `message.error`，且 `BaseScopeSelectorProps` 不提供错误处理 prop、包也未导出错误回调；页面不新增错误类型、拦截器或绕过框架的错误提示，也不重复提示同一失败。**院区恒定单值的实现要求**：范围值由页面按 S3-D22 规则受控解析（可信院区优先、级联取第一项），切换组织或医院后自动重算院区值；`BaseScopeSelector` 是否提供禁用清空的属性由实施时按包实际导出核对，核对结论记入阶段报告；组件属性不满足时先回报再定替代方案，页面不自造第二套选择控件。

**API Client 累计生成。** 保留阶段 1 已交付 F01 接口、阶段 2 已交付 F02 接口与本阶段稳定契约（两个金额查询的 Request 新增可选 `keyword`，端点清单不变），排除后续阶段接口与 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、可空性、枚举与无残留后续端点。生成入口、配置与 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

## 已接受风险

- 不分页及重审条件以阶段决策 S3-D8 为准，不另设判据；四栏列视图全平铺的纵向长度沿用同一口径，出现可复现卡顿、超时或内存问题才重审。
- `BaseScopeSelector` 在非受控时自动选中首项、使用静态 `message.error`、无错误回调 prop 或错误回调导出，均为组件既有行为，本阶段不改动组件源码；本页以受控范围值规避自动写入；「不可清空」属性有无为实施时核对项。
- 可空枚举筛选形态（S3-D14）：本页不下推枚举筛选，也不手改生成物；两个状态 Segmented 只做本地裁剪，取值来自读模型布尔与文本字段，不触碰生成物枚举。生成管线侧由对应阶段管理。
