# 阶段 3 前端设计

## 页面与交互

本阶段交付两个页面，名称与路由由本项目提供，菜单子项与授权由负责人在权限系统配置；页面不实现角色判断，也不做权限二次确认。两个页面与「互认项目」页统一（S3-D22～S3-D29）：页头三级范围（仅医院管理员页）、筛选区与地址栏参数、四栏层级列视图、行内金额编辑与状态机制（平台管理员页院区恒定单值与两道防线，医院管理员页院区恒为登录院区）；两个金额页共用一份列表视图组件（S3-D29），页面只保留数据接线外壳。

| 页面 | 菜单名称 | 路由 | 数据范围 |
|---|---|---|---|
| 平台管理员页 | 互认项目金额维护 | `recognition-amounts` | 组织、医院可切换，院区恒定单值，取值随请求提交 |
| 医院管理员页 | 本院区互认项目金额 | `branch-recognition-amounts` | 组织与医院取可信上下文并固定展示，院区恒定单值 |

两个页面都从宿主登录页与宿主菜单进入，不提供本地直达入口。

**页头（S3-D23，2026-10-12 修订，2026-10-13 修订（第三轮）按共用组件承载）。** 平台管理员页页头只保留标题与副标题，不展示组织、医院、院区范围——该页正文自带三级范围选择器，页头重复展示同一信息，页面也不再发起页头范围展示所需的读取。医院管理员页维持原口径：标题右侧展示当前登录范围的三级名称（组织、医院、院区），单行纯文字「组织名 / 医院名 / 院区名」，不展示编码：名称超长单行省略、悬停经 Tooltip 展示全文；某级名称缺失或反查失败时该级显示「未知」，不回退编码；名称尾部自带「（编码）」后缀时剔除。组织名称取自可信范围查询返回的组织名称；医院、院区名称按登录上下文编码经基础目录接口反查（与 `@dy/auth` 同源认证适配器自动携带宿主登录令牌），反查失败属接口错误、由宿主统一提示，页面不自行提示。页头范围固定展示登录范围，不随筛选区选定范围变化。该展示由共用列表视图组件的页头插槽承载（S3-D29），展示内容与口径不变。两个页面的页头都不设纯图标刷新按钮，刷新能力由查询区的空条件提交承担（S3-D25）。

**范围选择（S3-D22）。** 平台管理员页使用机构范围选择器：组织、医院可切换，院区可选且为单值；选项存在时选定一个院区，范围不完整时不发金额业务请求：可信院区（`getBranchID()`）存在且属于当前组织、医院 → 院区选中它；可信院区缺失 → 院区取当前组织、医院下的第一项；切换组织或医院 → 院区自动重取（可信院区属于新范围则选中它，否则选新范围第一项），随即按新范围重载列表。医院管理员页**不提供院区选择**（2026-10-10 修订，原「本侧院区可选、三档解析」口径作废）：组织、医院、院区恒取可信上下文（`LoginUserManager` 的 `orgId`/`hosId`/`getBranchID()`），查询与保存的院区参数恒为登录院区；登录院区变化（宿主重新签发 token）视为范围变化，直接整表重读、不弹确认框。院区为空属权限配置错误：页面不伪造院区、不回退默认院区、不进入整页阻断；受适配层「空院区拒绝构造请求」的既有契约约束，登录院区缺失时页面零业务请求并以空态说明，不做全院查询。
- 平台管理员页在已认证的工作身份下展示范围选择器；登录组织、医院、院区仅在属于对应可选项时作为默认值，缺失或不属于选项时逐级选择第一项。任一级选项为空或尚未加载完成时保留范围选择器并显示范围未完整状态，不发送金额查询、保存或导出请求；选项加载失败沿用组件错误提示。未认证时不发业务请求。医院管理员页可信组织或医院缺失时整页阻断：只渲染标题与错误 Alert，不渲染筛选区与列表、不发业务请求。
- 平台管理员页在组织、医院、院区选项均可确定后按选定范围自动加载列表；医院管理员页按登录范围加载。

**筛选区（S3-D25，2026-10-13 修订（第三轮），两个页面为同一形态）。** 查询区只承载关键字输入框与金额状态筛选两个条件：关键字以输入原文为草稿，输入框右侧内嵌查询图标按钮（`type="text"`、`SearchOutlined` 图标、`aria-label="查询"`、`autoInsertSpace={false}`），点击图标或在输入框内回车时按该关键字向服务端查询（S3-D26），返回值即匹配集合，本地不再按关键字判定；输入框的清空动作同时清空输入原文与已生效关键字并触发一次空条件读取（空条件提交等价于刷新）。金额状态筛选以行内文字标签「金额状态」加 `Select` 承载（全部/已配置/未配置，取读模型 `IsAmountConfigured`）；互认配置状态筛选为贴在列表上沿的页签（Tabs，全部/启用/停用，取 `ConfigurationStatusText` 对应的状态值），款式与「互认项目」页配置状态页签相同（S2-D21），页签底边与列表容器边框重合。两个状态筛选都切换即生效、只在服务端结果上本地裁剪、不触发读取、不下推服务端；切换配置状态页签时收起进行中的行内编辑并放弃未保存输入。两个页面都不设「重置」控件与独立「查询」主按钮，不设独立刷新控件；读取在途时框内查询图标进入 `loading` 形态，行内操作一并禁用。查询区版面口径与「互认项目」页一致：控件间距 8px、外边距 16px 0 12px，关键字输入框宽 320px。原医院管理员页 2026-10-10 行内表单口径（`Form layout="inline"`、两个 `Segmented`、行尾查询与重置按钮）作废。两个页面的已生效关键字与两个状态都回写本页路由地址的查询参数（`keyword`、`amountStatus`、`configurationStatus`）：进入页面按参数初始化，条件变化后用替换当前历史项的方式回写，输入原文不写入；页面嵌在宿主工作区里时参数位于子应用路由地址上。

**导出（S3-D30，经 S3-D29 共用列表视图组件承载）。** 导出按钮由共用列表视图组件承载在配置状态页签行的右侧：可见文本「导出」、可访问名称「导出互认项目金额」，为标准按钮语义，键盘焦点顺序随 DOM 顺序，两个金额页与「互认项目」页三页同位同款；列表其余区块（列头、页脚计数）不因导出能力变化。门控与状态：医院管理员页可信组织或医院缺失的整页阻断态不渲染列表区，导出按钮不存在；平台页当前选定范围未完整（组织、医院、院区未选全）或处于待切换提示态（确认框取消后）时禁用且零请求——此时导出所取范围与页面展示不一致，与既有写门控同口径；本院区页登录院区缺失时按钮随空态禁用且零请求（该页不整页阻断、无待切换提示态——院区恒随登录院区，不存在「选定范围滞后于可信范围」的前提）；两页读取失败、写入后刷新失败三态内同样禁用零请求（页面数据不可靠，恢复以重试为先）；列表读取在途与仅行内编辑进行中（无范围变化）不限制导出（导出为只读链），既有写门控（读取在途禁用行内操作与写入口）不因导出改变。点击导出的行为两页一致：平台页提交当前选定的组织、医院、院区三值，本院区页提交点击时刻现读的登录院区（现读值与已应用不一致时零请求），关键字取已生效值；金额状态下拉与配置状态页签档位不参与请求；在途按钮进入 loading 并防重复；取得字节后经共享下载模块 `src/shared/exportFileDownload.ts` 触发浏览器保存，文件名分别为「互认项目金额维护 + `yyyyMMddHHmmss`（发起时刻）+ `.xlsx`」与「本院区互认项目金额 + `yyyyMMddHHmmss` + `.xlsx`」，保存后释放对象地址；失败时结束 loading、保留已有列表与筛选、不误刷新、不误报成功，错误提示由宿主统一展示，页面不解析错误响应体（零记录业务拒绝同样走宿主提示，服务端不生成空文件）；导出动作与条件不写入本页路由查询参数（导出不是页面视图状态，S3-D25 的地址栏参数只承载筛选）。

**列表（S3-D23、S3-D24）。** 横向四栏层级列视图全平铺（类型｜分类｜分组｜项目），无折叠控件，款式同「互认项目」页（S2-D16）：类型格与分类格纵向跨其名下全部行以表达从属关系；层级格按 `content-visibility: auto` 声明离屏跳过渲染；列表由 antd `Table` 承载，两个页面的行高、单元格间距、表头底色、边框、圆角与悬停底色的取值与「互认项目」页列表样式一致（2026-10-12 修订，平台管理员页与「互认项目」页列表的间距与位置口径统一；2026-10-13 修订（第三轮），医院管理员页经共用列表视图组件接入同一套样式覆写，原「维持原有 antd `Table` 默认样式口径」作废）；列宽与配套版面同样以「互认项目」页为准（2026-10-13 修订）：类型列 88px、分类列 186px、分组列 208px、当前金额列 190px、互认配置状态列 130px、当前不可用原因列 190px，项目列弹性填充，横向滚动基准 1252px（行内编辑态保存与取消为图标按钮，编辑控件回归当前金额单元格内；同日二次修订，当前金额列由 140px 改 190px，编辑态输入框完整显示八位整数加两位小数的金额）；表格上沿外边距 14px；项目编码颜色 `#6b7280`、字号 12px（编码与名称同行的布局保留）；互认配置状态徽标颜色取同一推导出口 `configurationStatusTagColor`（启用 success、停用默认、未知 warning）；页脚计数靠左排列、上间距 12px、等宽数字。行集是当前范围已建立互认配置的标准项目；行的类型、分类、分组由列表查询实时关联标准目录交付（读模型字段不变），层级归类与跨行在适配层完成，服务端按项目类型、分类名称、分组名称、标准项目名称逐级升序交付（S3-D18），视图按服务端行序依次折叠分组，前端不再本地重排。项目行字段：标准项目编码＋名称、当前金额、互认配置状态、当前不可用原因（2026-10-12 修订，删除金额状态徽标列：当前金额列的「未配置」标记与数值已完整表达配置与否，状态列与之一一重复）；互认配置状态中文取服务端返回值（`ConfigurationStatusText`），本地兜底只用于接口约定字段缺失；行内不展示组织名称、医院名称、院区名称（平台管理员页范围由范围选择器承载、医院管理员页由页头展示），不展示组织编码、医院编码、院区编码，不展示项目类型，不展示最后修改时间与最后修改人。

**未配置与零元必须可区分。** 未配置行金额位置显示"未配置"标记（`IsAmountConfigured=false`、金额无值）；`0.00` 按已配置的正常金额展示。两者不得用同一呈现。

**金额行内编辑（S3-D27）。** 每行的金额是行内就地编辑入口，款式同「互认项目」页可互认时间行内编辑：点击当前金额值（含"未配置"标记）进入编辑；入口为非编辑态可点的值按钮（悬停显现边框与底色，与可互认时间值按钮同款，2026-10-12 修订，原链接按钮款式作废）；编辑态为「输入框＋保存＋取消」（与可互认时间编辑器同款；2026-10-13 修订，保存与取消改为图标按钮——保存取 `CheckOutlined` 图标、取消取 `CloseOutlined` 图标，可访问名保留既有「保存金额：…」「取消修改金额：…」文案，图标按钮以同一文案作悬停提示（含按钮处于禁用态时）；2026-10-13 修订（第三轮），医院管理员页接入同一编辑器，原纯输入原款式（回车保存、Esc 取消、无按钮）作废），回车与保存按钮走同一条提交路径、Esc 与取消按钮都只放弃本次编辑；金额使用数字输入且限制为不小于零、最多两位小数；校验不通过时在编辑器内就地显示提示（与可互认时间编辑器的就地提示同款，2026-10-12 修订，原页面消息 `message.error` 口径作废；2026-10-13 修订（第三轮），医院管理员页同步接入列内就地提示）；零写请求、输入保留；同值照常提交；编辑器以当前行的金额值为键重新挂载，后台刷新交付新值后回填当前值；目标行离开当前行集时不渲染编辑态；提交成功后给出保存成功消息（`message.success`）、收起编辑态并整表重载；提交失败保留编辑态与输入，拒绝文案由宿主统一展示，页面不自行捕获写失败。目录或互认配置停用不影响行内编辑入口，只影响"当前不可用原因"与配置状态列的显示。

**加载、失败与状态机制（S3-D28）。** 页面首次进入按默认范围自动加载。加载期间禁用写入。读取失败时保留已有数据、结束加载态并进入不可写状态，页面**不渲染错误横幅**，错误由宿主统一提示，重试经查询区的查询入口（框内查询图标按钮）（2026-10-12 修订；2026-10-13 修订（第三轮），重试入口两个页面都经框内查询图标按钮；2026-10-10 修订，原读取失败横幅作废）；写成功但随后的刷新失败时，仍按写成功呈现并保留"写入已成功，数据待刷新"门禁横幅（承载维护操作暂不可用状态与恢复入口），允许重试刷新，不显示为保存失败。范围切换时清空未保存输入与旧范围数据，目标范围读取失败不得进入其可操作状态。

状态机制按页面分两式（2026-10-10 修订，医院管理员页原「确认框 + 三层比对」两道防线随院区选择移除作废；2026-10-13 修订，两页提交前复核拦截原因的呈现口径写实为页面消息，与两页统一提示出口一致）：平台管理员页保留两道防线——可信范围变化（宿主重新签发 token）且存在未保存内容时弹组织变化确认框：「放弃并切换」清空并加载新范围，「取消」保留内容并进入待切换提示态（再次确认或未保存内容消失后自动切换），未保存内容判定口径为行内编辑正在编辑的行仍在当前行集；保存发起前现读可信院区，与页面应用该范围时记录的可信院区比对（组织、医院两层不参与本页比对；院区层按缺失值参与比对，两侧同为缺失视为一致），不一致即零写请求并以页面消息给出可见原因（`message.error` 就近提示）；用户主动切换范围维持静默清空未保存输入（C21），不弹确认。医院管理员页无选定范围可滞留：可信范围（含登录院区）变化时直接清空未保存输入并按新范围整表重读，不弹确认框；保存发起前现读可信组织或医院，读不到即零写请求并以页面消息给出可见原因，保存请求以提交时生效的院区发出，随后渲染按现登录院区切换重读。组织不一致期间两页都不回退展示旧范围结果、也不允许对旧范围发起写入。

**排序与分页。** 服务端按项目类型、分类名称、分组名称、标准项目名称逐级升序，名称相同按标识兜底（S3-D18）；本阶段不分页（S3-D8）。

**空态与计数口径。** 该范围零互认配置时显示空态文案；有条件但未命中时显示未命中空态文案；页脚报当前显示条数（「共 N 项」，按生效筛选后的可见行计数）。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。保存使用 `SaveOrganizationHospitalBranchRecognitionAmount`（平台管理员页）与 `SaveBranchRecognitionAmount`（医院管理员页）；查询使用 `QueryRecognitionAmountList` 与 `QueryBranchRecognitionAmountList`，两个查询各带可选 `keyword`（S3-D26，页面条件为空时不携带）。适配层负责把生成的 Request/ReadModel 转换为稳定视图模型：列表侧交付列视图模型（层级归类、跨行计算、行字段），页面不直接扩散生成的 Kiota 类型，也不经手第二套契约来源。两个金额查询的既有 `standardProjectCode` 入参保留、新页面不再使用。

**新增运行时配置与依赖。** 子应用新增 `@dy/components-base@0.1.4` 与 `@dy/api-client-base@0.1.39` 两个依赖（不使用会与现有 `@dy/auth@0.1.39` 形成双实例的 `0.1.28` 组合），新增 `src/runtimeConfig.ts` 承载 `RuntimeConfig`（`apiBaseUrl`、`baseApiBaseUrl`），在入口调用一次 `configureBaseComponents({ baseUrl: baseApiBaseUrl })`；`public/config.development.json` 增加 `baseApiBaseUrl`，开发值取 `http://183.224.180.166:35001`。生产配置文件本阶段不改（S3-D13）。`client/pnpm-workspace.yaml` 增加 kiota overrides，统一到 `1.0.0-preview.103`；`pnpm-lock.yaml` 现存 kiota `.102` 与 `.103` 并存，overrides 落地后须实测 `typecheck`/`build` 确认依赖树不冲突，若冲突则回退 overrides 并登记为已知依赖形态。

开发值 `http://183.224.180.166:35001` 与后端 `IOrganizationAppService` 代理的 Host 同值，也与环境规范第 1 节「外部系统地址」行登记的"用户信息 / 组织信息 / 系统参数 / 字典 → `http://183.224.180.166:35001`"一致；环境规范第 1 节把"对外依赖的平台 Base API"列为待配置项。**本阶段不判定该地址的可用性**，只登记其取值来源；批次 1 必须以真实调用确认，确认前范围下拉不得视为已验证。

**组件既有行为与本页的应对。** `BaseScopeSelector` 的 `selectFirstOption` 默认为 `false`：仅为非受控（或显式传 `selectFirstOption=true`）时才会为对应级自动选中第一项并触发变更回调，受控时不回调。本页仍把范围值受控保存、只在用户明确提交时发送写请求，因此不因自动选中而自动写入；范围变化时清空未保存的金额输入。该组件在加载失败时调用 antd 静态 `message.error`，且 `BaseScopeSelectorProps` 不提供错误处理 prop、包也未导出错误回调；页面不新增错误类型、拦截器或绕过框架的错误提示，也不重复提示同一失败。**院区恒定单值的实现要求**：范围值由页面按 S3-D22 规则受控解析（可信院区优先、级联取第一项），切换组织或医院后自动重算院区值；`BaseScopeSelector` 是否提供禁用清空的属性由实施时按包实际导出核对，核对结论记入阶段报告；组件属性不满足时先回报再定替代方案，页面不自造第二套选择控件。

**API Client 累计生成。** 保留阶段 1 已交付 F01 接口、阶段 2 已交付 F02 接口与本阶段稳定契约（两个金额查询的 Request 新增可选 `keyword`，端点清单不变），排除后续阶段接口与 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、可空性、枚举与无残留后续端点。生成入口、配置与 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

## 已接受风险

- 不分页及重审条件以阶段决策 S3-D8 为准，不另设判据；四栏列视图全平铺的纵向长度沿用同一口径，出现可复现卡顿、超时或内存问题才重审。
- `BaseScopeSelector` 在非受控时自动选中首项、使用静态 `message.error`、无错误回调 prop 或错误回调导出，均为组件既有行为，本阶段不改动组件源码；本页以受控范围值规避自动写入；「不可清空」属性有无为实施时核对项。
- 可空枚举筛选形态（S3-D14）：本页不下推枚举筛选，也不手改生成物；两个状态 Segmented 只做本地裁剪，取值来自读模型布尔与文本字段，不触碰生成物枚举。生成管线侧由对应阶段管理。
