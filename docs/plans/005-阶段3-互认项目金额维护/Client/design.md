# 阶段 3 前端设计

## 页面与交互

本阶段交付两个页面，名称与路由由本项目提供，菜单子项与授权由负责人在权限系统配置；页面不实现角色判断，也不做权限二次确认。

| 页面 | 菜单名称 | 路由 | 数据范围 |
|---|---|---|---|
| 平台管理员页 | 互认项目金额维护 | `recognition-amounts` | 组织、医院、院区三级可切换，取值随请求提交 |
| 医院管理员页 | 本院区互认项目金额 | `branch-recognition-amounts` | 组织与医院取可信上下文并固定展示，院区可选 |

两个页面都从宿主登录页与宿主菜单进入，不提供本地直达入口。

**范围选择。** 两级范围都用 `@dy/components-base` 的 `BaseScopeSelector`：平台管理员页不传固定值，三级均可选；医院管理员页把 `@dy/auth` 的 `LoginUserManager.getOrgID()`/`getHosID()` 作为 `orgId`/`hosId` 固定传入（对应级不渲染下拉），只让院区可选，请求也只提交院区。院区默认值取 `LoginUserManager.getBranchID()`；**可信院区缺失时不下拉默认选中**，要求用户显式选择后才允许提交，且不把空值作为请求参数发出。可信组织或医院缺失时页面给出阻断提示、不渲染院区下拉、不允许提交，不伪造组织、不降级为空值、不发业务请求。

**列表。** 按当前范围展示该组织已建立互认配置的标准项目及其金额状态，列为：标准项目编码、标准项目名称、组织名称、医院名称、院区名称、当前金额、金额状态、互认配置状态、当前不可用原因。组织名称、医院名称、院区名称与标准项目名称都取服务端返回值；选择器自身的选项数据同时提供这三级的展示名称，两者由服务端统一保证一致。不展示最后修改时间与最后修改人，不展示组织编码、医院编码与院区编码。

**未配置与零元必须可区分。** 未配置行金额列显示"未配置"标记（`IsAmountConfigured=false`、金额无值）；`0.00` 按已配置的正常金额展示。两者不得用同一呈现。

**金额录入。** 每行提供独立的金额维护入口，使用弹窗录入并提交，与阶段 2 的编辑口径一致：金额使用数字输入且限制为不小于零、最多两位小数；校验不通过时给出行内提示且**不发送写请求**；提交失败保留弹窗与输入；提交成功后关闭弹窗并整表重载。目录或互认配置停用不影响本页维护入口，只影响"当前不可用原因"与配置状态列的显示。

**加载与失败。** 页面首次进入自动加载，并提供手动刷新。加载期间禁用写入。读取失败时保留已有数据、进入不可写状态并允许重试；写成功但随后的刷新失败时，仍按写成功呈现并提示"写入已成功，数据待刷新"，允许重试刷新，不显示为保存失败。范围切换时清空未保存输入与旧范围数据，目标范围读取失败不得进入其可操作状态。

**排序与分页。** 按标准项目编码升序；本阶段不分页（S3-D8）。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。保存使用 `SaveOrganizationHospitalBranchRecognitionAmount`（平台管理员页）与 `SaveBranchRecognitionAmount`（医院管理员页）；查询使用 `QueryRecognitionAmountList` 与 `QueryBranchRecognitionAmountList`。适配层负责把生成的 Request/ReadModel 转换为稳定视图模型，页面不直接扩散生成的 Kiota 类型。

**新增运行时配置与依赖。** 子应用新增 `@dy/components-base@0.1.4` 与 `@dy/api-client-base@0.1.39` 两个依赖（不使用会与现有 `@dy/auth@0.1.39` 形成双实例的 `0.1.28` 组合），新增 `src/runtimeConfig.ts` 承载 `RuntimeConfig`（`apiBaseUrl`、`baseApiBaseUrl`），在入口调用一次 `configureBaseComponents({ baseUrl: baseApiBaseUrl })`；`public/config.development.json` 增加 `baseApiBaseUrl`，开发值取 `http://183.224.180.166:35001`。生产配置文件本阶段不改（S3-D13）。`client/pnpm-workspace.yaml` 增加 kiota overrides，统一到 `1.0.0-preview.103`；`pnpm-lock.yaml` 现存 kiota `.102` 与 `.103` 并存，overrides 落地后须实测 `typecheck`/`build` 确认依赖树不冲突，若冲突则回退 overrides 并登记为已知依赖形态。

开发值 `http://183.224.180.166:35001` 与后端 `IOrganizationAppService` 代理的 Host 同值，也与环境规范第 1 节「外部系统地址」行登记的"用户信息 / 组织信息 / 系统参数 / 字典 → `http://183.224.180.166:35001`"一致；环境规范第 1 节把"对外依赖的平台 Base API"列为待配置项。**本阶段不判定该地址的可用性**，只登记其取值来源；批次 1 必须以真实调用确认，确认前范围下拉不得视为已验证。

**组件既有行为与本页的应对。** `BaseScopeSelector` 的 `selectFirstOption` 默认为 `false`：仅为非受控（或显式传 `selectFirstOption=true`）时才会为对应级自动选中第一项并触发变更回调，受控时不回调。本页仍把范围值受控保存、只在用户明确提交时发送写请求，因此不因自动选中而自动写入；范围变化时清空未保存的金额输入。该组件在加载失败时调用 antd 静态 `message.error`，且 `BaseScopeSelectorProps` 不提供错误处理 prop、包也未导出错误回调；页面不新增错误类型、拦截器或绕过框架的错误提示，也不重复提示同一失败。

**API Client 累计生成。** 保留阶段 1 已交付 F01 接口与阶段 2 已交付 F02 接口，加入本阶段稳定契约，排除后续阶段接口与 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、可空性、枚举与无残留后续端点。生成入口、配置与 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

## 已接受风险

- 不分页及重审条件以阶段决策 S3-D8 为准，不另设判据。
- `BaseScopeSelector` 在非受控时自动选中首项、使用静态 `message.error`、无错误回调 prop 或错误回调导出，均为组件既有行为，本阶段不改动组件源码；本页以受控范围值规避自动写入。
- 可空枚举筛选形态（S3-D14）：本页不下推枚举筛选，也不手改生成物；生成管线侧由对应阶段管理。
