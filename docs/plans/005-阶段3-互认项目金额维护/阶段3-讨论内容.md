## 当前基线

- 阶段编号：005。
- 阶段名称：互认项目金额维护。
- 业务范围：SRS F10。
- 业务层级：一个组织下有多个医院，一个医院下有多个院区；医院管理员管理的是**本医院下的多个院区**，不是单个院区。

- 端：跨端，管理端页面为「互认项目金额维护」与「本院区互认项目金额」两个页面（依据 `docs/plans/001-总体计划/design.md` 4.5 与 `impl.md` 第 6 节）。

## 执行状态与环境边界

1. **本阶段未修改** `server/` 或 `client/` 的实现文件；工作区中 `server/`、`client/` 的既有改动不由本阶段产生。
2. **环境无第二个组织**：跨组织的真实宿主面不可构造。因此跨组织用例（V29）以应用层证据为准并记 `AcceptedRisk`，真实宿主面记 `Blocked`（决策 S3-D20）。
3. 可复用的既有技术结论（不重复取证）：SqlMap 使用显式实体 scope + 业务 sqlId、不调用 `SetContext`；无 `[WorkUnit]` 的生产入口由框架 `EventBusActionUnitFilter` 统一 Flush；无 WorkUnit 入口的写入失败不回滚且事件队列失败即清空。
4. 数据库目标确认与建表按项目现行规则执行；未建表前不依赖目标表的集成测试。

## 现行业务事实（SRS / CONTEXT / UML 当前文本）

以下为既有权威文档的**当前**规定，不是本阶段新增决定。条目已按本阶段对上游的改动更新，引用前以原文为准。

1. 金额业务键为组织编码、医院编码、院区编码和标准项目编码；不保存院内项目编码、名称或项目对照（SRS F10 业务规则 1、3）。
2. 零元是有效配置；未配置金额按零元参与预计节省金额计算（SRS F10 业务规则 2、后置条件 2）。
3. 不建立独立金额版本、金额变更历史或历史金额重算；金额调整只影响之后成功保存的采纳处理结果（SRS F10 业务规则 4、后置条件 3）。
4. 只要组织级互认配置存在，标准目录或互认配置当前停用也允许查看和维护金额；停用不删除既有金额（SRS F10 业务规则 5）。
5. 金额为人民币，必填、不小于零、最多两位小数；未配置与零元必须区分展示（SRS「互认项目金额维护」页面要求 4）。
6. 查询只返回组织级互认配置已存在的标准项目；金额未配置时 `IsAmountConfigured=false`、当前金额无业务值（UML2 `RecognitionAmountManagementModule` 说明）。
7. 页面展示标准项目名称、组织名称、医院名称、院区名称、当前金额和未配置状态；不展示最后修改时间和最后修改人（SRS「用户界面」章「互认项目金额维护」页面要求 2）。
8. 命令出参统一 `Boolean=true`，失败抛业务异常（`docs/uml/命令出参整改矩阵.md` B 组）。
9. 组织、医院和院区的编码及名称由可信组织服务提供；互认平台只用编码定位业务归属，不另建组织主数据（`CONTEXT.md`「组织、医院和院区」）。
10. 权限系统负责菜单、接口和操作授权，互认平台不重复判断操作权限；平台保留的组织、医院和院区校验只用于可信业务归属与记录归属一致性（`CONTEXT.md`「角色与菜单授权」、SRS:298）。
11. 医院管理员只能维护**可信上下文所属医院及其院区**的金额；提交其他医院，或提交不属于该医院的院区时拒绝保存（SRS F10 备选流 1、UML1 命令规则 4、`CONTEXT.md`「角色与菜单授权」）。本阶段只做这一层校验，**不引入"院区级数据权限"概念**。
