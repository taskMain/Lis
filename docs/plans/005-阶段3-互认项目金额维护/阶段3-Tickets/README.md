## 约定

1. **`Blocked by` 只表达票与票之间的依赖。** 只存在部分依赖时（例如某票的静态面可先做、完整核对需等他票交付），须在 `Blocked by` 内注明该范围。外部前置不并入依赖图，由每票的「外部前置」行单独登记：包与依赖的实测构建、依赖安装、私服与外部服务可达、负责人建表、权限系统的菜单与角色授权。
2. **`Status` 是领取标签，不是测试状态。** 测试状态只用 `testing-baseline.md` 定义的六种（`NotRun`、`Passed`、`Failed`、`Blocked`、`PendingRetest`、`N/A`），且只写在阶段根 `testReport.md`。受前置阻断的票以「外部前置」行表达，不另用领取标签区分。
3. **勾选纪律**：勾选项只有在有实际执行证据后才可勾选，勾选时附命令或证据出处；票面不得出现 `Passed`、`验收通过`、`已完成` 这类无证据措辞。
4. **证据归档**：执行的命令、结果、证据与残余风险统一写入阶段根 `testReport.md`，票面不复制结果。
5. **矩阵口径**：矩阵编号可跨批次、跨票引用，按完整用例只统计一次；只完成某一层级不把整条用例记为通过。每票末尾的「口径」段声明本票覆盖的层级，票面层级名与矩阵层级列的对照见文末「层级词表对照」。
6. **不改设计与批次**：实现票不得改动阶段设计、实施批次表和矩阵编号；需要变更时先按项目规则更新设计并取得确认。
7. **测试数据纪律**：业务数据与状态只经正常业务接口（公开 AppService/API）或页面形成；禁止直接执行 SQL、使用数据库工具或脚本写库；禁止伪造重复主键、孤儿关联或违反业务约束的数据作为用例前置。
8. **建表与授权**：目标库与 schema 由负责人确认并执行建表；权限系统的菜单子项与角色授权由负责人配置；未就绪时相关用例记 `Blocked`，不以本地直达、构建成功或接口直测替代宿主验收。
9. **范围**：审查工作目录与另一条并行工作线（阶段 2 目录）不属于任何票的输入、输出或修改范围。
10. **状态查询**：当前执行状态、阻断前提与测试状态以阶段根 `testReport.md` 为准；本目录不维护状态快照。

## 层级词表对照

票面「口径」段使用执行语义的层级名，矩阵侧使用自己的层级列取值，两者对照如下：

| 票面层级名 | 对应矩阵层级列取值 | 票 |
|---|---|---|
| 应用层（外部服务接入、路径解析与归属校验） | `Application` | 01 |
| 契约、领域写入与应用编排层 | `Contract`、`Domain/Repository`、`Application` | 02 |
| 查询契约、原因派生与应用编排层 | `Query`、`Contract`、`Application` | 03 |
| DDL 静态面与 SqlMap 映射面 | `Static/DB`、`Repository/Static` | 04 |
| 依赖与运行时配置的组件层 | `Client/testPlan.md` 的 `Component` | 05 |
| 客户端契约与适配层的组件层 | `Contract`；`Client/testPlan.md` 的 `Component` | 06 |
| 页面与组件的组件层 | `Client/testPlan.md` 的 `Component` | 07 |
| 真实数据库与真实生产入口层 | `Static/DB`、`Framework/Integration`；矩阵「真实数据库」列为是 | 08 |
| 宿主面 | `Client/testPlan.md` 的 `Host` | 09 |
