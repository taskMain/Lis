# 02: 金额保存写入与事件

**What to build:** 平台管理员与医院管理员都能保存某个「组织-医院-院区-标准项目」的当前金额：没有记录就新建，有记录就覆盖，零元算「已配置」，同值重复保存仍按成功处理并登记事件。两个入口共用同一个领域命令与同一个「金额已保存」事件，差异只在取值来源——平台管理员的三级值全取请求并校验归属；医院管理员的组织与医院取可信上下文、院区取请求且必须属于可信医院。保存前提是该组织已建立该标准项目的互认配置；标准目录或配置停用不阻断金额维护。并发首次保存同一业务键由唯一索引兜底，数据库异常按原样向外传播，不自动重试、不替用户循环重放意图。写入最多一条语句，不引入工作单元、不手工开事务。

**Blocked by:** 01（外部组织服务接入与组织路径解析）

**Status:** ready-for-agent

**外部前置：** 票 01 交付的包引用与实测构建；真实数据库面另需负责人建表（见票 04）

- [ ] 首次保存新建恰好 1 行、返回成功并登记保存事件（V1）
- [ ] 覆盖已有金额只更新金额与操作字段，不累加（V2）
- [ ] 保存 `0.00` 成功，该行金额已配置为真，与未配置可区分（V3）
- [ ] 负数、超过两位小数、缺省或非数值被拒绝，无写入、无事件（V4-V6）
- [ ] 同值重复保存仍成功，更新操作信息并登记事件，不做无变更短路（V7）
- [ ] 当前组织未建立该标准项目的互认配置即拒绝保存（V11）
- [ ] 平台管理员入口采用请求的组织、医院、院区；操作人只来自可信上下文；请求不含操作人（V12）
- [ ] 医院管理员入口请求不含组织与医院；组织与医院取可信上下文；请求院区不属于可信医院即拒绝（V13、V30）
- [ ] 可信组织或医院缺失即拒绝，不降级为空值、不使用默认值（V14）
- [ ] 标准目录或互认配置停用后仍可保存金额（V15）
- [ ] 并发首次保存：唯一索引兜底、库中恰 1 行、无脏写、无事件，冲突返回业务拒绝（V16）
- [ ] 事件含四个业务键与当前金额；事件创建人与创建时间取自命令的操作人/操作时间；校验失败、影响 0 行、影响大于 1 行、唯一冲突均不登记事件（V25）
- [ ] 两个保存请求与读模型的字段、可空性与设计一致，且不返回作用域编码与最后修改字段（V26）
- [ ] 实体注释与语义按 F10 修正为「当前金额维护」，写入路径无累加运算（V28）
- [ ] 每个写入口最多一条写语句（插入或更新二选一）；不声明工作单元、不手工开启事务
- [ ] 先建立目标失败证据（RED）或静态失败证据；完成适用影响分析
- [ ] 适用测试、构建、静态检查通过；`git diff --check` 干净；代码 symbol 变化时执行 GitNexus `detect-changes`
- [ ] 证据记入阶段测试报告

**口径：** 本票覆盖层级为契约、领域写入与应用编排层；本票只覆盖所引用矩阵用例在该层级的证据，事务与并发面之外的真实数据库面由验收票承接；矩阵编号可跨批次引用，按完整用例只统计一次，只完成部分层级不记为通过。
