## 实施闸门（本项目铁律，逐条适用）

1. 开始前 `git status --short --branch`；不回退、不清理非本轮修改；不创建分支/提交（除非本轮明确授权）。
2. 代码 symbol 修改前执行 GitNexus upstream impact；`HIGH/CRITICAL` 先说明影响与验证方案。
3. 新行为先建立准确失败测试（RED）再实现；测试状态只用 Testing Baseline 枚举，无证据不写 `Passed`。
4. 数据库只读；造数走业务接口或页面。
5. 既有 `StandardProjectCode` 入参、保存链、读模型字段与全部既有页面行为不变；改动已交付接口语义前停止并回报。
6. 完成时执行适用测试、构建、静态检查、`git diff --check` 与变更影响检查；页面能力必须真实宿主验收，本地直达与构建成功不替代。
