# 阶段 6 票拆分审查要求

本文是阶段 6 票拆分（`阶段6-Tickets/`）审查任务的方向与纪律要求。审查方的审查结果不写入本文档；审查方任务分配时另行告知结果写入位置。

## 审查目的与定位

- 审查的目的是**补盲**：发现票拆分中遗漏、矛盾、不可执行与不可判定之处，尤其是拆分者未注意到、决策人也未注意到的信息。审查不是对票作者的评判，提出的问题不按「挑刺」对待。
- 票审查**不重新裁定设计决策**：设计文档已经多轮审查定稿，设计层面的分歧按设计文档已登记结论（含 AcceptedRisk 与确认偏差）核对。发现只指向两类问题——「票未忠实承载设计」与「票集合自身的问题」（完备性、依赖、可判定性、范围纪律）。
- 审查必须**客观、全面**：每条结论必须有可追溯的证据（票原文 + 设计依据出处），无证据的判断标注为「疑问」而非「缺陷」。
- 区分四类情况并在结论中明确归类：**票缺陷**（票与设计或票集合事实冲突）、**设计本身如此**（差异源于设计已登记事项，票承接正确）、**理解偏差**（审查方对设计或票的理解不足）、**疑问**（证据不足、需澄清）。只有「票缺陷」与经论证的「遗漏/风险」进入正式发现。

## 审查对象与范围

**审查对象**（唯一审查事实载体）：`docs/plans/008-阶段6-互认统计与导出/阶段6-Tickets/` 下 README 与全部票文件（票 00 至票 09）。

**审查依据**（对照基准，只读，不作为审查对象）：

- 阶段 6 设计文档全集：根 `design.md`（含 S6-D1 至 S6-D18 台账与上游同步范围）、`Server/design.md`（含验证矩阵 V1-V45）、`Client/design.md` 与 `Client/testPlan.md`（C1-C30）、根/`Server/`/`Client/` 三个 `impl.md`（批次与矩阵编号归属）、根 `testReport.md`。
- 上游文档（仅在核对「票的验收项是否有设计依据」时引用）：SRS F08/F09 与界面节、`CONTEXT.md`、UML 5、总体计划、`.agents/instructions/` 相关规范、阶段 4/5 先例。不直接审查上游符合性。

**排除范围**：

- `docs/plans/008-阶段6-互认统计与导出/阶段6-审查相关/` 目录内全部内容（审查方向与审查结果，不属审查对象）；
- `阶段6-讨论内容.md`（过程记录，不参与票审查）；
- 仓库代码实现（本阶段尚未开工，无实现可审）；
- 其他阶段的阶段文档（仅作依据引用，不审查其历史结论）；
- `var/` 等运行留存目录。

## 审查纪律（硬性）

1. **结果写入位置以任务分配为准**：审查结果只写入任务分配时指定的文档；除此之外不得新建、修改、删除任何文件。
2. **写入前清空上一轮结果**：每次向指定文档写入审查结果之前，必须先把该文档中上一轮审查遗留的全部内容清空，再写入本轮结果；写入后文档中不得残留任何旧编号、旧结论或旧口径。首轮写入时目标文档应为空或仅含占位结构。
3. **只读纪律**：除指定结果文档外，对仓库内一切文件只读；不得实施整改、不得修改审查对象或依据文档。
4. **独立审查**：不得参阅、引用或打听其他审查方的过程与结论；如任务分配附带分工维度，该分工不影响对本清单全部维度的通读。

## 发现输出格式

每条发现按以下结构编写，缺一要素不作为有效发现：

| 要素 | 要求 |
|---|---|
| 编号 | 本轮内连续编号（如 1、2、3），清空重写后重新编号 |
| 标题 | 一句话说明问题 |
| 类型 | 缺陷 / 遗漏 / 风险 / 疑问 / 建议 |
| 严重度 | 高 / 中 / 低（影响范围与对实施顺序的后果为依据） |
| 位置 | 票文件 + 段落或行号 |
| 证据 | 引用票原文 + 设计依据（文档 + 章节/行号）；差异源于设计已登记事项时写明该登记的 ID（如 S6-D5、S6-D18） |
| 影响 | 该问题不处理时的实际后果（阻塞哪个票、导致哪条验收无法判定等） |
| 建议方向 | 修复方向（不写具体实现，整改与否由后续流程决定） |

文档末尾必须附**覆盖声明**：已审查的维度、每个维度「有发现 / 无发现」的结论、未覆盖的范围及理由。「无发现」必须显式写出，不得省略。

## 审查维度清单

以下维度为每个审查方的基线，分工不改变通读义务：

1. **票 ↔ 设计忠实性**：每张票的正文与验收项是否忠实承载设计口径与 S6-D 决策——无走样（数字、字段、层级、批次）、无遗漏（设计承诺的行为面无票承接）、无自创口径（票中出现设计没有的规则）、无依据替换（验收项引用的矩阵编号与设计层级相符）。AcceptedRisk 与确认偏差事项（S6-D3 占比分母、S6-D5 导出上限、S6-D9 脱敏、S6-D16 内存峰值、S6-D17 科室维度不可对账、S6-D18 范围口径）必须按登记口径承接，不得擅自改为硬验收条件、不得删除、不得加码。
2. **票集合完备性与编号归属**：V1-V45 与 C1-C30 是否全部被票覆盖且**唯一归属**、无跨票重复；S6-D1 至 S6-D18 是否全部被票承接或显式归属；票间共用的前置（索引 DDL 由负责人执行、宿主可用、两测试身份）是否声明一致。
3. **阻塞边与依赖正确性**：票间「Blocked by」与设计批次依赖一致；无环、无缺失、无多余硬阻塞；可立即开工的前沿票判断正确；前端票对后端运行态的需求以「非硬阻塞」方式表述。
4. **验收项可判定性**：每条验收项有明确通过判据（矩阵编号或设计段落）；无正常业务不可达的前置混入（对照 S6-D18「不构造空组织/医院/院区账号」口径）；无「证据见后续票」式空话——每张票的验收在其自身范围内可判定。
5. **范围纪律**：票不得引入设计排除的能力（排除项 17 趋势图/医生排名/绩效、排除项 18 其他导出格式/借导出解除脱敏，以及脱敏算法、独立匹配记录导出、跨组织统计）；不得扩张或收缩已登记口径（10 万行上限、不限日期跨度、行内占比分母、六个顶层读模型计数、10 方法/11 端点等）。
6. **票大小与可实施性**：单票工作量适合一个上下文窗口完成；按阻塞顺序执行时每票独立可验证、可交付；无「宽重构」型票混入——若发现某票的改动面符合宽重构特征（单次机械改动波及全部调用方），要求按 expand–contract 说明补充分批策略。

## 误报自控

- 提出「票缺陷」前，先在设计文档中核对是否已有承接或登记：差异源于设计已登记事项（AcceptedRisk、确认偏差、不构造口径）时，归类「设计本身如此」并在覆盖声明中说明，不进入发现列表。
- 提出「遗漏」前，先在全部票文件与设计文档中检索是否已在别处承接（含显式归属其他票、声明由后续票承接的面）。
- 票之间的措辞差异若语义一致，不进入发现；仅当该差异导致验收判据歧义时才立项。
- 对设计先例或框架行为不确定处，标「疑问」并写明需要澄清的具体事实，不臆断为缺陷。
