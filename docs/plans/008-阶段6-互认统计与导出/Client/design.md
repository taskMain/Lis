# 阶段 6 前端设计

## 页面与交互

本阶段交付四个页面，名称与菜单由本项目提供，菜单子项与授权由负责人在权限系统配置；页面不实现角色判断、不做权限二次确认，能进入页面即视为已获授权。四个页面的路由字符串在页面实现阶段确定，设计阶段只固定「四个入口、四条独立路由、四个页面、四个菜单」这一结构。四个页面共用查询区、两类导出入口与匹配记录弹窗；使用方两页共用主从双栏主体（汇总列表、明细卡片、明细表、原因筛选），提供方两页共用承接方核查版式（两行式分组清单、归属链卡头、使用方首列明细，S6-D24），差异在取值来源与固定文案。

| 页面 | 菜单名称 | 数据范围 |
|---|---|---|
| 平台使用方页 | 使用方互认使用统计 | 组织、医院、院区取值随请求提交（另可选提供方组织、医院、院区） |
| 本院使用方页 | 本院互认使用统计 | 本侧组织、医院、院区恒为可信上下文（院区为登录院区）；提供方医院、院区可选筛选（组织固定为可信组织） |
| 平台提供方页 | 提供方医院被互认统计 | 来源与接收两组组织、医院、院区取值随请求提交 |
| 本院提供方页 | 本院被互认统计 | 提供方组织与提供方医院取可信上下文固定，提供方院区为登录院区；使用方医院、院区可选筛选（组织固定为可信组织） |

四个页面都从宿主登录页与宿主菜单进入，不提供本地直达入口。

**页面结构。** 四个页面复用同一套统计页主体，路由、菜单、可信范围与页面标题不变。平台两页自上而下分为四段：页头、范围区（使用方与提供方对称双列卡片，中间仅一个指向使用方的箭头，不显示方向说明文字）、查询行、主从区。本院两页为：页头（标题、副标题与右侧登录范围条）、单行对侧筛选、查询行、主从区；不显示固定侧范围卡片与双列方向标记。查询行统一承载关键字、项目类型、统计时间区间与查询按钮。使用方两页的主从区为两列：左列为汇总列表卡片，宽 400px（容器 1200–1279px 时 360px），承载汇总维度下拉、共 N 行、导出汇总、分组列表与分页；右列为明细卡片，占剩余宽度，承载选中分组的标题与上下文、指标摘要、表格工具行明细类型切换、原因筛选、明细表与分页、导出明细。指标摘要为静态组合，四类明细数量只在该摘要出现一次；明细类型切换位于表格工具行右侧，标签只显示类型名称，不带数量；容器宽度小于 1200px 时改为单列堆叠，左列表在上、明细在下，选中行后把明细卡片滚入视口。提供方两页的主从区按 S6-D24 单独成版：左栏按容器宽度取 360px（1200–1279px）、400px（1280–1599px）、440px（≥1600px），承载汇总维度下拉、共 N 行、导出汇总、两行式分组清单与分页，分组行由主名称与归属次行组成，行尾计数块显示被互认次数，不绘制比较条；右明细卡卡头随汇总维度取值：医院维度为组织与医院两行，院区维度为组织、医院与院区三行，标准项目维度为标准项目名称与「编码 · 分类 / 分组」两行（名称缺失显示「未匹配标准项目」）；卡头右侧内联「被互认 N 次」与「导出明细」，卡头下只有一行上下文（统计时间、承接范围、明细总数），不设指标摘要条与独立工具行；容器宽度小于 1200px 时左栏退化为横向分组选择带（单格 168×112、单行横向滚动、分页压到带右端），明细卡独占下方主区。

**查询区与筛选提交式（2026-10-20 修订）。** 查询区与报告管理列表页同构（S6-D19）：`Form layout="inline"` 行内表单承载统一关键字输入框（可清空、输入原文提交，服务端按互认科室 ID/名称、标准项目编码/名称、互认医生 ID/姓名〔使用方明细〕任一前缀命中，空白视为未提供；占位按侧区分——使用侧「互认科室 / 互认项目 / 互认医生」、提供方「互认科室 / 互认项目」，提供方语句无医生列）、项目类型下拉、统计时间区间选择器（见「时间筛选」）与查询按钮（逐字规格 `type="primary"` + `SearchOutlined` + `aria-label="查询"` + `autoInsertSpace={false}` + `htmlType="submit"` + 文字「查询」）。原互认科室 ID、标准项目编码、互认医生 ID、不采纳原因代码四个独立手输框与「重置」按钮作废：不设重置，关键字与项目类型可清空、清空后经查询生效（与报告管理列表页同口径）。筛选控件改动只进入草稿条件、不发起请求；点「查询」把草稿提交为已生效条件（只提交范围、时间、关键字与项目类型），**一次提交同时重读汇总与明细两个区**；同条件再次提交等价刷新（保留左页、选中行、明细类型与原因，汇总与当前明细各重读一次）。汇总维度、明细类型是视图切换，原因是明细筛选，三者都即时生效、不进草稿；明细类型与原因只影响明细读取。翻页基于已生效条件自动读取。页头不设独立刷新按钮，首次进入自动加载，手动重读经查询按钮（条件为空时提交等价于刷新）。

**汇总列表。** 左侧列表每页 8 行，页容量固定、页容量选择器隐藏，服务端分页；卡头为汇总维度下拉（使用方：医院/院区/互认科室/标准项目；提供方：提供方医院/提供方院区/标准项目）、共 N 行与导出汇总。行内三行：主名称为医院名、院区名、科室名或标准项目名（标准项目名前带项目类型标签）；次行为组织名、`医院 · 组织`、`科室 ID · 院区 · 医院`、`编码 · 分类 / 分组`；指标行使用方为提醒、采纳、不采纳、引用，提供方为被互认。行按服务端顺序展示，不重排当前页。列表区域内部滚动（`max-height: 560px`），分页控件固定在卡片底部；页码变化后选中清空并自动选新页第 1 行。左侧指标数字只读展示，不响应点击。选中行底色 `colorPrimaryBg`、左侧 2px 主色竖条，并以 `aria-pressed` 表达选中态。同期互认率与预计节省金额在右侧指标摘要展示，原因次数与占比在右侧明细工具行展示；互认科室名称取服务端返回值，页面不按 ID 自行拼接或改名。互认科室维度行的提醒与同期互认率不含未反馈项，跨维度数字不可直接对账，页面不对不同维度的数字做合计校验。提供方两页的汇总列表按 S6-D24 呈现：每页 8 行、页容量固定、页容量选择器隐藏；行由主名称（维度决定取提供方医院名、院区名或标准项目名）与归属次行组成，行尾计数块以等宽数字显示被互认次数并在下方标注「被互认」；维度选项为提供方医院、提供方院区与标准项目；选中态与使用方页一致（底色、左侧 2px 主色竖条、`aria-pressed`）；行内不绘制比较条、不展示四类明细数量。

**选中与下钻。** 左列表首次加载完成后自动选中当前页第 1 行并读取提醒明细；列表为空时右侧显示空态「从左侧选择一行查看明细」。点击另一行选中该行，明细类型回提醒、原因清空、明细回第 1 页；点击已选中行等价于重试当前明细。下钻条件由已生效筛选与选中行派生，不回写查询条件，左侧列表不因下钻收窄；用户关键字始终保留，精确分组字段按侧别补充：使用方医院维度取该行组织与医院，院区维度取该行组织、医院与院区，互认科室维度另取 `RecognitionDeptId`，标准项目维度取 `ItemType` 与 `StandardProjectCode`；提供方取提供方组织、医院、院区与 `StandardProjectCode`。平台页未选组织时按该行组织补齐。右侧指标摘要与表格工具行页签切换明细类型，只重读明细；金额随采纳明细展示。汇总数字与明细计数不一致时以服务端为准并允许重查，页面不本地重算。

**状态复位。** 查询提交（条件变化）后汇总回第 1 页、选中清空并自动选新列表第 1 行、明细回第 1 页、明细类型回提醒、原因清空；同条件再次提交保留左页、选中、明细类型与原因，汇总与当前明细各重读一次。切换汇总维度回第 1 页并清空选中，重新加载后自动选第 1 行；切换左列表页码清空选中并自动选新页第 1 行；点击另一行将明细类型回提醒、原因清空、明细回第 1 页；切换明细页签保留选中、明细回第 1 页，原因只在原页签内保留；选择原因明细回第 1 页；可信范围变化时统计页主体整体复位，维度回医院、选中清空。

**明细与分页。** 明细卡片标题行展示选中分组的主名称与次行说明，右侧为「导出明细」；指标摘要使用方为提醒、采纳、不采纳、引用四项数量与同期互认率、预计节省金额两项静态指标，提供方为被互认一项摘要，指标值取选中汇总行、不额外请求；明细类型切换位于表格工具行，页签只显示类型名称、不重复数量。上下文行展示统计时间、承接范围与共 N 条，明细类型由表格工具行页签表达，不重复写入上下文；不采纳原因生效时追加原因名称。页签为提醒、采纳、不采纳、引用，只显示类型名称，不重复指标摘要中的条数；提供方无页签。明细工具行内提供原因下拉，选项为「全部原因（N 次）」与各原因「名称（N 次，X%）」，只影响明细查询与明细导出，不影响左侧汇总。明细表使用服务端分页，每页 10 条，页容量固定、页容量选择器隐藏，显示总数；分页控件位于表格下方，改变页码回到该页第 1 条。使用方明细表按汇总维度动态列：时间、患者、项目类型、项目、提供方、科室 / 医生、反馈结果、操作；医院维度且平台页未锁院区时增加「使用方院区」列，其他维度或本院页已锁院区时省略固定侧列。提供方明细表按 S6-D24 与 S6-D25 单独成列：首列为使用方（组织、医院、院区三行式、固定在左侧），其后依次为标准项目（名称主行、编码次行）、项目类型、分类、分组、互认时间、患者（姓名主行、证件号码次行）、科室 / 医生（科室主行、医生次行）；医院维度且平台页未锁院区时增加「提供方院区」列，其他维度或本院页已锁院区时省略固定侧列。标准项目名称、项目类型文本、分类名称与分组名称由服务端随行返回，页面不回查标准目录；项目名称为空显示「未匹配标准项目」，编码缺失显示「—」，分类或分组缺失时该段整体省略；使用方项目类型独立成列，项目列显示标准项目名称与编码次行，标准项目名称为空时显示「未匹配标准项目」。归属路径按三行式展示：单元格内为组织名、医院名与院区名，只显名称不显示编码，名称缺失的行显示「未知」，不回退编码（名称取服务端返回值，页面不做前端反查）。未反馈行在提醒明细中显示「未反馈」，处理结果列留空；页面不把未反馈行本地标记为不采纳。患者姓名与证件号码按服务端返回值原样展示（S6-D9），页面不做二次处理。使用方明细行支持行展开，展开展示就诊类型与流水号、证件号码、互认时间、预计节省金额、引用时间、引用科室、引用医生、不采纳原因与补充说明、匹配记录标识；表头固定，容器不足时横向滚动，表格 `tableLayout='fixed'` 保证列宽不被长名称撑开。使用方明细行提供只读「查看互认匹配记录」入口，弹窗展示组级信息、就诊、未反馈或已处理状态、决定主体与全部匹配项；弹窗不提供报告内容、PDF 或影像入口。

**导出入口。** 左卡片卡头设「导出汇总」，右卡片标题行设「导出明细」。`导出汇总` 使用已生效筛选与当前汇总维度，导出类型使用方 1、提供方 6，导出行顺序与页面一致；`导出明细` 使用已生效筛选、选中行的精确分组字段、当前明细类型与当前原因，导出类型使用方 `detailType + 1`、提供方 7，无选中行时禁用。两个入口共用一个 `exporting` 状态，导出期间都禁用，防止重复提交；导出继承页面当前查询条件与数据权限，导出全部记录而非当前分页，不带分页条件，导出条件不写地址栏。成功后按浏览器保存文件，失败由宿主统一提示（零记录时宿主提示「当前条件下无可导出数据」，超过 10 万行上限时由宿主统一提示缩小查询条件），页面不弹本地接口错误、不误刷新列表。

**时间筛选（2026-10-20 修订）。** 统计时间使用 antd `DatePicker.RangePicker`，与报告管理列表页同一控件与预设形态：预设「今天 / 近 7 天 / 近 30 天」，区间不可清空（`allowClear={false}`），必填，提交起止日期（`yyyy-MM-dd`），页面不拼接时分秒、不写入时区偏移；不限制最大跨度，页面不做跨度本地校验。进入页面与范围切换复位的默认时间窗为近 30 天（今天往前 29 天到今天的滚动窗，与「近30天」预设同义，即最近一个月），原「当月 1 日至当天」默认作废；首次读取恒带时间边界。

**页头与间距（2026-10-20 修订）。** 统计页配套 CSS 与报告管理列表页同值（S6-D19）：页头行左右结构、下间距 20px；范围选择行下间距 16px；查询行下间距 4px；汇总维度与明细类型工具行下间距 8px。原「统计页无配套 CSS、间距由内联样式承载」口径作废；颜色与控件形态一律组件库默认 token，不覆盖样式。

**范围取值。** 平台页组织、医院、院区三级均可选；来源组组织、医院、院区三级均可选。本院两页不显示固定侧范围卡片与双列方向标记，固定侧由页头登录范围条表达；本院使用方页只渲染「提供方筛选」一行，含提供方医院、提供方院区两个下拉；本院提供方页只渲染「使用方筛选」一行，含使用方医院、使用方院区两个下拉；对侧组织固定为可信组织、不渲染组织级选择器，不选表示全部对侧机构，筛选改动进草稿、点查询生效。本院页**不提供本侧院区选择**（2026-10-10 修订，原「本侧院区可选、为空即全院」口径作废）：本侧组织、医院、院区恒取可信上下文，请求院区参数恒为登录院区；院区为空属权限配置错误，页面不伪造院区、不做全院查询、不进入整页阻断，适配层拒绝构造请求、页面零业务请求并以空态呈现，恢复正确的权限配置后按登录院区重读。本院页页头为左右结构（2026-10-20 修订，与「本院区互认项目金额」「本院报告管理与历史版本」页同一结构）：左侧为大标题与描述副标题，右侧以单行纯文字承载当前登录范围条（「组织名 / 医院名 / 院区名」），范围条不再出现在筛选行；平台页页头不承载范围条。范围条不展示编码：名称超长单行省略、悬停经 Tooltip 展示全文；某级名称缺失或反查失败时该级显示「未知」，不回退编码。组织名称取自可信范围查询返回的组织名称；医院、院区名称按登录上下文编码经基础目录接口反查（与 `@dy/auth` 同源认证适配器自动携带宿主登录令牌），反查失败属接口错误、由宿主统一提示。可信组织或医院缺失（登录凭证缺失，或组织、医院编码任一空白）时页面整页只渲染标题与一条错误 Alert（带图标，文案说明无法读取当前登录组织或医院、已阻断本页查询与操作）、不渲染后续选择器、不发业务请求，不伪造组织、不降级为空值；院区缺失不进入该阻断。页面不做本地归属判断，越界选择由服务端拒绝。

**枚举展示。** 项目类型、就诊类型、处理结果、明细状态等取值中文取服务端随行返回的文本字段；筛选与表单选项使用集中缓存的枚举元数据；页面不新写中文映射表，本地兜底只用于契约字段缺失。

**加载与失败。** 页面首次进入自动加载，手动重读经查询区的查询按钮（页头不设独立刷新按钮）；四个页面为只读页面，失败面为汇总读取失败、明细读取失败、导出失败与弹窗读取失败四类。汇总读取失败保留旧列表、旧选中与旧明细；明细读取失败保留旧明细行、选中行与指标摘要；两种情况都结束加载态，页面**不渲染错误横幅**，错误由宿主统一提示，重试经查询按钮或重新选行。汇总与明细各自维护在途序号，只采纳最后一次响应；汇总重读时作废在途明细，避免旧行明细写回新汇总。汇总空页且总数大于 0 时按总数回退最后一页一次，明细同样；选中行在重读后不存在时清空选中并自动选新列表第 1 行，仍不存在则右侧空态。明细类型切换保留上一组明细行并以加载遮罩覆盖，新数据返回后整体替换，避免表格区域在加载期间先塌缩。已提交条件变化清空上一条件的数据与未提交筛选草稿。

## API 与组件

使用现有 API Client 上下文，不在页面创建客户端。查询使用八个查询端点（四能力 × 平台/本院），导出使用两个 POST 端点（返回文件字节），匹配记录弹窗使用单记录端点。适配层负责把生成的请求与读模型转换为稳定视图模型：平台/本院两个版本的分支收敛在适配层，页面组件不感知请求形态差异；分页响应在适配层收敛为页面分页模型，对页码、页容量与总数做安全整数校验；导出字节在适配层转为浏览器保存（沿用 PDF 下载模式）。页面不直接扩散生成的 Kiota 类型，不把患者证件号码等敏感条件写入地址栏。明细与明细导出请求增加系统填充字段：使用方 `RecognitionDeptId`、`StandardProjectCode`，提供方 `StandardProjectCode`；用户关键字继续以 `Keyword` 提交，字段由页面按选中行填充，不作为用户输入；汇总请求不变。2026-10-20 重开（S6-D19）：查询与导出请求以 `Keyword` 替换用户输入的互认科室 ID、标准项目编码、互认医生 ID 独立字段，API Client 累计重生成后同批核对字段集合；S6-D22 的精确分组字段同批核对。

## 已接受风险

- 左列表与明细表的宽度依赖宿主内容区；容器小于 1280px 时堆叠，明细表在 1200–1279px 两列形态下允许横向滚动（C56）。
- 明细精确分组字段依赖服务端接口约定同步（V50–V52）；未同步前不得上线该交互。
- 汇总行与明细行的同口径以服务端返回为准；页面不做本地合计或重算。
- 统计页无趋势图、排名、绩效评价；不新增导出格式。
- 真实宿主验收必须从宿主菜单进入四个页面（C58），本地直达与组件测试不替代宿主验收。
- 患者姓名与证件号码在统计页、明细与导出的展示/导出为业务原值（S6-D9），后续如需收紧按新决策处理。
- 日期不限最大跨度，超大数据量的加载时长取决于后端索引与数据量，页面只呈现加载态。
- 平台页的跨组织数据在本地环境不可构造时，真实宿主面按阶段 4 `S4-D39` 同类口径降级（应用层证据为准）。
- 提供方两页明细共 8 至 9 列，1280px 档内容区约需横向滚动 130px（首列固定）；列宽与宿主内容区的匹配度依赖实际容器宽度。
- 提供方明细的四项字段依赖后端读模型与 OpenAPI 同步（S6-D25）；未同步前提供方明细不得上线标准项目名称、项目类型、分类与分组四列。
