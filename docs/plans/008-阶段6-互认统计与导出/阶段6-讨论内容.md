# 阶段 6 互认统计与导出（F08+F09）讨论内容

本文记录阶段 6 设计前的讨论过程：事实依据、设计决策树、各轮拷问与结论。结论以最终决定为准；本文件不作为阶段设计文档，阶段设计写入 `design.md`。

## 1. 事实依据

### 1.1 需求与上游契约（已确认，无需再问）

- SRS F08（`docs/需求规约SRS.md:1917-2101`）：指标定义、业务时间归属（提醒按匹配生成时间、采纳/不采纳/金额按互认时间、引用按实际引用时间）、同期互认率=采纳/提醒（提醒为零不计算）、不采纳原因占比分母为范围内不采纳总次数、来源侧只计次数不计金额、按平台标准目录维度统计、不推断未反馈、短周期比率可超 100% 按原始展示、患者姓名与证件号码脱敏、不下钻到报告/PDF/影像。
- SRS F09（`:2103-2230`）：仅 `.xlsx`；导出 7 类（接收侧汇总/提醒/采纳/不采纳/引用明细 + 来源侧汇总/明细）；不受页面分页限制；明细按匹配项一行展开、组级字段重复；明细带匹配记录 ID 与匹配项 ID；无记录时不生成文件；不含报告结构化内容、PDF 标识、影像地址；不单独导出匹配记录。
- SRS 界面节（`:2418-2463`）：两个统计页 + 导出入口；接收侧筛选含日期、医院、院区、互认科室、互认项目，互认医生仅作明细条件；来源侧医院管理员只看本院数据。
- 排除项 17/18：不建趋势图/医生排名/绩效；不建 CSV/PDF 导出或借导出解除脱敏。
- UML `docs/uml/5-RecognitionStatisticsUiQuery.wsd`：四个汇总维度枚举（医院/院区/互认科室/标准项目）、接收侧明细类型枚举（提醒/采纳/不采纳/引用）、导出类型枚举（7 项）、六个查询契约（接收侧汇总/明细、来源侧汇总/明细、导出、匹配记录视图）、七个读模型（含 `StatisticsExportFileReadModel`、`RecognitionMatchRecordReadModel`）。
- `CONTEXT.md:28`：互认科室按「院区 + 业务 ID」归类，汇总展示名称取范围内互认时间最晚一条处理结果的科室名称；无医生排名绩效。
- 总体计划 §4.8：无新表；统计与导出**必须后端分页**；页面含「接收医院互认使用统计」「来源医院被互认统计」「统计导出入口」与只读匹配记录入口。

### 1.2 既有实现先例（探索实测）

- 范围校验先例（阶段 4 报告列表，`MedicalRecognitionReportQueryAppService.Reports.cs:33-104`）：平台管理员入口按请求组织/医院/院区筛选（只经组织路径解析校验存在、启用与父子归属，**不锁可信组织**）；医院管理员入口组织/医院取自可信上下文注入、院区取请求且必须属于可信医院。两个入口两套请求类型。
- 分页公共设计（`.agents/instructions/pagination.md`）：内嵌 `page` 对象、`PageResultDto<T>`、`PageQueryWindow`、计数与取页同筛选、Provider 适配层承载窗口、稳定唯一排序、前端共享分页控件。
- PDF 下载先例（`ReportPdfFileController.cs:120-132`）：应用层返回 `ReportPdfDownload(Stream, FileName)`，控制器 `File(stream, contentType, fileName)`；Kiota 生成 `ArrayBuffer`，前端适配层 Blob + `<a download>`。
- 脱敏现状：仅患者电话在应用层脱敏（`MaskPhoneNumber`，保留末 4 位，`Reports.cs:638-645`）；姓名与证件号码在阶段 4 完整返回。**统计场景姓名与证件的脱敏算法无既有实现、无上游细则**。
- Excel 生成能力：仓库内无任何 Excel 库；本机 NuGet 缓存有 **ClosedXML 与 NPOI**（EPPlus、MiniExcel 无缓存）；私有 NuGet 源不可达，新包只能来自本机缓存。
  - 勘误（2026-09-20）：私有源已于 2026-09-16 核实可用（见环境规范），上句『不可达』为更正前事实；ClosedXML 选型仍取本机缓存。
- 读模型占位：`Application.Contracts/ReadModels/` 下七个阶段 6 读模型已存在但多为 `object` 占位形态；查询契约与 SQL 映射均未建。
- 前端无任何统计/导出入口、路由或页面，需从零建四个页面与适配层。

## 3. 讨论轮次

### 第 1 轮（2026-09-20）

| 问题 | 结论 |
|---|---|
| Q1 数据范围模型 | 接收侧沿用阶段 4 双入口先例：平台管理员按请求组织/医院/院区（组织路径解析校验），医院管理员组织/医院取可信上下文、院区限可信医院；来源侧医院管理员锁定本院为来源医院，平台管理员按请求范围 |
| Q2 汇总行结构 | 每行 = 所选维度的一个分组值，未参与分组的维度字段为 `null`；维度枚举固定按 UML（接收侧 4、来源侧 3）；不做总计行 |
| Q3 不采纳原因汇总承载 | 嵌入每个汇总行（原因代码 + 次数 + 占比；该行不采纳为零时不计算）；`其他` 归入其他代码，补充说明只在明细与导出展示 |
| Q4 统计聚合层级 | SQL 层 `GROUP BY` 聚合，分页基于聚合后分组行计数；同期互认率与占比在应用层由行内次数计算；不建汇总中间表 |
| Q5 分页适用面 | 四个查询全部后端分页（公共分页形状）；匹配记录视图为按 ID 取单记录不分页；导出不分页 |
| Q6 日期范围语义 | 单一日期范围入参（`yyyy-MM-dd`，闭区间按本地日），每个指标按各自业务时间列独立过滤；日期范围必填 |
| Q7 日期最大跨度 | **不限跨度**；性能面以本阶段索引迁移批次缓解，登记 AcceptedRisk |
| Q8 Excel 生成库 | **ClosedXML**（本机缓存可用、MIT），集中入 `Directory.Packages.props` 并在使用工程显式声明；私有源不可达，不使用未缓存包 |
| Q9 导出端点与零记录行为 | POST + body（导出类型 + 全部查询条件），控制器返回 `File(stream, xlsx, fileName)`，沿用 PDF 下载先例；零记录业务拒绝「当前条件下无可导出数据」 |
| Q10 导出规模上限 | 封顶 10 万行，超限业务拒绝并提示缩小查询条件 |
| Q11 汇总导出行列 | 汇总导出 = 页面汇总行原样，含不采纳原因次数及占比 |
| Q12 患者脱敏算法 | **MVP 不实现统计脱敏**：统计页、明细与导出中的患者姓名、证件号码按业务原值返回；需同步权威文档（见第 2 轮 Q3） |
| Q13 匹配记录集合视图 | 按匹配记录 ID 取单记录，前端弹窗呈现；入口仅挂接收侧四类明细行 |
| Q14 前端下钻交互 | 汇总表 + 明细表同页上下联动：点击汇总行指标数字预填明细筛选；原因行点击加原因代码筛选；导出按钮沿用当前查询条件 |
| Q15 新增索引 | 同意；**以迁移文件落地**，命名与形态参照 `E:\MedSync\Dy.LisCenter\server\Dy.LisCenter.Repository\Scripts\Migrations`（`YYYYMMDD_<票号>_<描述>.sql`，必要时配 `_preflight`）；本阶段建议 `…_s6_statistics_indexes.sql`，最终列以查询设计为准，DDL 由负责人执行 |

### 第 2 轮（2026-09-20）

| 问题 | 结论 |
|---|---|
| Q1 端点形态 | 沿用阶段 4 双入口先例：查询契约声明 8 个方法（4 能力 × 平台/本院，各配独立请求类型，本院版请求不含组织/医院字段）；导出为 1 个方法 + 导出类型枚举 + 平台/本院两个请求形态（2 个端点）；匹配记录视图 1 个端点；合计 11 个新端点，角色由宿主菜单授权区分 |
| Q2 页面形态 | 建 4 个页面路由：「接收医院互认使用统计」「本院互认使用统计」「来源医院被互认统计」「本院被互认统计」，内部复用同一套组件；菜单与授权由权限系统配置 |
| Q3 脱敏决策的权威文档同步 | 已批准：SRS F08 后置条件 3、业务规则 25，F09 后置条件 2、业务规则 5，界面节通用要求 3、接收侧界面节、导出入口节，以及 CONTEXT.md 脱敏相关段，统一改为「MVP 不实现统计与导出场景的患者脱敏，姓名与证件号码按业务原值返回与导出」。已接受偏差登记：来源侧被互认明细向医院管理员展示其他医院患者完整姓名与证件（SRS 原文禁止）；排除项 18 在实现上无对象可解。阶段 7 排除项回归时复核 |

**补充规则（表结构变更双写）**：任何表相关变更必须同时落地两处——迁移文件（`Scripts/Migrations/`，命名参照 LisCenter 先例）与对应实体的建表脚本（`Scripts/mrec_*.sql`）同步更新，两者不得漂移；否则按最终建表脚本重建时会丢失变更。本阶段索引迁移须同步回写阶段 5 三份建表脚本。
