# 前端设计

总体范围及关键决策见 [阶段设计](../design.md)。本阶段不新增页面、路由与契约，核对对象为阶段 1–6 已交付的管理端页面。

## 页面与交互

- 走查页面清单（10 个，按宿主菜单项计）：标准项目目录维护（同一工作台合并承载「互认项目分类分组管理」与「标准医疗项目管理」两个界面节，S1-D20，单路由单菜单项）、互认项目管理、互认项目金额维护（平台管理员）、本院区互认项目金额（医院管理员）、报告管理（平台管理员）、报告管理与历史版本（医院管理员）、使用方互认使用统计、本院互认使用统计、提供方医院被互认统计、本院被互认统计（后四页随阶段 6 交付）。
- 开工时核对宿主菜单注册（两身份各自可见菜单清单）并与本清单比对（C11），走查身份按实际菜单授权分配：两身份各自走查其授权菜单覆盖的页面；矩阵中标注的身份为设计预期，以 C11 核对结果为准修正。
- 双入口页面的请求形态：平台入口页面提交组织/医院/院区请求值，本院入口页面不传本侧组织与医院（由可信上下文注入）。
- 患者信息展示：全部页面患者姓名、证件号码按业务原值展示；报告版本详情的联系电话按原值展示（S7-D8 仅推翻脱敏子口径，承载面与布局不变）；报告管理页版本详情的电话原值展示为本阶段唯一前端行为修订，属等价修复。
- 权限不扩散：页面不实现任何角色二次确认；能经宿主菜单进入页面即认定有权限（C-4 前端面）。
- 已决策差异保持：阶段 1–3 列表不分页不动；阶段 6 分页与导出交互维持交付形态（S7-D6）。
- 操作列规格统一：表格操作列使用 `type="link" size="small"` 文字按钮横排；次级、低频操作收进「更多」下拉；破坏性操作（停用、作废等）为红色（`danger`）并保留既有二次确认。标准项目目录维护的行操作已按该规格交付；其余走查页面的操作列按同一规格核对，发现偏离按等价修复处理并回写所属阶段文档。
- 查询按钮与反馈规格统一（2026-10-10 起）：全部列表页与看板页的查询按钮逐字使用 `type="primary"` + `SearchOutlined` 图标 + `autoInsertSpace={false}` + `htmlType="submit"` + 文字「查询」，颜色继承宿主主题、不覆盖样式；列表页与看板页均为提交在途即 `loading`；筛选采用提交式（草稿条件与已生效条件分离，「重置」恢复默认条件，条件为空提交等价于刷新）。读取失败不渲染页面内错误横幅，错误由宿主统一提示、重试经查询按钮；前端可预判的输入校验失败经 `message.useMessage()` 实例的 `message.error` 提示、操作成功经 `message.success` 反馈，接口错误一律空 catch 并保留上一次成功数据。各页面已按该规格交付；走查发现偏离按等价修复处理并回写所属阶段文档。

## API 与组件

- 不重生成 API Client：无新增后端契约；患者原值口径不改变生成模型。
- 同类能力统一（S7-D7）前端面：时间/日期筛选控件、弹窗与表单交互、前端分页形态在各页面间统一为实现一套；判定规则见 [阶段设计](../design.md) §2，统一动作按等价修复处理并回写受影响阶段文档。已知现状：日期筛选仅报告管理两入口实现（共用组件），统计页交付后随 C16 复核前提再执行统一判定。
- 无新增错误拦截器、响应处理器或本地接口失败文案；接口失败由宿主统一处理，失败路径复用各阶段既有证据。
