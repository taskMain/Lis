# 阶段 7 Tickets

本目录是阶段 7（横向治理与发布收口）的实施任务拆分。设计见 [根 design](../design.md)（决策台账 S7-D1 至 S7-D12、排除项核对清单 EX-01 至 EX-27 与 DC-01 至 DC-11）、[后端设计](../Server/design.md)（验证矩阵 V1-V33）、[前端设计](../Client/design.md) 与 [前端矩阵](../Client/testPlan.md)（C1-C22）；结果统一写入 [阶段测试报告](../testReport.md)。

## 外部前置（批次外动作，按阶段 6 先例声明）

- 阶段 6 收口（`Complete`，负责人裁定）：含统计四页交付、三条统计索引由负责人按阶段 6 迁移文件建成、导出链路可用——阶段 7 的 C7-C10、V6、V12、C22 依赖这些交付面。
- 宿主可用且外部服务（组织、参数、权限系统）代理映射就位；宿主不可用时依赖宿主的条目记 `Blocked` 并走定级残余出口（S7-D2）。
- 两测试身份同组织（组织 `01` 下医院 `0101` 与 `CSYY2`）；不构造空组织/医院/院区账号类用例（权限系统限制，正常业务不可达）。

## 执行纪律

- 票间依赖见各票的 Blocked by；同一时间只推进一张票，完成并取证后再开下一张。
- 每张票的验收以矩阵编号定案为准：验收通过 = 该票覆盖的矩阵条目取得符合预期的证据并登记进根 `testReport.md`。
- 数据库只读；无迁移。数据经既有接口与页面按业务顺序构造，不构造正常业务不可达的用例；开发期冗余、孤岛或错误数据不作为缺陷处理。
- 框架层事务控制不构造强制失败用例；数据库错误原样抛出；接口失败由宿主统一处理，不新增本地错误处理。
- 核对发现的问题按 S7-D4 三桶在发现票内分流处置：①等价修复在发现票内直接修复并登记 V19/C20；②契约级或范围级问题暂停受影响范围、登记未关闭项并请求决策；③文档一致性类直接修正原阶段文档并登记 V19。票 06 的 V33 含未关闭项与发布结论的联动（存在未关闭项即 `NotReady`）。
- 审查相关：`阶段7-审查相关/` 目录是审查方向与结果，不属实施对象。
