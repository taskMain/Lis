# 阶段 4 后端设计

## 设计基线

聚合沿用 `MedicalRecognitionReportAggregate`。阶段 4 只新增报告采集与生命周期能力：四个医院接入接口、10 张表、报告与版本定位、平台患者归属、作废、PDF 存储与下载、管理端报告查询；不提供报告变化推送、影像文件接收、版本恢复、报告查看权限模型或统计能力。

当前代码事实：10 个报告实体已在 `Domain/MedicalRecognitionReportAggregate/` 生成（`partial`、扁平字段、无导航属性）；对外的 10 个报告 DTO 已生成且枚举为强类型；14 个报告表 SqlMap 已生成但每个只有列清单与无条件的全量查询两条语句，且**作用域统一写成聚合名**，与项目已落地的"作用域＝实体名"约定不一致；10 个建表脚本已生成但为**无 `mrec_` 前缀、无注释、无索引**；4 个页面用报告读模型已生成但把枚举与嵌套对象退化为 `object`；报告生命周期命令、事件、管理器方法、仓储方法与查询实现**均不存在**；宿主工程无控制器目录。以上都是待实现或待修正的现状，不是已验证结论。

高风险决策台账只维护在阶段根设计，本文件细化实现边界与验证矩阵，不复制台账；下文按需引用台账的决策编号（编号定义以阶段根台账为准）。

## 公共契约与分层

**四个医院接入接口。** 两个完整报告提交用手工控制器的 multipart 动作承载（动作校验文件后调用公开应用服务提交入口）；两个作废走既有应用服务接口的自动端点。四个接口成功统一返回 `Boolean=true`，失败以既有框架业务异常表达。手工控制器的路由前缀为 `api/v1/report-pdf`（小写路径段），与框架按接口名推导的自动端点前缀 `/Api/<接口名>/<动作名>` 分属不同前缀，因此不重复、不遮蔽；下载动作为 `GET {reportId}/versions/{reportVersionId}/pdf`。（对应阶段根台账 S4-D6、S4-D15、S4-D34）。

**提交请求信封。** `multipart/form-data` 只有两个部件，部件名固定为 `reportJson`（文本部件，承载完整报告 JSON 文档）与 `pdfFile`（文件部件，承载 PDF 文件流）。JSON 字段名用 camelCase，反序列化拒绝未知字段。两个报告类型各一个端点，不设置报告类型判别字段。单文件上限由配置节 `ReportPdfFiles` 的 `MaxFileBytes` 提供（单位字节，默认 83886080），不硬编码；超限在读取文件流前由控制器动作拒绝。单文件上限必须低于宿主请求体上限，否则超限文件会使整个请求体超过框架上限、在读取阶段即被拒绝，控制器分支不可达：宿主请求体上限由框架程序集设置、应用源码内无配置键，实测约为 104857600 字节；部署侧反向代理请求体上限同步到不小于宿主请求体上限的取值。

**提交链。** 控制器动作 → 校验 PDF（非空长度、大小上限、类型与扩展名、文件头签名）→ 反序列化文本部件 → 按文件名安全规则得到下载名（缺失或不安全时回退为"报告单号加扩展名"）→ 落盘取新文件键 → 调用公开应用服务提交入口；应用服务校验公共输入、解析可信组织、医院、院区与操作人、组装提交命令 → 管理器定位或创建报告、解析患者、追加版本与当前版本指向并更新报告主体上的报告时间、患者姓名、证件号码、写入专项内容与明细、登记事件 → 返回成功；任一步失败时控制器删除本次新文件并原样抛出原始异常。

**作废链。** 自动端点 → 应用服务校验请求、解析可信上下文与操作人、取本次请求接收时间 → 组装作废命令 → 管理器定位报告、读取当前版本平台接收时间、校验作废时间边界、判定幂等或冲突、写入状态与作废事实、登记事件。

**查询链。** 两个列表入口共用读模型与分页：应用服务校验分页窗口（必须在第一次仓储访问之前完成）→ 按入口取值来源组装查询条件并施加业务归属范围（医院管理员入口限可信组织与医院范围）→ 查询仓储先取总数、再取当页 → 应用服务按名称回填口径读取组织、医院、院区名称后对当页整体赋值 → 映射读模型并派生枚举文本。版本列表与版本详情按报告定位并按业务归属范围校验；详情按报告类型返回检验或检查内容读模型之一；下载按报告标识与报告版本标识定位并按报告来源归属校验。

**分层职责。** Host 只做绑定、文件校验与编排；Application 做公共输入校验、可信上下文解析、外部服务编排、命令组装与读模型映射；Domain 管理器做业务不变量校验、持久化协调与事件登记；Repository 做读写、业务键定位、影响行数检查与唯一冲突识别；Contracts 不引用领域实体。

## 提交请求字段

填报要求口径：**必填**＝缺失即整份报告失败；**成对**＝ID 与名称同时有值或同时为空；**应填**＝源系统存在时必须提供、不存在时允许为空；**条件应填**＝仅在对应条件下适用。必填时间字段省略或传零值均视为缺失并拒绝。

**请求结构。** 完整检验报告为 `ReportNo` + `MedicalReportVersionRequest`（公共版本信息）+ `LaboratoryReportContentRequest` + `LaboratoryResultItemRequest` 集合（至少一条）+ `LaboratoryBacteriaResultRequest` 集合（可空，每条内含 `LaboratoryAntimicrobialSusceptibilityRequest` 集合）；完整检查报告为 `ReportNo` + `MedicalReportVersionRequest` + `ExaminationReportContentRequest` + `ExaminationItemRequest` 集合（至少一条，每条内含 `ExaminationSiteRequest` 集合）。互认项目编码字段统一命名 `StandardProjectCode`。

### 框架机制映射

| 项 | 本阶段口径 |
|---|---|
| 目标框架与工作单元声明 | Dy Framework 的 `[WorkUnit(UseTransaction = true)]` 特性，声明在用例实际到达的端点方法上；管理器、仓储、实体与内部辅助方法不控制事务生命周期 |
| 公开事务入口 | 两个提交入口方法（`IMedicalRecognitionReportAppService` 的两个提交方法，同时是医院接入提交入口）；控制器上传动作只做绑定、文件校验与编排，并按下列机制要求同时声明事务 |
| 事务声明的承载位置 | 框架的事件过滤器 `WorkUnitEndpointFilter` 通过 `GetWorkUnitAttribute(RouteEndpoint)` 从**路由端点元数据**取事务声明，据此决定是否开启与回滚事务。医院接入的两个提交由手写控制器动作承载，该动作就是端点，因此事务声明必须落在两个上传动作上；应用服务入口上的同一声明保留，供框架自动暴露的提交端点使用。仅在应用服务入口声明、控制器动作不声明时，该调用路径不开启事务，写入后失败不会回滚（运行期已实测） |
| 自动端点 | 两个提交方法与两个作废方法均由框架按接口自动暴露为端点；提交端点不属于医院接入契约，接入契约是控制器的 multipart 动作，该端点只按"文件键必须在存储中可读"的同口径处理，文件键指向不存在或不可读的文件时拒绝且不产生版本与业务数据 |
| 事务边界与文件落盘的相对位置 | 文件落盘在进入工作单元之前完成；工作单元内只做数据库读写与事件登记；数据库失败后由控制器删除新文件并原样抛出原始异常 |
| 事件处理顺序与已验证边界 | 事件登记发生在全部写入之后；事件队列的具体冲刷与提交时序属框架生命周期，本阶段不作为设计前提、不手工干预、不新增观察点；无专用观察点时事件可见性记不可取证并说明框架边界 |
| 可验证的机械检查点 | 事务声明可静态识别：架构断言核对两个提交入口方法带 `[WorkUnit(UseTransaction = true)]`、两个上传动作同样带该特性、下载动作与两个作废入口不带；PDF 文件校验与单文件上限取自配置节并在控制器动作内、读取文件流之前完成，可静态识别；仓储调用点必须显式传作用域与语句标识（沿用既有源码守卫） |

**并发兜底。** 报告业务键唯一索引拦截同一业务标识的并发首插；版本序号唯一索引拦截同一报告的并发追加；患者证件键唯一索引拦截同一证件的并发首插，撞键时复读一次核对核心身份。三处冲突均翻译为业务拒绝，不自动重试。不增加版本字段、悲观锁或并发压测。

## 报告提交与生命周期

**报告定位。** 按组织、医院、院区、报告类型与来源报告单号定位；组织、医院、院区来自可信调用身份，报告类型由调用的接口确定，报告单号取请求。报告不存在时创建当前有效报告、作废时间与作废原因为空；存在且未作废时取得；已作废时拒绝追加版本。

**版本追加。** 每次成功完整提交追加一个完整版本并立即成为当前版本；旧版本不写可变状态，其历史性由报告当前版本指向推导。版本序号在同一报告内按平台成功形成顺序递增。源端报告修改时间随版本保存，仅用于来源追溯。平台接收时间由服务端取，不采用请求值。

**报告主体上的报告时间与患者检索列。** 报告主体保存报告时间、患者姓名与证件号码，三者取值都来自该次提交版本，与当前版本指向在同一事务内一并更新；因此报告主体上的这三列恒等于当前版本的对应取值且非空，列表的筛选、排序与索引都基于这三列，不需要按当前版本反复关联。报告时间与患者身份本身仍属版本业务事实，取值与上游要求一致，报告时间不参与版本顺序判断。（对应阶段根台账 S4-D19）。

**患者归属。** 按证件类型与证件号码定位平台患者；命中时核对姓名、性别代码与出生日期；未命中时创建平台患者。首次版本把报告与该患者关联；后续版本必须解析到该报告原有关联患者，解析到其他患者或核心身份不一致时整份失败，不允许报告跨患者迁移。首次提交携带的身份信息与既有患者不一致时按患者身份信息冲突拒绝，不覆盖既有资料、不创建第二个患者。

**作废。** 只改变生命周期状态、作废时间与作废原因；作废时间不得早于当前版本平台接收时间、不得晚于本次请求接收时间，两端含边界；不与源端报告修改时间比较。已作废且作废时间与原因完全一致时幂等成功且不重复登记事件；任一不同返回作废信息冲突。作废不生成内容版本、不物理删除、不删除已保存的 PDF 文件。

## PDF 存储与下载

**存储契约与实现。** 契约只暴露保存流返回文件键、按键读取、按键删除；实现按配置键 `ReportPdfFiles:RootDirectory` 提供的**完整绝对路径**解析文件键，单文件上限取同一配置节的 `MaxFileBytes`（单位字节，默认 83886080），文件键格式为 `<yyyyMMdd>/<guid:N>.pdf`，写入采用不覆盖模式并在写失败时删除半成品，读取返回只读流，删除不存在时幂等成功，解析后越出根目录即拒绝。配置缺失、为空、目录不存在或不可写时直接抛出明确业务事实，不静默回落到应用基目录。

**配置项与归属。** PDF 存储与上限由一个配置节提供，宿主 `appsettings.json` 中形如：

```json
"ReportPdfFiles": {
  "RootDirectory": "",
  "MaxFileBytes": 83886080
}
```

对应一个实现框架选项接口的配置类 `ReportPdfFileOptions`，用 `[Options("ReportPdfFiles")]` 绑定该节，属性为 `RootDirectory`（完整绝对路径）与 `MaxFileBytes`（字节，默认 83886080，必须低于宿主请求体上限），并提供 `Validate()` 校验根目录非空、为绝对路径且上限大于零，缺失或非法即抛异常、不兜底；该类与本地文件存储实现同处仓储层，由仓储模块注册，控制器与存储实现都按框架选项注入方式取值。受版本控制的默认配置只放空根目录与默认上限，开发期绝对路径写在开发环境配置；部署环境按部署配置提供实际目录。（对应阶段根台账 S4-D10、S4-D37）。

**提交时的顺序与补偿。** 控制器先完成 PDF 校验与落盘、再调用公开应用服务提交入口写入数据库；写库失败时删除本次新文件并原样抛出原始异常；删除文件失败只记录日志、不改变对外结果与原始异常；追加新版本不删除旧版本文件。删除失败可能留下不可追踪的孤儿文件，该残留面按阶段根台账登记为已接受风险。

**文件名。** PDF 的类型、扩展名与文件头签名校验失败即拒绝整份报告；文件名安全时按其保存为下载名，缺失或不安全时回退为"报告单号加扩展名"，**不因文件名问题拒绝报告**；文件名只保留名称本身，不保留客户端目录，不参与报告身份、版本或幂等判断。

**下载。** 按报告标识与报告版本标识定位版本与报告（报告标识用于归属定位、版本标识用于定位版本），并按报告的来源组织、医院、院区与可信范围比对后返回；响应为 PDF 文件流，内容类型为 `application/pdf`，通过响应头 `Content-Disposition` 使用该版本保存的下载文件名，并禁止缓存；不返回文件键、物理路径或对外下载地址。版本不存在、文件缺失、归属不匹配分别抛出明确业务事实；已作废报告的历史版本仍可下载。

## 管理端报告查询

**两个入口。** 平台管理员入口的组织、医院、院区取自请求；医院管理员入口的组织与医院取自令牌可信上下文并覆盖同名请求字段，院区取自请求且必须属于可信医院；两个入口共用同一分页契约与读模型，操作人取自可信上下文。

**筛选与排序。** 列表支持按组织、医院、院区、报告时间日期范围、报告类型、报告单号、患者证件号码与患者姓名筛选；患者姓名只作为明确输入的查询条件。证件号码与患者姓名均按规范形式做前缀匹配：输入值先去首尾空白、证件号码统一大写，再按前缀比较；`%` 与 `_` 按普通字符处理、不作为通配符；两列在报告主体上有文本前缀索引支撑。时间范围作用于报告主体上的报告时间，采用左闭右开区间：请求侧的两个筛选字段是日历日期（`DateOnly`，只提交年月日、不携带时刻与时区），服务端按下界取该日零点、上界取该日次日零点，得到的边界值不带时区标注，避免数据库驱动按本机时区对边界再次换算。排序为报告时间倒序加主键倒序，分页窗口排序与最终排序逐字一致。分页通过先取总数、再按偏移与页容量取当页实现。

**读模型。** 列表返回报告标识、报告单号、报告类型与文本、报告时间、生命周期状态与文本、来源组织、医院、院区编码与回填名称、当前版本序号、患者姓名与证件号码；版本列表返回版本标识、版本序号、源端报告修改时间、平台接收时间、报告医生名称、审核医生名称、来源报告备注、PDF 文件名、是否当前有效版本、是否已被后续版本替代与报告生命周期状态与文本；版本详情在版本信息外返回报告类型与文本、报告单号及检验或检查内容读模型之一与文件信息。枚举文本由服务端按枚举描述派生，空集合使用空数组或空引用而非占位值。

**名称回填。** 组织全量只读一次，每个不同组织读取一次医院，每家不同医院读取一次院区，对当页整体赋值；调用次数只随当页涉及的组织与医院数量增长，不随返回行数增长，禁止按行逐条请求。外部服务不可用时整次查询失败，不降级为编码或空名称。

**字段脱敏。** 患者姓名与证件号码完整返回；患者联系电话按来源字段保存并在返回时脱敏。

**范围校验与权限判定分离。** 平台管理员入口按请求使用组织、医院、院区并校验三者存在、启用与父子归属；医院管理员入口的组织与医院取自可信上下文，院区必须属于可信医院，列表、版本列表、版本详情与下载均在该可信范围内执行，跨医院或跨院区定位不可得。上述校验只确认可信业务归属与记录归属一致性，不构成操作权限判断；本阶段不引入报告查看权限模型，也不新增角色门控。
