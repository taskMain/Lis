## 自定义配置

除了手动从配置上下文（IConfiguration）获取配置外，框架内置了一种基于DI的简化方式：

1 定义一个类并实现 Dy.Core.Abstractions.Modularity.IOptions 接口，如

```cs
public class RabbitMQOptions : IOptions
{
    public string HostName { get; set; } = "localhost"; //如果没有显式设置则默认 localhost
    public string UserName { get; set; }
    public string Password { get; set; }
}
```

默认从appsettings中取当前对应（类名去掉 Options 后缀）的节点，如果配置中的节点与类名不对应，则需要通过 Options 特性指定节点的名称，如：

```cs
[Options("Rabbit")] //从名为“Rabbit”的json节点获取配置
public class RabbitMQOptions : IOptions
{
}
```

2 在appsettings.json文件中定义相应的配置信息，如：

```javascript
"RabbitMQ": {
    "HostName": "localhost",
    "UserName": "guest",
    "Password": "guest"
},
```

3 在需要使用的地方通过构造函数注入，如：

```cs
public class RabbitMQManagerService : ISingletonDependency
{
    private readonly RabbitMQOptions options;
    public RabbitMQManagerService(IOptions<RabbitMQOptions> options)
    {
    this.options = options.Value;
    }
}
```

除了通过构造函数注入外，还可以通过 ServiceProvider.GetService<IOptions<RabbitMQOptions>>() 获取。

## 配置文件（appsettings）

配置文件一般存在两种： appsettings.json 和 appsettings.<Environment>.json ，其中 appsettings.json 是默认 配置，用于统一配置结构和默认值，默认随git提交到代码仓库；而 appsettings.<Environment>.json 则与实际运行环 境有关，如 appsettings.Development.json 仅在调试模式下生效，可用于配置开发环境，一般不提交到仓库中（每个人 的开发环境可能不一样）。在运行时，会 自 动使用 appsettings.<Environment>.json 文件的设置覆盖 appsettings.json ，其他说明参照官方介绍。
