# 03: 报告读模型重建与分页契约

**What to build:** 把四个页面用的报告读模型从生成态重建为可用形态，并落地服务端分页的公共契约，使两个管理端入口有唯一、强类型的返回契约。读模型侧：枚举与嵌套占位类型改为强类型；同时返回枚举值与文本字段（文本由服务端按枚举描述派生）；版本内容的公共、检验、检查三段分别强类型化，检验与检查各一套内容读模型；版本文件信息不含文件标识与对外下载地址；版本列表同时给出「是否当前有效版本」与「是否已被后续版本替代」；列表补齐组织、医院、院区名称回填字段、当前版本序号与患者姓名、证件号码；版本列表与版本详情的报告责任人员为结构化字段。分页侧：公共请求为业务筛选加 `page: { pageIndex, pageSize }`（页码一基、页容量取值域 1–200），公共响应为 `items` 加 `page: { pageIndex, pageSize, totalCount }`（总数为长整型），不出现 `HasNext`、`Pagination`、`SkipCount`、`PageCount`；窗口校验类型与仓储返回的当页切片属内部类型，不出现在对外契约。本票的读模型定义以票 00 同步后的上游模型为源。

**Blocked by:** 00（UML2 上游同步）

**Status:** ready-for-agent

**外部前置：** 无（不改数据库、不启动宿主）

- [ ] 四个报告读模型族的枚举与嵌套占位类型均为强类型，且每个枚举同时给出取值与文本字段（V73、V84）
- [ ] 版本内容读模型按公共、检验、检查三段强类型化；检验与检查各一套；两套按报告类型二选一返回（V72、V84）
- [ ] 版本文件信息读模型不含文件标识与对外下载地址（V84）
- [ ] 版本列表读模型含「是否当前有效版本」与「是否已被后续版本替代」两个标识（V71 的读模型面、V84）
- [ ] 版本列表与版本详情读模型的报告责任人员为结构化字段（报告医生名称、审核医生名称；检验版本另带检验人名称与明细检测人，检查版本另带检查医生名称），不做字符串拼接、不做优先级取值（V84）
- [ ] 列表读模型含来源组织、医院、院区名称回填字段、当前版本序号与患者姓名、证件号码（V61、V84）
- [ ] 分页请求与响应的字段名、嵌套结构与总数类型与设计逐字一致；契约中不出现禁用字段（V84）
- [ ] 窗口校验类型与当页切片类型不出现在对外契约；类型归属与设计的分层表一致（V84）
- [ ] 契约不引用领域实体；Contracts 层不出现持久化标识之外的内部字段（V84）
- [ ] `git diff --check` 干净；证据记入阶段测试报告（无矩阵编号）
