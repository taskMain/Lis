# 07: 重提交、并发与文件补偿

**What to build:** 让报告在真实并发与失败条件下保持数据一致：并发提交不产生重复报告或重复版本、写库失败不留下「有文件没记录」的垃圾文件、既有版本与其文件不受影响。并发面：数据库唯一索引兜底并发（报告业务键、报告版本序号、患者证件键），冲突一律翻译为业务拒绝、不自动重试；患者证件键撞键时复读一次，核心身份一致则继续追加版本、不一致按患者身份信息冲突拒绝；不增加版本字段、悲观锁或并发压测。补偿面：文件落盘在事务之外、数据库写入之前；写库失败时删除本次新文件并原样抛出原始异常，删除文件失败只记录日志、不改变对外结果与原始异常；追加新版本不删除旧版本文件。失败注入使用测试替身，只覆盖本项目自己的代码路径，不测框架工作单元的事务与事件行为。

**Blocked by:** 05（报告与版本基础链路）、06a（检验报告完整内容）、06b（检查报告完整内容）

**Status:** ready-for-agent

**外部前置：** 批次一 3 张表已建表确认（唯一索引是本票的前置条件）；测试数据须经正常提交接口建立合法前置后再发起并发；上述前置未就绪时，依赖该前置的勾选项在阶段报告记 `Blocked`，其余未执行项记 `NotRun`

- [ ] 并发首次提交同一报告业务标识时唯一约束兜底，其中一个请求按业务拒绝并提示刷新后重试，库中恰有一份报告（V85）
- [ ] 并发首次解析同一证件时复读一次：核心身份一致则继续追加版本，不一致按患者身份信息冲突拒绝；大小写或空白差异不产生第二个患者（V86）
- [ ] 检验报告与检查报告两条链路的写库失败注入都能删除本次新文件，且响应对应原始业务失败（V45、V60）
- [ ] 历史版本文件不受本次失败与其补偿影响，既有版本与其文件仍可正常回读与下载（V45、V60、V79）
- [ ] 删除文件失败只记录日志，不改变对外结果与原始异常类型；该残留面按已接受风险登记，不在本票消除（无矩阵编号，属已接受风险的登记口径）
- [ ] 提交失败后库中无版本记录、无专项内容与明细残留；本次新文件已删除（V18、V79）
- [ ] 并发与失败注入用例的前置数据均由正常提交接口建立，未直接写库、未伪造重复主键或孤儿关联（无矩阵编号，属测试数据纪律）
- [ ] 未新增事务 API、未手工提交或回滚、未包装框架工作单元；未新增并发压测条目（无矩阵编号，属设计口径约束）
- [ ] `git diff --check` 干净；证据记入阶段测试报告（无矩阵编号）

**口径：** 本票覆盖层级为领域防重、应用编排与文件补偿面（V45、V60、V79、V85、V86，以及 V18 的失败零残留面）；明细唯一性三条（V25、V26、V35）由票 06a 承接，真实库与真实文件系统上的联合证据由票 12 复核。矩阵编号可跨批次引用，按完整用例只统计一次，只完成部分层级不记为通过。
