# 02: PDF 存储与宿主请求体配置

**What to build:** 打通报告 PDF 的本地文件存储能力，使提交链路能够先落文件、再写库，并在写库失败时完成补偿。契约只暴露三个操作：保存流并返回文件键、按键读取只读流、按键删除（删除不存在的键幂等成功）。实现按配置提供的完整绝对路径解析文件键，文件键为日期目录加平台生成的文件名，写入采用不覆盖模式并在写失败时删除半成品，解析后越出根目录即拒绝。存储根目录与单文件上限由同一配置节提供，对应一个实现框架选项接口的配置类，并提供校验：根目录非空、为绝对路径、上限大于零；配置缺失、为空、目录不存在或不可写时抛出明确业务事实，不静默回落。受版本控制的默认配置只放空根目录与默认上限，开发期绝对路径写在开发环境配置；本地运行期数据目录由忽略规则排除、不入版本控制。同一票内登记宿主请求体上限的配置点，使提交入口的请求体上限与应用侧单文件上限、部署侧反向代理上限对齐到同一取值。
