# 01: 建表脚本与 SqlMap 物理映射

**What to build:** 交付阶段 4 十张表的最终建表脚本，并让报告相关的数据访问语句与物理表、实体作用域逐一对齐。脚本须包含表注释、列注释与索引注释；列序按项目 DDL 规则（主键、UML 业务列序、生命周期状态标志、操作时间、操作人），报告主体上冗余保存的报告时间、患者姓名与证件号码保持业务列序位置；报告主体除业务键唯一索引与「组织、医院、院区、报告时间倒序、主键倒序」组合索引外，另建两列文本前缀索引（列、运算符类与命名以设计的索引定义小节为准）；报告版本只保留报告标识与版本序号唯一索引。SqlMap 侧：作用域与调用点统一为实体名、不调用共享映射器的上下文设置方法、只访问 `mrec_` 前缀表、查询语句不含方言特征；本阶段十个表文件覆盖插入、按业务键或主键读取、条件更新与存在性判断，阶段 5 的四个表文件只保持作用域与查询口径一致、不改语句。建表由负责人按已确认的目标库与 schema 分三批执行。**闸门：负责人确认建表完成前，依赖新表的集成验证不执行。**

**Blocked by:** None（DDL 静态面与语句骨架可立即开始）

**Status:** ready-for-agent

**外部前置：** 负责人确认目标库与 schema 并执行三批建表；语句调用点的完整核对不属本票，由票 16 在调用点全部落地后承接；上述前置未就绪时，依赖该前置的勾选项在阶段报告记 `Blocked`，其余未执行项记 `NotRun`

- [ ] 十张表的列序、类型、可空性、中文注释与索引声明逐条与设计一致，含报告主体两列文本前缀索引的列、运算符类与命名（V80）
- [ ] 报告主体上的报告时间、患者姓名与证件号码为非空业务列，列位置在当前版本指向之后、生命周期状态之前（V80，并由票 12 的 V80b 复核目标库）
- [ ] 全部表为 `mrec_` 前缀；无跨系统外键；业务时限列与实体 `DateTime` 对齐、操作时间列为带时区类型；字符串列使用文本类型（V80）

- [ ] 脚本与映射的改动不波及既有表与其他系统对象（无矩阵编号，属改动范围约束）
