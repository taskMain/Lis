# 08: 管理端报告列表查询与 PDF 下载

**What to build:** 让管理员能按多个条件查到报告、看到全部历史版本及其完整内容、下载任一版本的原始 PDF。两个列表入口共用一套读模型与分页契约：平台管理员入口的组织、医院、院区取自请求；医院管理员入口的组织与医院取自令牌可信上下文并覆盖同名请求字段，院区取自请求且必须属于可信医院。列表支持按组织、医院、院区、报告时间日期范围、报告类型、报告单号、患者证件号码与患者姓名筛选；时间范围作用于报告主体上的报告时间、左闭右开；排序为报告时间倒序加主键倒序且分页窗口排序与最终排序逐字一致；患者证件号码与姓名按规范形式做前缀匹配（输入先去首尾空白、证件号码统一大写），该筛选落在报告主体表且有文本前缀索引支撑，输入经规范化后为空时不施加该筛选条件。分页窗口校验在第一次仓储访问之前完成，页码小于 1、页容量小于 1 或超过 200 按业务拒绝；仓储先取总数、再取当页，计数语句与数据语句共用同一套筛选条件。名称回填按分层批量读取：组织全量一次、每个不同组织读取一次医院、每家不同医院读取一次院区，调用次数只随当页涉及的组织与医院数量增长、不随行数增长；外部服务不可用时整次查询失败，不降级为编码或空名称。版本列表与版本详情按报告定位并按业务归属范围校验，详情按报告类型返回检验或检查内容之一，枚举文本由服务端按枚举描述派生。下载按报告标识与报告版本标识定位（报告标识用于归属定位、版本标识用于定位版本），并按报告的来源组织、医院、院区与可信范围比对后返回 PDF 文件流与该版本保存的下载名、响应头禁止缓存、不返回文件键或路径；版本不存在、文件缺失、归属不匹配分别抛出明确业务事实；已作废报告的历史版本仍可下载。患者姓名与证件号码完整返回，联系电话返回时脱敏。

**Blocked by:** 03（报告读模型重建与分页契约）、05（报告与版本基础链路）——与票 05 的顺序理由：两个下载动作与两个上传动作落在同一个控制器类型上，下载动作在票 05 落地该类型后追加

**Status:** ready-for-agent

**外部前置：** 查询表与索引已建（批次一建表确认即可覆盖列表与版本查询）；外部组织服务可用；上述前置未就绪时，依赖该前置的勾选项在阶段报告记 `Blocked`，其余未执行项记 `NotRun`

- [ ] 医院管理员入口的组织与医院取可信上下文并覆盖同名请求字段；院区不属于可信医院时拒绝（V62）
- [ ] 时间范围边界正确：起始日零点含边界、结束日次日零点不含上界，跨日数据分别命中（V63）
