## 约定

1. **`Blocked by` 只表达票与票之间的依赖。** 只存在部分依赖时（例如某票的静态面可先做、完整核对需等他票交付），须在 `Blocked by` 内注明该范围。外部前置不并入依赖图，由每票的「外部前置」行单独登记：负责人按批次建表、部署侧请求体上限同步、宿主菜单与角色授权、真实存储目录可用。
2. **`Status` 是领取标签，不是测试状态。** 测试状态只用 `testing-baseline.md` 定义的六种（`NotRun`、`Passed`、`Failed`、`Blocked`、`PendingRetest`、`N/A`），且只写在阶段根 `testReport.md`。受前置阻断的票以「外部前置」行表达，不另用领取标签区分。
3. **勾选纪律**：勾选项只有在有实际执行证据后才可勾选，勾选时附命令或证据出处；票面不得出现 `Passed`、`验收通过`、`已完成` 这类无证据措辞。
4. **证据归档**：执行的命令、结果、证据与残余风险统一写入阶段根 `testReport.md`，票面不复制结果。
5. **矩阵口径**：矩阵编号可跨批次、跨票引用，按完整用例只统计一次；只完成某一层级不把整条用例记为通过。每票末尾的「口径」段声明本票覆盖的层级，**每条勾选项在句末内联标注其对应的矩阵编号**（可对应多条时写全，例如「（V13、V14、V15）」）；不对应任何矩阵条目的勾选项标注「（无矩阵编号）」并说明其性质（如改动范围约束、测试数据纪律、证据形态要求、已接受风险的登记口径）。票面层级名与矩阵层级列的对照见文末「层级词表对照」。同一矩阵编号被多票共同声明时，各票的口径段应写明自己承接的层级面。
6. **不改设计与批次**：实现票不得改动阶段设计、实施批次表和矩阵编号；需要变更时先按项目规则更新设计并取得确认。
7. **测试数据纪律**：业务数据与状态只经正常业务接口（公开 AppService/API）或页面形成；禁止直接执行 SQL、使用数据库工具或脚本写库；禁止伪造重复主键、孤儿关联或违反业务约束的数据作为用例前置。为验证防御分支可构造不可达或损坏前置，但必须逐条标注目的。
8. **建表与授权**：目标库与 schema 由负责人确认并执行建表；权限系统的菜单子项与角色授权由负责人配置；未就绪时相关用例记 `Blocked`，不以本地直达、构建成功或接口直测替代宿主验收。
9. **范围**：审查相关目录（`阶段4-审查相关/`）与讨论期材料不属于任何票的输入、输出或修改范围。
10. **状态查询**：当前执行状态、阻断前提与测试状态以阶段根 `testReport.md` 为准；本目录不维护状态快照。
11. **上游文档同步票的边界**：票 00 属上游文档同步，可更新 `阶段4-规格.md` 上游同步点表中该行的状态列，但不得改动设计决策内容、批次表与矩阵编号；其余各票按约定 6 处理。
12. **实现约束**：本阶段全程按受保护的手工维护推进——不重跑后端代码生成器、不覆盖再生成保护清单中的配置与启动文件、不新增第二套聚合或管理器、不新增异常中间件与响应包装。该约束由票 16 以静态断言或源码守卫核对，不分散写入各实现票的勾选项。
