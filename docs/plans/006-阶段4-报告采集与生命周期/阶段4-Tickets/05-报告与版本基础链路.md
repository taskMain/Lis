# 05: 报告与版本基础链路（提交与作废）

**What to build:** 医院侧采集服务第一次能把一份已审核的报告送进平台，并能让同一份报告进入不可恢复的作废状态。提交为 multipart 两个命名部件（完整报告 JSON 与 PDF 文件流），成功统一返回布尔真、失败以框架业务异常表达；控制器动作只做 multipart 绑定、PDF 校验（非空长度、大小上限、类型与扩展名、文件头签名）、文件落盘与失败补偿，事务边界声明在公开应用服务提交入口的方法上，控制器不承载事务。管理器按序完成：定位或创建报告（仅新建时登记报告已创建事件）→ 解析平台患者并核对 → 追加版本并更新当前版本指向、同时把报告主体上的报告时间、患者姓名与证件号码更新为本次版本取值 → 调用专项内容与明细的写入步骤 → 登记事件；任一步失败整次提交不保存任何内容、不登记后续事件，写库失败时控制器删除本次新文件并原样抛出原始异常。本票交付报告定位、版本追加、当前版本指向与三列更新、患者归属、事件登记、作废语义，以及请求信封与请求到命令的组装；检验与检查两类的专项内容与全部明细分别由票 06a、票 06b 落地，本票不实现明细校验。患者身份字段按规范形式处理（去首尾空白、证件号码统一大写）后再比较与保存，报告版本表保留来源原值。请求字段的填报要求以服务端设计的提交请求字段章节为正式载体（本票的勾选项只承载接口级口径，不复制字段表）。作废走既有应用服务接口的自动端点：只改生命周期状态、作废时间与作废原因，不生成内容版本、不物理删除、不删除已保存的 PDF；作废时间不得早于当前版本平台接收时间、不得晚于本次请求接收时间（两端含边界）；已作废且时间与原因完全一致时幂等成功且不重复登记事件，任一不同返回作废信息冲突；已作废报告不得再提交。本条链路同时覆盖文件名与文件校验的分离口径：文件本身校验失败即拒绝整份报告，文件名缺失或不安全只回退为「报告单号加扩展名」、不拒绝报告。

**Blocked by:** 01（建表脚本与 SqlMap 物理映射）、02（PDF 存储与宿主请求体配置）、03（报告读模型重建与分页契约）、04（既有测试断言同步）

**Status:** ready-for-agent

**外部前置：** 批次一 3 张表（平台患者、报告主体、报告版本）由负责人建表确认；存储根目录已配置且可写（已就绪）；上述前置未就绪时，依赖该前置的勾选项在阶段报告记 `Blocked`，其余未执行项记 `NotRun`

- [ ] 首次提交创建报告与首个版本，当前版本指向该版本、版本序号为 1，登记报告已创建事件与提交事件（V1）
- [ ] 同一报告再次提交追加新版本并成为当前版本，旧版本不被改写、版本序号递增；报告主体上的报告时间、患者姓名与证件号码同步更新为本次版本取值且非空（V2）
- [ ] 报告业务标识各分量（报告单号、报告类型、院区）不同即视为不同报告（V3）
- [ ] 必填字段缺失、成对字段单边提供、必填时间为零值或缺失、就诊类型非法值、业务时间三类逆序均拒绝整份报告且不保存任何内容（V5、V6、V7、V8、V87）
- [ ] 请求反序列化拒绝未知字段；JSON 字段名为 camelCase；互认项目编码字段名为 `StandardProjectCode`（V84 的 Request 契约面）
- [ ] 首次解析患者创建平台患者并关联报告与版本；后续版本命中既有患者；证件已存在但姓名、性别或出生日期不一致时按患者身份信息冲突拒绝，不覆盖既有患者、不创建第二个患者（V9、V10、V11）
- [ ] 后续版本解析到其他患者时拒绝追加，不允许报告跨患者迁移（V12）
- [ ] 患者身份字段按规范形式保存与比较：含首尾空白与小写字母的输入命中同一患者，报告版本表保留来源原值（V9、V10）
- [ ] 作废首次生效并写入作废事实，不生成内容版本、不物理删除；作废时间早于当前版本平台接收时间或晚于本次请求接收时间均拒绝，两端相等时接受；重复作废在时间与原因完全一致时幂等成功，任一不同返回作废信息冲突且不覆盖（V13、V14、V15）
- [ ] 报告不存在时作废拒绝并表达业务事实，不创建占位记录；已作废报告再次提交被拒绝（V16、V4）
- [ ] PDF 文件本身校验失败（非 PDF、内容类型或扩展名不符、文件头签名无效、文件为空）拒绝且不进入业务写入；文件名缺失或不安全不拒绝报告，下载名回退为「报告单号加扩展名」且可按该名回读（V19、V19b）
- [ ] 超过配置的单文件上限时由控制器动作在读取文件流前拒绝，不进入业务写入（V20）
- [ ] 提交请求携带不可读的文件键时拒绝，不产生版本与业务数据，既有报告与文件不受影响（V89）
- [ ] 提交接口成功返回布尔真且数据可回读；提交校验失败时不产生任何业务数据（V17、V18）
- [ ] 两个上传动作只接受 multipart 且仅两个命名部件（`reportJson` 与 `pdfFile`）；控制器动作的路由不与既有自动端点冲突（V83 的两个上传动作形态面与路由面）
- [ ] 事务声明可静态识别：提交入口带工作单元事务声明、控制器动作不带该特性（无矩阵编号，属框架机制映射的可静态识别检查点）
- [ ] `git diff --check` 干净；证据记入阶段测试报告（无矩阵编号）

**口径：** 本票覆盖层级为契约、领域写入、应用编排与宿主面（V1–V20、V19b、V87、V89 的静态与层级证据，V84 的 Request 侧契约面，以及 V83 的两个上传动作形态面）；并发兜底与并发证据由票 07 承接，检验与检查两类明细条目分别由票 06a、票 06b 承接，语句调用点的完整核对由票 16 承接，真实数据库与真实文件系统上的完整链路证据由票 12 承接。矩阵编号可跨批次引用，按完整用例只统计一次，只完成部分层级不记为通过。
