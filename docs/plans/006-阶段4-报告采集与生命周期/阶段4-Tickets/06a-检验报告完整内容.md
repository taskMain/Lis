# 06a: 检验报告完整内容

**What to build:** 承接批次 2 的检验侧完整内容：让一份检验报告的全部明细随提交落库，并在校验不通过时整份拒绝。提交形态与报告与版本基础链路一致（multipart 两部件、成功返回布尔真、管理器内分步写入并最后登记事件、失败不保存任何内容）。需落实：院内标本号、标本类型编码与名称必填，检测完成时间必填，检验人 ID 与名称必填且成对；标本采集时间、标本送检时间、检验科接收时间、报告备注、报告类别编码与名称、整体异常标识、来源医嘱流水号按应填处理（缺省仍接收）；普通检验结果至少一条，每条来源项目名称、来源结果原文、结果类型、展示序号必填，结果类型仅接受数值型、定性型、文本型；明细唯一性三条（来源明细标识提供时同一版本内不重复、普通结果展示序号同一版本内不重复、药敏展示序号同一版本同一细菌鉴定结果下不重复）任一重复即整份失败；互认项目编码缺失或当前不可用不影响接收、随明细原样保存；细菌鉴定结果支持培养未检出（未检出时仍提交一条以表达未检出，不要求菌种编码或名称；检出具体菌种时来源菌种名称必填）；药敏结果挂在细菌鉴定结果下，受试药物名称、来源结论、展示序号必填，量值按来源文本保存、不解析不换算；明细可选人员成对规则成立。检查报告的对应能力由票 06b 承接，两票共用同一提交与作废链路。

**Blocked by:** 05（报告与版本基础链路）

**Status:** ready-for-agent

**外部前置：** 批次二 4 张表（检验专项内容、普通检验结果、细菌鉴定结果、药敏结果）由负责人建表确认；上述前置未就绪时，依赖该前置的勾选项在阶段报告记 `Blocked`，其余未执行项记 `NotRun`

- [ ] 检验专项内容必填字段缺失即拒绝；应填字段缺省时仍接收成功（V21、V22）
- [ ] 普通结果集合为空即拒绝整份报告；普通结果必填字段缺失即拒绝；结果类型仅接受三种取值，其他值拒绝（V23、V24、V42）
- [ ] 明细唯一性三条各自成立：来源明细标识重复即拒绝、全部缺失时仍接收；普通结果展示序号重复即拒绝；药敏展示序号在同一版本同一细菌下重复即拒绝、不同细菌下相同序号可接受（V25、V26、V35）
- [ ] 互认项目编码未提供、提供但不存在、超出组织范围、停用或目录不可用、与无编码混合时均仍接收并原样保存（V27）
- [ ] 细菌鉴定结果必填字段缺失即拒绝；未检出表达被接受且不要求菌种编码或名称；检出具体菌种时来源菌种名称缺失即拒绝；培养信息与仪器缺省时仍接收（V29、V30、V31、V32）
- [ ] 药敏结果必填字段缺失即拒绝；药敏归属字段不可为空（契约与代码级静态断言，不产生无法归属的记录）（V33、V34）
- [ ] 药敏量值按来源文本保存，不解析、不换算（含比较符号与单位文本）（V36）
- [ ] 明细可选人员成对规则：检测人 ID 与名称单边提供即拒绝，同时为空时接收（V28）
- [ ] 检验明细来源字段（单位、参考范围、检测方法、仪器、收费编码、异常与危急值标志）按来源值保存；异常标志与危急标志取值正确（V41、V43）
- [ ] 检验报告备注与整体异常标识不参与接收判断：应填字段缺失、异常标识与明细标志不一致时均不拒绝（V44）
- [ ] 检验报告完整链路回读一致：提交成功后按业务标识回读，专项内容与全部明细逐字段一致；第二版本保存全部明细且旧版本明细保持原样；明细按展示序号返回（V37、V39、V40）
- [ ] 检验报告作废后再次提交被拒绝（V38）
- [ ] `git diff --check` 干净；证据记入阶段测试报告（无矩阵编号）

**口径：** 本票覆盖层级为契约、领域写入与应用编排层（V21–V45，即批次 2 的检验侧范围）；检查侧范围由票 06b 承接，真实数据库与真实文件系统上的完整链路证据由票 12 承接。矩阵编号可跨批次引用，按完整用例只统计一次，只完成部分层级不记为通过。
