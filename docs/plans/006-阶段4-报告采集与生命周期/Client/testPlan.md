# 阶段 4 前端测试前矩阵

本文件是阶段 4 前端的测试前矩阵（用例、边界、测试层级、预期结果）。实际执行命令、结果、证据、状态与残余风险只写阶段根 [testReport.md](../testReport.md)。

## 测试数据与前置边界

- 验收数据只通过平台接口或页面形成：报告数据由两个提交接口构造，组织、医院、院区与用户档案来自既有测试身份；禁止直接写库或使用脚本注入数据。
- 两个测试身份分属同一组织下的不同医院与院区，用于相互验证报告列表与版本可见性。
- 不设置需要构造正常业务不可达前置的用例；页面级失败态用可控的接口失败注入验证。
- 依赖真实后端、真实数据库与真实 PDF 存储目录的条目在矩阵中标注；条件不具备的受影响条目记 `Blocked`。

## 矩阵

| 编号 | 用例与边界 | 层级 | 预期 | 依赖真实后端 |
|---|---|---|---|---|
| C1 | API Client 累计生成与手写入口 | Contract | 生成后公开入口完整；请求与读模型字段、可空性、枚举、分页形状与后端契约一致；保留阶段 1-3 已交付接口；登录接口仍被排除；手写入口文件内容恢复 | 否 |
| C2 | 累计范围核对 | Contract | 无后续阶段端点泄漏；无退化类型；无残留占位模型 | 否 |

| C5 | 适配层分页响应收敛 | Unit | 合法响应收敛为页面分页模型；页码小于 1、页容量小于 1、总数负数或非安全整数一律按契约错误处理，不伪造分页状态 | 否 |

| C12 | 列表筛选组合 | Component | 组织、医院、院区、报告时间日期范围、报告类型、报告单号、患者证件号码、患者姓名各自生效；患者证件号码与姓名按用户输入原样提交、由服务端规范化；筛选变化回到第 1 页并保留页容量 | 否 |
| C13 | 列表时间范围取值 | Component | 日期范围以起止日期提交，页面不拼接时分秒 | 否 |
