## 约定

1. **`Blocked by` 只表达票与票之间的依赖。** 外部前置不并入依赖图，由每票的「外部前置」行单独登记：负责人建成四张表、三个系统参数在平台系统参数系统配置、三个参数编码取值确认、宿主可用。
2. **`Status` 是领取标签，不是测试状态。** 测试状态只用 `testing-baseline.md` 定义的词汇（`NotRun`、`Passed`、`Failed`、`Blocked`、`PendingRetest`、`N/A`），且只写在阶段根 `testReport.md`。受前置阻断的票以「外部前置」行表达，不另用领取标签区分。
3. **勾选纪律**：勾选项只有在有实际执行证据后才可勾选，勾选时附命令或证据出处；票面不得出现 `Passed`、`验收通过`、`已完成` 这类无证据措辞。
4. **证据归档**：执行的命令、结果、证据与残余风险统一写入阶段根 `testReport.md`，票面不复制结果。
5. **矩阵口径**：矩阵编号可跨票引用，按完整用例只统计一次；只完成某一层级不把整条用例记为通过。每票末尾的「口径」段声明本票覆盖的层级，**每条勾选项在句末内联标注对应的矩阵编号**；不对应任何矩阵条目的勾选项标注「（无矩阵编号）」并说明其性质。同一矩阵编号被多票共同声明时，各票的口径段写明自己承接的层级面。
6. **不改设计与批次**：实现票不得改动阶段设计、实施批次表和矩阵编号；需要变更时先按项目规则更新设计并取得确认。
7. **测试数据纪律**：业务数据与状态只经正常业务接口（公开 AppService／API）或页面形成；禁止直接执行 SQL、使用数据库工具或脚本写库；禁止伪造重复主键、孤儿关联或违反业务约束的数据作为用例前置。为验证防御分支可构造不可达或损坏前置，但必须逐条标注目的。
8. **建表与授权**：目标库与 schema 由负责人确认并执行建表；未就绪时相关用例记 `Blocked`，不以本地直达、构建成功或接口直测替代宿主取证。
9. **范围**：审查相关目录（`阶段5-审查相关/`）与讨论期材料不属于任何票的输入、输出或修改范围。
10. **状态查询**：当前执行状态、阻断前提与测试状态以阶段根 `testReport.md` 为准；本目录不维护状态快照。
11. **上游同步不设票**：S5-D4（参数口径）、S5-D14（UML 删列）、S5-D6（匹配查询子命令合并）的上游同步均已完成（依据：SRS F04 业务规则 8／9、F06 业务规则 9、SRS 设计约束 17；`docs/uml/1-MedicalRecognitionReport.wsd` 的两实体删列、两个创建命令与两个事件删除及匹配查询命令的内部步骤注记；`docs/uml/4-MedicalRecognitionExternalSystemQuery.wsd` 的本院报告匹配参数注记）；本目录各票不得改动上游文档，其自身产物（两个领域实体、两个对外 DTO、两份建表脚本的删列）分别由票 00 与票 02 承接。
12. **实现约束**：不新增手写控制器与角色门控、不新增异常中间件与响应包装、不重复声明共享语法助手、不重建聚合与管理器、不重生成 API Client、**不重跑后端代码生成器、不覆盖再生成保护清单中的配置与启动文件**（见 `project-context.md` §3.2）；新增源码守卫若复用共享语法工具，须登记守卫的消费方清单（`Architecture/SourceGuardReuseTests.cs` 的受治理清单）并保持精确一致。该约束由票 07 以静态断言与差异检查核对，不分散写入各实现票的勾选项。
13. **请求校验取证**：不把本阶段入口并入阶段 1–3 的固定入口清单；四个请求类型分别以 `MedicalRecognitionRequestValidator` 断言必填与标识类型的拒绝与通过（票 01），并在写路径上用真实入口断言「请求校验先于领域写入」（票 03、04、06）。
14. **参数口径**：三个系统参数按平台级编码读取、不传组织与医院与院区维度、均不设默认值；取值缺失、非法或参数服务失败一律整次失败。该口径由票 00 声明常量、由票 03 与票 05 取证。
