# 03: 匹配查询（F04）

**What to build:** 医院 HIS 按患者证件与拟开项目发起匹配查询，平台在单个管理器方法内串行完成：校验并去重项目编码 → 解析患者 → 筛选候选报告并按匹配基准时间与报告时间选优 → 非空时写入匹配记录与匹配项（管理器内部步骤，不单独建模为命令）并形成提醒 → 只登记一次匹配已返回事件；空匹配在任何写入前返回成功空结果。本院报告匹配开关与排除时长按平台级编码读取，取值缺失、非法或参数服务失败一律整次失败、零写入、不登记事件。响应提供匹配记录、项目级内容、来源医疗机构名称回填与 PDF 与影像入口。

**Blocked by:** 01、02

**Status:** ready-for-agent

**外部前置：** 四张表由负责人建成；三个系统参数在平台系统参数系统配置；三个参数的编码取值已确认（见票 00）

- [ ] 非空匹配生成一条匹配记录与若干匹配项，返回报告公共信息与项目级内容，登记匹配已返回事件（V1）
- [ ] 空匹配返回成功空结果，不创建记录、不登记事件（V2）
- [ ] 项目编码不存在、未纳入当前组织互认范围、配置已停用、标准目录层级不可用时整次失败并指出相关标准项目编码，不创建记录、不返回同批其他匹配、不登记事件（V3、V4、V5、V6）
- [ ] 同一次查询重复提供相同编码只处理一次，只形成一条匹配项（V7）
- [ ] 患者不存在时返回成功空结果，不创建记录（V8）
- [ ] 候选报告按检验取检测完成时间、检查取实际检查时间选最晚者；时间相同时取报告时间最晚者；两者均相同时以报告版本标识升序稳定兜底（V9、V10、V11）
- [ ] 可互认时间边界按包含处理（V12）
- [ ] 匹配基准时间晚于查询时点的报告不作为候选（V13）
- [ ] 报告已作废或版本非当前有效、报告已形成后续版本、来源组织与接收组织不一致时不参与匹配（V14、V15、V16）
- [ ] 本院报告排除时长的五类取值与边界行为按设计：开关关闭、未达排除时长、满足排除时长与可互认时间、排除时长为零、排除时长大于项目可互认时间（V17、V18、V19、V20、V20b）
- [ ] 联合报告命中多个项目时分别形成匹配项并关联同一报告版本；部分命中时只形成命中项（V21、V22）
- [ ] 匹配查询不形成处理结果、引用结果或调阅状态（V22b）
- [ ] 参数三侧异常（取值缺失、取值非法、参数服务异常）一律整次失败、零写入、不登记事件（V89）
- [ ] 项目编码数组为空时整次失败；不带认证凭据的请求被拒绝；提醒事实为互认匹配项记录且本阶段不做提醒计数；同一次查询的重复执行不复用旧集合（V91、V92、V93、V94）
- [ ] 新增写入口后，既有写入口契约方法集合等值断言与写侧分部文件逐文件等值断言同批同步（无矩阵编号：既有断言同步面，见 `Server/design.md` 的端点与分部文件清单段；查询入口的同步见票 05）
- [ ] 写路径上的真实入口断言「请求校验先于领域写入」（无矩阵编号：取证方式见 README 约定 13）
