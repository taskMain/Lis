# 阶段2任务票约定

这些任务票是阶段2的执行分解，业务设计以阶段正式设计文档为准，测试结果以阶段根 `testReport.md` 为准。

`Blocked by` 表示完整交付的阻塞关系，不代表每个静态子任务都必须等待；可独立执行的部分应先执行，未满足前置的完整验证记录为 `NotRun` 或 `Blocked`。

`Status` 是任务领取标签，不是测试状态。`ready-for-agent` 表示可以领取；`blocked-until-prerequisites-ready` 表示完整交付受前置条件阻断。测试结果只使用项目 Testing Baseline 的六种状态。

证据统一归档到阶段根 `testReport.md`；具体检查要求以项目现行规范为准。

所有任务票的测试数据均通过真实业务接口或页面添加、修改和启停；禁止直接执行SQL或通过数据库工具、脚本、测试夹具绕过业务入口写库，包括造数、修正数据或清理数据。接口或页面触发服务端正常持久化，不属于授权代理直接写库。数据库核对仅可在授权范围内只读进行；无法通过正常业务入口建立的前置应记录受阻，不通过直接写库补齐。

不把相同主键、孤儿关联、已删除对象、手工重复业务键或其他违反约束的数据作为普通业务用例前置。排序只验证正常业务能产生的数据集合；并发、唯一约束和资源范围验证也必须先通过正常接口或页面建立合法数据。

目标库/schema和建表由负责人确认并执行，任务执行者只交付脚本、核验完成确认，不代执行DDL。Host用例仍须从宿主登录页和菜单操作，不能用接口造数替代规定的页面验证。`阶段2审查相关` 不属于任何票的输入、输出或修改范围。
