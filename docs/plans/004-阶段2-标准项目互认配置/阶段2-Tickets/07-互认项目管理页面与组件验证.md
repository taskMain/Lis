# 07: 互认项目管理页面与组件验证

**What to build:** 通过阶段2稳定 API Client 实现“互认项目”管理页面，完成组织范围、目录选择、配置维护、启停、刷新、失败恢复和写后状态更新的可验证用户流程。

**Blocked by:** 03 互认配置写入与启停并发规则；04 互认配置查询与目录停用说明；06 累计 API Client 生成与契约校验

**Status:** ready-for-agent

- [ ] 进入页面自动加载当前组织配置和当前有效标准目录，并提供手动刷新。
- [ ] 新增选择器只允许选择最底层当前有效标准项目；当前组织已存在配置的项目（含停用配置）不可选；切换组织后按目标组织重新计算排除集合。
- [ ] 支持新增、修改时间、独立启停；停用目录仍可修改时间和停用，重新启用失败时保留状态和操作入口。
- [ ] 写入失败保留必要输入和弹窗；写成功后刷新列表和选择数据；刷新失败不改判为写入失败并阻止继续写入。
- [ ] 覆盖组织切换清理、迟到响应隔离、查询失败恢复、同值保存和重复提交保护。
- [ ] 覆盖未保存新增/编辑内容时的组织切换确认；取消保留内容，确认才清理。
- [ ] 页面设计遵循已确认的前端规范，不新增权限模型、错误拦截器或分页。

**Verification and evidence:**

- [ ] 先建立组件/契约失败证据，再实现并精确复测。
- [ ] 覆盖 C1-C3、C6、C8、C10-C11、C13-C21、C23；归档组件、typecheck 和必要 Host 证据到阶段 `testReport.md`。
- [ ] C25 的不分页风险证据在真实环境由本票或 Ticket 08 归档。
- [ ] 完成适用组件测试和检查，证据归档到阶段 `testReport.md`。
