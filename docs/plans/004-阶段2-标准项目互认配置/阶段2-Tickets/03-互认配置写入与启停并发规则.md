# 03: 互认配置写入与启停并发规则

**What to build:** 让互认项目配置的新增、可互认时间修改、启用和停用形成完整后端业务闭环，并保证组织归属、唯一性、幂等、并发状态更新和领域事件语义一致。

**Blocked by:** 01 组织上下文与事件机制取证；02 互认配置公共契约与生成物整理

**Status:** ready-for-agent

- [ ] 新增时按编码取得标准项目，校验标准项目、分类和分组当前有效，创建后默认启用。
- [ ] 修改只改变可互认时间；停用配置仍可修改；同值保存仍正常登记修改事件。
- [ ] 启停按 `ID + 可信组织 + 原状态` 条件更新，影响1行才登记事件。
- [ ] 重复同方向操作幂等成功；0行通过可信组织复读区分幂等、并发冲突、不存在和越组织；不自动无限重试。
- [ ] 创建事件包含启用状态；修改和启停事件包含所需配置、组织、项目和公共操作字段。
- [ ] 唯一键冲突统一返回重复配置业务错误；跨组织配置 ID 写入拒绝且不修改数据或登记事件。

**Verification and evidence:**

- [ ] 先取得准确 RED 或静态失败证据，再实现并精确复测。
- [ ] 覆盖 V1-V9、V11、V15-V16、V26-V27；所有前置配置通过正常接口或页面建立，记录证据到阶段 `testReport.md`。
- [ ] 组织和事件机制未解除时，只执行不依赖它们的契约/静态工作，相关验证保持 `Blocked`。
- [ ] 四个写入口各保持最多一条写语句且不声明 `[WorkUnit]`；若出现同表多写或跨表原子写入，先由负责人修订设计。
- [ ] 按项目现行规范完成必要检查，证据归档到阶段 `testReport.md`。
