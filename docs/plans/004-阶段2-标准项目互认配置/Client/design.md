# 阶段 2 前端设计

## 页面与交互

页面名称为“互认项目”，从宿主登录页和菜单进入。平台管理员可在授权组织范围内切换组织；组织由可信上下文确定，不由页面自由输入。医院管理员只使用可信上下文允许的组织。

页面展示当前组织的互认项目配置及标准目录关联的编码、名称、类型、分类、分组、可互认时间、配置状态和必要的 `UnavailableReason`。不展示创建/修改人和时间，不展示独立的“标准目录有效”或“可用于新匹配”字段。

新增只选择当前有效标准目录的最底层标准项目，隐藏当前组织已经配置的项目。配置停用后仍可修改可互认时间；启停独立确认。组织切换和请求加载失败时保护旧状态，禁止基于不完整数据写入。

页面首次进入自动加载当前组织配置和标准项目选择数据，并提供手动刷新。刷新期间禁用新增、修改和启停；同组织读取失败保留已有有效列表和选择数据，同时进入不可操作的失败状态，允许重试。切换组织前若存在未保存的时间修改或新增内容，必须确认放弃；确认后清空旧列表、选择、筛选和弹窗状态，再加载目标组织，失败时不得进入目标组织的可操作状态。

新增成功后保留组织和筛选条件，清空新增表单，刷新配置列表和标准项目选择数据。修改成功后关闭弹窗并刷新；同值保存仍发送请求并按成功处理。写入成功但刷新失败时，仍显示写入成功，保留可识别的当前页面状态并阻止继续写入，允许重试刷新。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。配置查询使用 `QueryRecognitionProjectConfigurationList`；写入使用 `1-MedicalRecognitionReport.wsd` 中已有的四个互认配置命令。新增后刷新配置列表和标准项目选择数据，保留组织和筛选条件。

功能适配层负责把生成的 Request/ReadModel 转换为稳定视图模型：新增 Request 不提交组织编码；ReadModel 不包含创建/修改人和时间、两个独立状态字段，`UnavailableReason` 可为 `null`，状态和类型使用生成枚举。目录停用原因由后端实时返回，配置自身停用只由配置状态表达。

API Client 按累计范围生成：保留阶段1已交付 F01 接口，加入阶段2稳定契约；排除后续阶段接口及 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、nullable、enum 和无残留后续端点。生成入口、配置和 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

页面不新增业务错误类型、拦截器或权限模型。所有写失败保留输入；写成功关闭弹窗，刷新失败不改判为写入失败。
