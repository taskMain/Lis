# 阶段 2 前端设计

## 页面与交互

页面名称为“互认项目”，从宿主登录页和菜单进入。页面不提供组织切换控件，也不持有可选组织集合：组织由可信上下文确定（登录管理器 `@dy/auth` 的 `LoginUserManager` 的当前登录组织，来源与同组织参照项目 `Dy.LisCenter` 一致），宿主重新签发 token 导致可信组织变化时，页面按变化重新加载并清理旧组织状态。医院管理员与平台管理员都只使用可信上下文给出的组织。登录凭证缺失（token 不存在）或组织、医院编码任一空白时，页面整页只渲染标题与一条错误 Alert（带图标，文案说明无法读取当前登录组织或医院、已阻断本页查询与操作），不渲染列表与筛选区、不发出业务请求；院区缺失不进入该阻断，由接口报错经宿主提示。

页头右侧只有主操作「新增互认项目」，与页面标题、宿主菜单项同名（S2-D23）；页头不展示组织、医院、院区范围，不出现任何三级名称或编码（S2-D22）。

页面主体为横向四栏列视图：类型｜分类｜分组｜项目四栏恒定全显，不设折叠或展开控件（S2-D16）；类型格纵向跨其名下全部分组行、分类格纵向跨其名下全部分组行，纵向位置与跨行高度表达从属关系。窄视口下表格区横向滚动，不压缩列宽。**页面行集是本组织已配置的互认项目**（S2-D16）：每行按其标准项目编码从当前有效标准目录补齐名称、类型、分类、分组，并展示配置状态（启用／停用）与必要的 `UnavailableReason`（目录已停用徽标），可互认时间就地展示；有效目录中未被本组织配置的项目不进列表，因此层级格只在其名下存在已配置项目时出现，列表行数与页脚「共 M 项配置」恒等（页脚报当前显示条数，S2-D24）。不展示创建/修改人和时间，不展示独立的“标准目录有效”或“可用于新匹配”字段。

**未配置项目的入口只有一个——页头「新增互认项目」弹窗**（S2-D17）：未配置项目在页面上没有任何可执行动作，若同时出现在列表里，"缺什么"的发现职责就会同时落在两处，用户无法判断该在哪一处动手。发现与选择因此全部收在弹窗里，弹窗自带关键字搜索与全选当前结果（S2-D26）。

点击类型、分类或分组格只高亮其整条下级链路（类型→分类→分组→项目），用于在全平铺结构中定位从属范围；高亮不携带任何写操作，点击其他区域清除。项目数量增长时页面纵向滚动，不折叠、不分页（S2-D7 口径不变）；层级格按 `content-visibility: auto` 声明离屏跳过渲染并给出固有尺寸估计（S2-D28），不做真正的窗口化。

查询区只承载关键字一个查询条件：一个宽关键字输入框，框内右侧为查询图标按钮（S2-D21）；配置状态改为贴在列表上沿的页签（「全部 / 启用 / 停用」）。关键字是**单个**查询条件，按字面包含同时匹配标准项目编码、标准项目名称、所属分类名称与所属分组名称，比较不区分大小写（S2-D29）。关键字以输入原文为草稿，输入过程不读取也不改变列表；点击查询图标按钮或在输入框内按回车后，页面**按该关键字向服务端查询配置列表**（页面读取只有配置列表 1 次），返回值即匹配集合，本地不再对关键字做判定（S2-D24）。配置状态页签是离散选择，切换即生效，只在服务端结果上做本地裁剪、不触发读取。关键字输入框的清空动作同时清空输入原文与已生效的关键字条件，并触发一次空条件读取。不设「重置」：还原默认条件只需清空关键字与状态点回「全部」两步，重置键不减少其中任何一步。查询图标按钮逐字规格 `SearchOutlined` 图标、`aria-label="查询"`、`autoInsertSpace={false}`，颜色继承宿主主题、不覆盖样式，与页头「新增互认项目」分属两个操作区域；读取在途时该按钮进入 `loading` 形态（图标换成旋转指示，读取在途期间的点击不再发起新的读取），使「点了查询之后正在取数」这件事在用户刚点击的位置可见。**读取在途期间列表内的行内操作一并禁用**（沿用 `canWrite` 含 `!loading` 的既有门控），因此旧数据在这段时间只能查看、不能修改；不给列表加遮罩：重读通常是短时操作，遮罩会在快的时候闪烁，而按钮的旋转指示已足够指向。页脚报**当前显示条数**（「共 M 项配置」）：配置列表响应没有总数来源，页面行集（S2-D16）本身就是本组织的配置集合，需要看总量时清空条件提交一次即可。提交应用条件后可见行集随之变化，行内编辑态一并清除——目标行可能被筛掉，筛选恢复后编辑态若"复活"，用户会看到一个自己没有打开过的输入框（与改变本地筛选同一理由）。**已生效的筛选条件与本页路由地址的查询参数保持一致**（S2-D27）：进入页面时按 `keyword`、`status` 两个参数初始化筛选，条件变化后以替换当前历史项的方式回写，不新增历史项；关键字输入原文不写入，只有经提交生效的条件才写。页面嵌在宿主工作区里时浏览器地址栏属于宿主外壳，参数落在子应用的路由地址上（独立运行或直达子应用地址时即为浏览器地址栏），且不跨宿主整页刷新保留。关键字条件下推服务端后，页面不再持有本组织全量配置，也不再读取标准目录（S2-D29）：查询范围由关键字收窄，本地只保留配置状态这一项与展示无关范围的裁剪。读取失败、提交失败与行内校验这类异步出现的提示在渲染位置上声明 `aria-live="polite"`，使读屏软件能读到状态变化而不是只在视觉上出现。新增弹窗内的本地拦截错误（未勾选、可互认天数非法）以字段级红字在对应输入区域就近提示，弹窗保持打开、保留用户输入，不再使用弹窗内 Alert 表达输入错误。

新增互认项目使用弹窗（S2-D17）：弹窗内复用同一横向列视图，仅列出当前组织未配置且目录有效的标准项目；支持按项目复选，也支持在分组格整组勾选（点击分类或类型格的空白处等价于整类、整型勾选）；底部为统一的 `RecognitionDurationDays` 输入（S2-D18）与已选计数。确定后批量创建（S2-D19），全部默认启用；页面本体不出现复选框与选择模式。新增成功后关闭弹窗、清空弹窗选择，保留组织和筛选条件，刷新配置列表与可新增项目数据；刚创建的项目不再出现在弹窗可选集合（可新增集合由服务端按「有效目录 − 本组织已配置」交付，S2-D29）。配置停用后仍可修改可互认时间；启停独立确认。

**弹窗是本页唯一的选择面**（S2-D16、S2-D17），因此它必须自己承担"看到缺什么、一次选到位"（S2-D26）：弹窗顶部为「关键字输入框 + 搜索按钮」（与页面查询区同一提交口径），提交后**按该关键字向服务端查询可新增标准项目**，结果即当前搜索结果；底部提供文字「全选当前结果」，把当前搜索结果里的全部可新增项目一次勾选，与既有的层级整组勾选并存。选择条数超过单批上限（1000 条）时，确定动作在本地被拦下并在弹窗内给出条数说明，不发请求。项目行整行都是勾选命中区（点名称、点编码与点复选框等价），不留"看着能点、点了没反应"的空白区。

弹窗的可选集合不沿用页面最近一次读取的快照（S2-D25）：**弹窗打开时重新读取可新增标准项目**——一次查询即「三级均启用的有效目录 − 本组织已配置」（S2-D29），可选集合按本次查询结果计算，因此打开那一刻看到的就是当时真实可新增的项目。弹窗内提供文字「重新读取」按钮，供弹窗已打开时手动再读；读取在途与读取失败沿用既有的写界面门控口径（在途期间禁用确定、失败时就地给出原因并允许重试），不新增一套状态。重读完成后，已不在可选集合中的勾选从选择中剔除，并在弹窗内给出被剔除的条数说明——剔除不静默进行，否则用户会看到计数与自己勾选的数量对不上。整批创建被服务端拒绝时就地即可重读，不必关闭弹窗再去页面刷新。该按钮常驻弹窗底部而不是只在失败后出现：写失败的文案由宿主统一展示，页面不自行捕获写失败，因此页面既拿不到拒绝原因、也无从按原因渲染指向文案。

可互认时间在项目行内就地修改：点击时间值进入行内编辑，只允许正整数天（最小 1）；非法输入拒绝保存、保留输入并给出提示，同值保存仍发送请求。编辑取值与回填以当前行集为准，不保留打开时刻的行快照；行集里找不到该行时不渲染编辑态。启停仍为独立确认弹窗，只持目标配置标识，目标行与动作目标每次渲染按当前行集重取（目标行不在行集或其当前状态未知时不渲染弹窗）。

组织切换和请求加载失败时保护旧状态，禁止基于不完整数据写入。刷新期间禁用新增、修改和启停；同组织读取失败保留已有有效列表和标准目录数据，同时进入不可操作的失败状态，允许重试。宿主重新签发 token 使组织发生变化时，若存在未保存的时间修改或新增弹窗内容，必须先确认放弃；确认后清空旧列表、选择、筛选（含编码输入原文）和弹窗状态，再加载目标组织，失败时不得进入目标组织的可操作状态。组织未对齐（可信组织已变化而页面尚未应用）或处于读取失败态时，新增弹窗与启停弹窗禁用确定按钮并给出原因，提交动作在发起请求前读**现值**可信组织并与页面已应用组织比对，不一致或读不到即零写请求并在弹窗内给出可见原因（覆盖渲染与提交之间的组织变化）。

写入成功但刷新失败时，仍显示写入成功，保留可识别的当前页面状态并阻止继续写入，允许重试刷新。

在途请求的处置口径固定为**只作废结果、不取消请求**：生成客户端契约没有取消入口（`@microsoft/kiota-abstractions` 的 `RequestConfiguration<T>` 只有 `headers`、`options`、`queryParameters`，没有 `AbortSignal`，生成方法只能原样调用适配器；适配层亦未暴露取消能力），页面按请求序号丢弃迟到响应。旧请求因此会在网络与服务端照常跑完，但其响应不写入任何页面状态；页面不得为此自建底层 HTTP 调用或新增拦截器（[frontend-api-client](../../../../.agents/instructions/frontend-api-client.md) 第 2、5 节）。该边界与 `useEnumMetadata` 的卸载守卫同一口径，登记为规范边界与残余风险。

页面状态只持**页面视图模型**：适配层交付的列视图模型——类型／分类／分组三栏结构与项目行集合（每行含配置状态、可互认时间与 `UnavailableReason`）。行集合只包含本组织已配置的项目；每行的名称、类型、分类、分组与层级结构由配置列表查询实时关联标准目录交付，页面因此不再单独读取标准目录（S2-D16、S2-D29）。生成读模型（如 `EffectiveMedicalStandardCatalogReadModel`）只作为读取响应经过加载函数，不进入页面状态，契约形状变化在适配层吸收。

项目行标识规则：优先取契约唯一键，缺失时用业务字段组合；同一组业务字段完全相同的多行只在组内回退到出现序号，保证行 key 唯一、行内操作控件不串位，该序号不参与任何业务判定、不作为字段提交或展示。该规则由组件层用例按行 DOM 实际渲染值断言（两行互不相同），不依赖 React 的重复 key 告警文本。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。配置查询使用 `QueryRecognitionProjectConfigurationList`（按 `Keyword` 过滤）；可新增标准项目使用新增的 `QuerySelectableStandardItemList`（不接收入参组织，入参只有可选的 `Keyword`，S2-D29）；写入使用 `1-MedicalRecognitionReport.wsd` 中已有的四个互认配置命令与重开轮新增的批量创建命令（契约形状以阶段根 [design.md](../design.md) 的 S2-D19 为准：提交标准项目编码集合与统一可互认天数，不提交组织编码）。**读取分两条路径、互不共用数据**：页面读取（配置列表，1 次）由页面进入与切换组织、搜索提交（S2-D24）触发；弹窗读取（可新增标准项目，1 次）由弹窗打开（S2-D25）、「重新读取」与弹窗内搜索（S2-D26）触发，弹窗读取不重读配置列表。新增成功后刷新配置列表与可新增项目数据，保留组织和筛选条件。

功能适配层负责把生成的 Request/ReadModel 转换为稳定视图模型：新增与批量新增 Request 均不提交组织编码；ReadModel 不包含创建/修改人和时间、两个独立状态字段，`UnavailableReason` 可为 `null`。配置状态与项目类型在生成端是数值（`number | null`，OpenAPI 已声明取值、成员名与中文说明），生成端不产出 TypeScript 枚举；取值域、取值域判定与兜底文案由跨页面共享模块 `src/shared/configurationStatus.ts`、`src/shared/medicalItemType.ts` 承载（取值须与后端枚举声明一致），本适配层按原名字转发。目录停用原因由后端实时返回，配置自身停用只由配置状态表达。

枚举中文来源（与 `Dy.LisCenter` 同口径）：**服务端是枚举中文的唯一来源，前端不再自持文案映射**。页面按两条路径取用：(1) 列表、只读资料等展示文本直接取只读模型交付的 `ItemTypeText` / `ConfigurationStatusText`，适配层不再用本地文案表推导展示；(2) 需要选项集合的下拉（配置状态筛选）用 `useEnumMetadata('ConfigurationStatus', fallback)` 从枚举元数据接口取 `value`/`label`。本地常量（`MEDICAL_ITEM_TYPE_TEXTS`、`CONFIGURATION_STATUS_TEXTS`、`CONFIGURATION_STATUSES`）降级为**接口不可用或字段缺失时的兜底**：页面在元数据加载失败时仍可用稳定取值渲染，不出现空下拉或空文案。`useEnumMetadata` 按 API Client 实例缓存同一枚举名的请求，失败时清除缓存以便重试；加载失败不改判为页面错误，仍由宿主统一展示 API 错误。

筛选口径：关键字是**服务端查询条件**（`Keyword`），按字面包含同时匹配标准项目编码、标准项目名称、所属分类名称与所属分组名称，比较不区分大小写，`%` 与 `_` 按普通字符转义（S2-D29）；服务端返回什么就展示什么，本地不再按关键字判定——本地再判一次会把按名称、分类或分组命中的行错误裁掉。配置状态是离散选择，切换即生效，只在服务端结果上做本地裁剪、不触发读取（S2-D21）。两项条件的生效时机见「页面与交互」：关键字经搜索按钮或输入框回车提交并按该关键字查询（S2-D24），因此结果始终是数据库当前状态。已生效的条件与本页路由地址的查询参数保持一致（S2-D27；宿主内参数落在子应用路由地址上，不跨宿主整页刷新保留）。关键字口径由后端矩阵 V12-V14 与 V35 覆盖：V12-V14 守配置列表查询的四列匹配与排序，V35 守可新增标准项目查询（组织取自可信上下文、关键字原样下传、层级组装、空白关键字在进入查询前被拒绝）。枚举契约（`MedicalItemType`、`ConfigurationStatus`）已于 2026-09-16 修复为在 OpenAPI 中声明取值与中文说明，生成端按数值读写。配置状态筛选的**选项标签**取自枚举元数据接口（兜底为本地常量），筛选仍是本地判定：元数据只提供展示文案，不改变筛选位置与范围。

枚举元数据接口**不属组织范围数据**：服务端 `POST /Api/EnumMetadata/GetEnumMetadata` 只接受 `enumName`（无组织入参），返回的是启动时由 SourceGen 描述器投影出的**进程级静态表**（枚举成员取值与 `[Description]` 中文），不读业务数据、不按调用方组织过滤；因此 `useEnumMetadata` 的缓存身份是「API Client 实例 + 枚举名」，同一 client 换组织时数据完全相同，按组织再分维度只会重复请求同一份数据。请求时机由 `enabled` 门控：可信组织或医院不可用时页面整页渲染统一阻断面板（标题加一条错误 Alert）、不渲染任何需要枚举文案的区域，此时不发起该请求（该开关只改请求时机，不参与缓存口径，也不引入新的数据来源）。**边界**：若将来该接口改为按组织交付文案，缓存键与失效时机必须同步加入身份维度，不能沿用当前口径。

API Client 按累计范围生成：保留阶段1已交付 F01 接口，加入阶段2稳定契约；排除后续阶段接口及 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、nullable、enum 和无残留后续端点。生成入口、配置和 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

页面不新增业务错误类型、拦截器或权限模型。所有写失败保留输入；写成功关闭弹窗，刷新失败不改判为写入失败。

## 已接受风险

不分页及重审条件以 [阶段决策 S2-D7](../design.md) 为准，不另设判据。全平铺列视图在项目数量大时的纵向长度与滚动成本由同一口径覆盖：出现可复现卡顿、超时或内存问题才重审，不设任意记录数阈值。
