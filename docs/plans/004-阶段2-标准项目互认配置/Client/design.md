# 阶段 2 前端设计

## 页面与交互

页面名称为“互认项目”，从宿主登录页和菜单进入。页面不提供组织切换控件，也不持有可选组织集合：组织由可信上下文确定（登录管理器 `@dy/auth` 的 `LoginUserManager` 的当前登录组织，来源与同组织参照项目 `Dy.LisCenter` 一致），宿主重新签发 token 导致可信组织变化时，页面按变化重新加载并清理旧组织状态。医院管理员与平台管理员都只使用可信上下文给出的组织。

页面展示当前组织的互认项目配置及标准目录关联的编码、名称、类型、分类、分组、可互认时间、配置状态和必要的 `UnavailableReason`。不展示创建/修改人和时间，不展示独立的“标准目录有效”或“可用于新匹配”字段。

新增只选择当前有效标准目录的最底层标准项目，隐藏当前组织已经配置的项目。配置停用后仍可修改可互认时间；启停独立确认。组织切换和请求加载失败时保护旧状态，禁止基于不完整数据写入。

页面首次进入自动加载当前组织配置和标准项目选择数据，并提供手动刷新。刷新期间禁用新增、修改和启停；同组织读取失败保留已有有效列表和选择数据，同时进入不可操作的失败状态，允许重试。宿主重新签发 token 使组织发生变化时，若存在未保存的时间修改或新增内容，必须先确认放弃；确认后清空旧列表、选择、筛选和弹窗状态，再加载目标组织，失败时不得进入目标组织的可操作状态。组织未对齐（可信组织已变化而页面尚未应用）或处于读取失败态时，写弹窗禁用确定按钮并给出原因，提交动作在发起请求前读**现值**可信组织并与页面已应用组织比对，不一致或读不到即零写请求并在弹窗内给出可见原因（覆盖渲染与提交之间的组织变化）。

新增成功后保留组织和筛选条件，清空新增表单，刷新配置列表和标准项目选择数据。修改成功后关闭弹窗并刷新；同值保存仍发送请求并按成功处理。写入成功但刷新失败时，仍显示写入成功，保留可识别的当前页面状态并阻止继续写入，允许重试刷新。

在途请求的处置口径固定为**只作废结果、不取消请求**：生成客户端契约没有取消入口（`@microsoft/kiota-abstractions` 的 `RequestConfiguration<T>` 只有 `headers`、`options`、`queryParameters`，没有 `AbortSignal`，生成方法只能原样调用适配器；适配层亦未暴露取消能力），页面按请求序号丢弃迟到响应。旧请求因此会在网络与服务端照常跑完，但其响应不写入任何页面状态；页面不得为此自建底层 HTTP 调用或新增拦截器（[frontend-api-client](../../../../.agents/instructions/frontend-api-client.md) 第 2、5 节）。该边界与 `useEnumMetadata` 的卸载守卫同一口径，登记为规范边界与残余风险。

修改可互认时间弹窗只持目标配置的**标识**，行数据每次渲染都按**当前行集**重取，不保留打开那一刻的行快照；后台刷新（重试读取、写后刷新）交付新值后，弹窗的只读资料与表单回填都取当前行。取舍是后台刷新会同时覆盖该弹窗中尚未提交的输入——输入框不是独立数据源，页面持有的当前行才是。行集里找不到该配置（已不在本组织视图）时不渲染弹窗，避免对未知行提交写入。启停确认弹窗按同一规则：只持目标配置的**标识**，目标行与其动作目标每次渲染都按**当前行集**重取（目标行不在行集、或其当前状态未知时不渲染）。

页面状态只持**页面视图模型**：配置行为适配层交付的行模型，标准目录为摊平后的候选集（`SelectableStandardItem[]`）。生成读模型（如 `EffectiveMedicalStandardCatalogReadModel`）只作为读取响应经过加载函数，不进入页面状态，契约形状变化在适配层吸收。

表格行标识规则：优先取契约唯一键，缺失时用业务字段组合；同一组业务字段完全相同的多行只在组内回退到出现序号，保证表格 key 唯一、行内操作控件不串位，该序号不参与任何业务判定、不作为字段提交或展示。该规则由组件层用例按 rc-table 渲染的 `data-row-key` 实际值断言（两行互不相同），不依赖 React 的重复 key 告警文本。

## API 与组件

使用现有 API Client 上下文，不在页面创建 Client。配置查询使用 `QueryRecognitionProjectConfigurationList`；写入使用 `1-MedicalRecognitionReport.wsd` 中已有的四个互认配置命令。新增后刷新配置列表和标准项目选择数据，保留组织和筛选条件。

功能适配层负责把生成的 Request/ReadModel 转换为稳定视图模型：新增 Request 不提交组织编码；ReadModel 不包含创建/修改人和时间、两个独立状态字段，`UnavailableReason` 可为 `null`。配置状态与项目类型在生成端是数值（`number | null`，OpenAPI 已声明取值、成员名与中文说明），生成端不产出 TypeScript 枚举，取值与兜底文案由适配层的本地常量承载（取值须与后端枚举声明一致）。目录停用原因由后端实时返回，配置自身停用只由配置状态表达。

枚举中文来源（与 `Dy.LisCenter` 同口径）：**服务端是枚举中文的唯一来源，前端不再自持文案映射**。页面按两条路径取用：(1) 列表、只读资料等展示文本直接取只读模型交付的 `ItemTypeText` / `ConfigurationStatusText`，适配层不再用本地文案表推导展示；(2) 需要选项集合的下拉（配置状态筛选）用 `useEnumMetadata('ConfigurationStatus', fallback)` 从枚举元数据接口取 `value`/`label`。本地常量（`MEDICAL_ITEM_TYPE_TEXTS`、`CONFIGURATION_STATUS_TEXTS`、`CONFIGURATION_STATUSES`）降级为**接口不可用或字段缺失时的兜底**：页面在元数据加载失败时仍可用稳定取值渲染，不出现空下拉或空文案。`useEnumMetadata` 按 API Client 实例缓存同一枚举名的请求，失败时清除缓存以便重试；加载失败不改判为页面错误，仍由宿主统一展示 API 错误。

筛选口径：标准项目编码与配置状态筛选由页面在**已读取结果上本地执行**，不下推服务端——下推会缩小读取范围，破坏新增排除集合的完整性；服务端查询契约保留同名字段，其端口与 SQL 面由后端矩阵 V12-V14 覆盖。枚举契约（`MedicalItemType`、`ConfigurationStatus`）已于 2026-09-16 修复为在 OpenAPI 中声明取值与中文说明，生成端按数值读写，因此"不下推"是业务口径而非契约限制；细节见阶段 `testReport.md` 的枚举契约修复节。配置状态筛选的**选项标签**取自枚举元数据接口（兜底为本地常量），筛选仍是本地判定：元数据只提供展示文案，不改变筛选位置与范围。

枚举元数据接口**不属组织范围数据**：服务端 `POST /Api/EnumMetadata/GetEnumMetadata` 只接受 `enumName`（无组织入参），返回的是启动时由 SourceGen 描述器投影出的**进程级静态表**（枚举成员取值与 `[Description]` 中文），不读业务数据、不按调用方组织过滤；因此 `useEnumMetadata` 的缓存身份是「API Client 实例 + 枚举名」，同一 client 换组织时数据完全相同，按组织再分维度只会重复请求同一份数据。请求时机由 `enabled` 门控：可信组织不可用时页面整体为「组织范围不可用」阻断分支、不渲染任何需要枚举文案的区域，此时不发起该请求（该开关只改请求时机，不参与缓存口径，也不引入新的数据来源）。**边界**：若将来该接口改为按组织交付文案，缓存键与失效时机必须同步加入身份维度，不能沿用当前口径。

API Client 按累计范围生成：保留阶段1已交付 F01 接口，加入阶段2稳定契约；排除后续阶段接口及 `/auth/login`。生成前核对累计清单，生成后核对公开入口、Request/ReadModel 字段、nullable、enum 和无残留后续端点。生成入口、配置和 `kiota-lock.json` 受版本控制，生成过程不得提交本机路径、日志或临时文件。

页面不新增业务错误类型、拦截器或权限模型。所有写失败保留输入；写成功关闭弹窗，刷新失败不改判为写入失败。
