`UsageStatus` 契约固定为数字枚举 `Unused=0`、`InUse=1`；生成客户端、适配映射与页面判断必须一致，按 C27 核对，按 C67 验证状态转换。刷新未就绪的「未知」使用前端读取状态表达，不新增业务枚举值或默认映射为 `Unused`。

同一客户端包采用「已交付范围 + 本阶段稳定契约」累计生成，公共维护规则见 [总体实施](../../001-总体计划/impl.md) 第 2.5 节。本阶段仍只纳入 F01，不提前生成 F02；后续阶段不得因只选择当期模块而移除已交付 F01 的接口、类型及公开入口，须核对既有消费者兼容性。本轮只更新规则，不重生成。

选中空分类修改项目类型的顺序沿用 A2：成功重载后先按同一分类 ID 的实际新类型同步控件与 scope，再进行适用状态回退判断；不因旧类型范围先回退。C3 在名称搜索为空、显示停用开启的独立起点验证两种类型方向及启停状态，保留分类选中和右侧条件；不将此确认扩展为名称搜索组合细化的批准。

**A2 呈现与筛选实施约束**：树标题仅名称与停用标记，编辑/更多图标常显固定槽，默认展开且可收起；使用情况移至编辑弹窗只读展示，保留 `UsageStatus` 与类型冻结。左侧显示停用默认勾选，取消时隐藏停用分组，停用分类按名称搜索命中的启用分组保留必要祖先展示。**scope 回退单独按忽略名称搜索的状态树判断**：选中节点不满足状态显示时回退最近满足状态条件的祖先，否则对应类型根；祖先判断也忽略名称搜索。写后成功重载确认节点不存在时，沿旧祖先链查找仍存在且满足状态条件的祖先；读取失败不能当作节点不存在。仅名称隐藏不改 scope，切换显示停用或重载也不因此回退；重新显示不恢复旧选择。新增保留当前 scope 及全部筛选，不自动选择新增对象、清筛选或强制出现，未命中仍可保存成功。左树不额外裁剪右表数据，仅状态树回退改变 scope；右表独立 Segmented 仅过滤项目 `IsValid`。类型与 scope 联动，回退保留右侧条件；右侧重置不改左侧状态。进入默认检验根、显示停用=true、右侧全部及文本筛选为空，不持久化。对应 C1/C8/C14/C35、C19/C21、C31–C34、C50/C68/C70–C73；正式用例均为 `NotRun`。

**编辑与保存的实施约束**：按 S1-D26 最终规则落实分类、分组名称及备注可编辑，不因自身、父级启停或已有下级限制；分类存在任何分组（含停用）时只冻结 `ItemType`，无分组时可改；分组创建后归属永远不可改，无拖拽、改挂，所属分类只读展示且不进入更新 Request；项目仍仅备注可改。名称唯一性仍为分类全平台唯一、分组分类内唯一，查重排除自身；新增仍校验启用父级。对应 C3–C5、C12–C13、C37–C40、C51–C56、C66、C68。

**可达入口与验证边界**：按 A2 保留停用分类新增分组入口及弹窗停用分类选项的禁用状态（C9、C39），启停仅提供当前状态的反向操作（C7、C45）。C68 只通过取消显示停用隐藏唯一停用分组；名称搜索按 C34 验证分类命中保留下级、分组命中保留祖先、均不命中一起隐藏，不为测试改变原型。必填文本缺失、空串、纯空白及实际可编辑必选项缺失按 C62 验证本地反馈、零写请求与输入保留；不解除只读/冻结限制或新增长度、字符集要求。C28、C42 的 Contract 验证仅证明本层契约与错误传播，不证明真实后端拒绝或宿主提示；后端拒绝由后端矩阵承担，可达业务失败的宿主提示与输入保留由 C62 等 Host 用例承担。

父级停用不限制既有分组或项目的独立启用（C45），不得复用新增的父级有效性限制；顺序操作后核对自身启用、父级状态不变及项目仍无效，不引入并发测试。C20 验证树中分组归属和选择分类仅改变右表范围、不发筛选请求；后端按分类查询分组不作为页面调用路径。

新增项目的停用分类/分组选项禁选由 C41 验证，不用 Contract 模拟拒绝代替。C65 分别装配未完成读取与携带未知枚举的成功响应，验证保护及合法响应恢复，不把防御数据当正常业务数据。C49/C63 用六类弹窗的适用字段验证放弃脏输入、清除校验错误、同对象重开和换对象，不为备注弹窗伪造必填规则。

**提交与验证约束**：保存提交整份可编辑资料和必要目标标识，分类为 `ItemType/Name/Remark`（类型冻结时发送原值），分组为 `Name/Remark`，项目修改仅为 `Remark`。`Remark` 未改发送原值、清空发送显式 `null`，不得省略；完全同值也正常提交，不增加 dirty 比较。同值保存由后端正常校验、保存、更新 `OperId/OperTime` 并登记修改事件；启停仍独立操作，重复启停幂等规则不变。按 C52、C57、C61 核对实际序列化请求与提交次数，后端审计和事件以实际后端证据验证，不能用页面成功提示替代。

C44 按分类、分组、项目及启停方向参数化验证确认框：打开及确认前零写请求，取消或关闭后仍零写请求，状态和 scope 不变；再次打开并确认后才提交。保留确认文案与不级联断言，不用六类维护表单的取消证据代替启停确认框。C57 的 Component/Contract 同时覆盖三类新增表单未填备注的完整链路，序列化请求须包含 `Remark: null`，不得省略、发送 `undefined` 或空字符串；C1/C8/C14 各取代表性 Host 实际请求核对，无需扩展全部新增组合。

原型弹窗 `toRemark` 的无条件 trim/空串转 null 是已知业务偏差，不在 A2 布局交互绑定范围内，正式实现不得复用。表单保留原始备注和主动清空意图，原 `null`、`""`、`" 原文 "` 未改均原样提交，非空新输入不 trim；编辑时主动清空发送 `null`，新增未填写也发送 `null`，未改原 `null` 保留 `null`。C52 从真实表单起点核对实际请求与读回，C57 分开记录 Component 表单链路和 Contract 映射证据，不只从适配输入证明表单正确；记录原值不用于禁用同值保存。本轮不修改原型代码。

**读取与写后恢复**：C58 由组件实际加载/重载入口触发，在 API Client 读取边界用可控 Promise 安排返回顺序，不依赖真实后端或固定等待；同一集合只接纳最新读取，本地筛选不发请求。写成功即关闭弹窗，与集合刷新分开；部分失败保留旧数据并标明待刷新，派生状态标未知，限制依赖旧关系的写操作，只重试读取，不重放成功写入（C59/C69）。C14 从独立空分组新增首项目，核对分组重读及 `Unused→InUse`，名称备注仍可编辑；C67 保留分类新增首分组与既有分组停用后恢复的独立起点，C6 覆盖分类恢复，不用读取恢复替代业务恢复。

**可信身份及证据装配**：按既有规范承接有效主体 A→B 及可信组织、路由、业务视角变化，取消可取消的旧读取并使全部旧读取失效，清理选择、缓存、详情、编辑输入、校验和弹窗；新上下文就绪后按默认态重新加载。不得让 A 的迟到响应恢复 B 的旧表单或覆盖新数据；已发写请求不能因取消而宣称回滚，不重放写入，旧写结果与新状态隔离并通过可信读取核对。C64 Component 使用测试装配的可信 Context 和可控读取验证缺失/失效/有效切换；Host 只用实际登录、菜单、退出或宿主支持的切换/失效流程独立取证。不可达分支如实记录边界，不注入页面身份或新增生产测试入口，不假定宿主切换必定卸载。

接口、宿主或账号未就绪时记录受影响范围，继续独立工作；**不使用本地页面或 mock 替代真实宿主验收**。
