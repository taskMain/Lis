### 页面结构

单一页面，左右分栏：

**左侧「目录」区**

- `antd` `Tree`，三级结构：类型（检验/检查，两个固定根节点）→ 分类 → 分组。
- 节点标题只显示名称与停用标记；启用节点不显示启用标签，使用情况移到分类、分组编辑弹窗只读展示。
- 节点右侧操作图标常显并使用固定槽位，不依赖悬停出现：分类、分组显示编辑与更多图标（含 Tooltip）；更多菜单按节点类型提供新增分组、启用/停用等操作，类型根节点提供新增分类。操作能力不因标题精简而减少。
- 节点操作按钮点击时阻止冒泡，避免改变右侧列表范围。
- 树上方提供：分类或分组名称过滤输入；类型单选（全部/检验/检查）；Checkbox「显示停用」，默认勾选。
- 树默认全部展开，允许手动收起与再次展开。

**右侧「标准项目列表」区**

- 筛选条：编码、名称、状态 Segmented（全部/启用/停用，默认全部），不使用状态 Select；操作：重置、新增项目。状态仅按项目自身 `IsValid` 筛选，与左侧「显示停用」独立，不按「当前有效」筛选。
- 表格列：编码、名称、类型、分类、分组、状态、当前有效、备注、操作。
- 行操作：修改备注（弹窗）、启用/停用。
- **不使用分页**：一次展示全部数据，不渲染分页控件。
- 空结果展示空态，不报错。

### 交互规则

| 规则 | 实现口径 |
|---|---|
| 树选中即筛选 | 选中类型/分类/分组后，右侧列表按已加载完整数据本地过滤；选中类型根节点时按类型过滤 |
| 类型与 scope 联动 | 类型选择「全部」时展示两个类型根且 scope 为全部；选择检验或检查时 scope 切到对应类型根。选中树内类型、分类或分组时，scope 切到对应节点，类型控件同步为所属类型；右侧编码、名称、状态条件保留。修改当前选中且无分组的分类类型后，沿用 A2：成功重载后先按同一分类 ID 的新类型同步类型控件及 scope，再判断状态回退；不得因旧类型范围不含该分类而退回旧类型根。分类仍满足状态显示时保留该分类选中与右侧条件；这是已确认的 A2 联动，不代表名称搜索等组合细化已获确认 |
| 筛选执行位置（必须逐项固定） | **目录树名称过滤**：本地过滤，只裁剪已加载的树节点，不发起请求。**类型单选**：本地过滤已加载的完整分类、分组和项目数据，不发起请求、不改动 API 入参。**右侧列表的编码/名称/状态筛选**：本地过滤已加载项目，不发起请求，分别按 `Code`、`Name`、`IsValid` 语义执行。**分类名称过滤**：本地过滤；有效目录查询的 `CategoryName` 入参只服务于该查询本身，本阶段页面不消费它。该页面数据量较小，前端参与过滤是本 MVP 的明确取舍。 |
| 左树停用过滤与必要祖先 | 勾选「显示停用」时，启用与停用节点均按原名称搜索规则参与展示。取消勾选时隐藏自身停用的分组；停用分类若仍有符合搜索的启用分组，作为必要祖先保留，且仍可选择、编辑和执行启用；否则隐藏。启用分类仍按原搜索规则展示。此为树的本地可见性过滤，不以整条链路当前有效为条件 |
| 状态过滤后的选择回退 | 回退依据是**忽略名称搜索的状态树**：按类型与显示停用构建，取消显示停用时停用分组不在其中，停用分类有启用分组时仍作为必要祖先保留。选中节点不满足该状态树时，沿完整关系回退最近满足状态条件的祖先，否则对应类型根；祖先判定同样忽略名称搜索。写后成功重载确认节点不存在或不满足状态显示时使用同一规则，节点不存在时沿重载前已知祖先链查找仍存在且满足状态条件的祖先。读取失败不等于节点不存在。仅被名称搜索隐藏的节点保留 scope，即使切换显示停用或写后重载也不因此回退；回退目标可仍被名称搜索隐藏。右侧编码、名称、状态保留，重新显示不自动恢复旧选择 |
| 左右过滤边界与关系判断 | 名称搜索沿用 A2：分类名命中时保留该分类下符合状态显示条件的分组；仅分组名命中时保留该分组及必要祖先；两者均不命中则隐藏该分类。显示停用开启时，名称搜索不能隐藏唯一分组却保留其分类。左侧名称搜索、显示停用仅裁剪树的展示，不额外裁剪右表完整项目数据，只有选择回退导致的 scope 变化例外。类型与 scope 联动仍按对应规则执行。隐藏节点**仍参与**完整关系、使用情况、类型冻结和当前有效判断，不能将隐藏下级当作无下级 |
| 右侧重置 | 仅清空右侧编码、名称并把状态恢复为「全部」；不改变左侧类型、名称搜索、选中 scope、显示停用与展开状态 |
| 新增后的范围与可见性 | 新增成功后保留现有 scope 与全部筛选，不自动选择新增对象、不清空筛选、不强制显示新增结果。只有新增对象命中当前树展示或右表 scope 与筛选时才显示；未命中仍是新增成功，按写后刷新规则读取完整集合。原选中节点若不存在或不满足状态显示，仅按状态树规则回退 |
| 派生判断的数据来源 | 分类 `ItemType` 冻结判断与「使用情况」取自**查询返回的派生字段**（`UsageStatus`，S1-D22）与所选范围对应的**已加载完整集合**，不依据筛选后可见行的数量推断。当前有效的父级状态同样不得从被筛选/被裁剪的可视集合推断。**未就绪行为**：查询未完成或失败时，分类类型冻结与使用情况标记为「未知」，不按默认值放行类型修改；不得据此冻结已完整回显的名称、备注。无法取得完整可编辑资料时禁止提交 |
| 写后刷新范围 | 任一写操作成功后，**重新加载受影响的集合**：新增/编辑/启停分类或分组 → 重载目录树与当前列表；新增/编辑项目、改备注、启停项目 → 重载当前列表；影响上级「使用情况」或下级「当前有效」的操作 → 一并重载对应集合。特别是空分组新增首项目后重读分组集合，使 `UsageStatus` 从 `Unused` 更新为 `InUse`，重开编辑弹窗展示已使用；不因此冻结分组名称、备注 |
| 写成功与刷新失败 | 写请求成功即关闭维护弹窗，写入结果与后续读取结果分别处理；刷新失败不改判为写入失败、不恢复可再次提交的原弹窗。写后重载未完成或部分集合刷新失败时，保留旧数据供查看并标明待刷新，但受影响的「使用情况」「当前有效」及分类类型冻结判断标为「未知」，不得把旧数据或新旧混合集合当作当前有效事实。限制依赖旧关系、状态或旧回显资料的写操作，恢复读取后再放行；不因此新增名称、备注的业务冻结规则。重试只读取待恢复的集合，不重放已经成功的写请求 |
| 新增与修改 | 全部通过弹窗完成：新增分类、编辑分类、新增分组、编辑分组、新增标准项目、修改备注，共 6 个弹窗 |
| 编辑表单不含启用开关 | 分类与分组的编辑弹窗包含可编辑资料及只读使用情况（分组另有只读所属分类），不含启用开关；启停状态只能通过节点或行上的独立启用/停用操作改变 |
| 分类可编辑资料 | 名称、备注始终可编辑，不受自身启停或已有下级限制；分类有任何分组（含停用）时仅 `ItemType` 置灰并说明原因，无分组时可改类型。分类名称全平台唯一，修改时查重排除自身 |
| 分组可编辑资料与归属 | 名称、备注始终可编辑，不受自身、父级启停或已有项目限制；名称在所属分类内唯一，修改时查重排除自身。创建后 `CategoryId` 永远不可改，无论是否有项目；可只读展示所属分类，但更新 Request 不提交 `CategoryId`，也不提供拖拽或改挂 |
| 标准项目仅备注可改 | 标准项目的修改入口只提供备注；编码、名称、分类、分组不可通过普通修改改变 |
| 启停确认 | 只提供当前状态的反向操作：启用对象显示停用，停用对象显示启用，不提供同方向重复调用入口。父级停用不限制既有分组或项目的独立启用，不复用新增时父级必须启用的限制；启用后仅自身状态改变，父级仍停用时项目仍非当前有效。可执行的启用与停用均弹出确认框，文案明确"该操作只修改当前数据状态，不会级联修改下级状态"。打开确认框不发写请求；确认前及取消、关闭后均为零写请求，数据状态与 scope 不变；再次打开并明确确认后才提交，仅改变目标自身状态，不级联。分类、分组、项目及启停方向按 C44 参数化验证；后端重复调用幂等由后端矩阵验证，不为 Host 测试新增入口 |
| 上级有效性提示 | 新增仍校验启用父级：新增分组要求分类启用，分类停用时禁用节点的新增分组入口，新增分组弹窗中的停用分类选项也禁用并标明停用；新增标准项目要求分类和分组均启用，弹窗的停用分类与停用分组选项均标记停用并禁选。新增标准项目时**切换分类必须清空已选分组**，分组选项只列出该分类下的分组，使「分组不属于所选分类」的组合在页面上不可提交。该新增约束不用于阻止既有分类或分组的名称、备注编辑 |
| 当前有效的呈现 | 列表展示派生结果（标准项目自身、所属分组、所属分类均启用），不可用时以悬浮说明给出原因。分类或分组重新启用并完成读取后，完整启用链路恢复有效；分组或项目自身仍停用时继续无效，恢复父级不改变下级自身状态 |
| 使用情况的呈现 | 分类与分组的使用情况仅在各自编辑弹窗只读展示（已使用 / 未使用），文案取查询返回的 `UsageStatusText`；树节点不展示。`UsageStatus` 契约与分类 `ItemType` 冻结判断保留且同源，分组使用情况不决定名称、备注或归属的可编辑性；标准项目的使用情况本阶段不展示（S1-D21、S1-D32） |
| 状态恢复 | 不保留：每次进入默认选择检验及其类型根 scope，显示停用=true，右侧状态为全部，左右文本筛选为空，树默认展开。不写入 URL 参数，不做持久化 |
| 异步与竞态 | 初次加载和写后重载期间正确维护 loading；查询失败不得用空结果覆盖已有数据，受影响的派生判断标为未知。对同一集合重叠的真实加载、重载请求，只接纳最新一次读取的结果；较早发起的请求即使迟到也不得覆盖新结果或清除未知状态。筛选为本地计算，不发请求；读取完成后按当前筛选计算可见结果 |
| 可信身份生命周期 | 上下文身份未就绪时不可写，失效时按平台错误边界处理。有效主体 A 切换为 B，以及可信组织、路由或业务视角变化时，取消可取消的旧读取并使旧读取结果失效，清理旧选择、缓存、详情、编辑弹窗、未保存输入和校验状态；新上下文就绪后重新加载并按进入默认态建立状态。旧响应不得覆盖新上下文、恢复旧编辑状态或清除新 loading；不新增角色系统或改变全平台目录范围。已发写请求的取消不能证明服务端回滚，不自动重放；旧写响应不得恢复旧弹窗或污染新状态，结果需要在可信上下文下重新读取核对 |
| 保存与完整提交 | 点击保存即提交整份可编辑资料，即使与回显值完全相同也提交，不加 dirty 比较、不因同值禁用保存。分类提交 `ItemType`、`Name`、`Remark`（冻结的 `ItemType` 保持原值）；分组提交 `Name`、`Remark`，不提交 `CategoryId`；项目只提交 `Remark`，各请求保留必要的目标标识。`Remark` 必须发送原值或显式 `null` 清空。同值保存仍由后端正常校验、保存、更新 `OperId/OperTime` 并登记修改事件，不套用重复启停的幂等规则 |
| 提交与失败恢复 | 提交中禁用重复提交；**写请求失败保留已填输入**，不自动关闭弹窗，列表既有数据不变。写成功立即关闭弹窗；后续刷新失败按读取失败恢复，不提示重新保存。读取恢复后重新打开编辑，即使完全同值仍可正常保存 |
| 必填本地校验 | 从合法表单起点逐项检查实际必填字段：分类新增/编辑的名称和可编辑类型、分组新增/编辑的名称及新增时所属分类、项目新增的编码/名称/分类/分组。必填文本缺失、空串或纯空白，以及必选项缺失均在本地反馈并阻止写请求，保留其他输入；只读归属与冻结类型不为测试改成可清空控件，备注仍可空，不新增未确认的长度或字符集规则 |
| 弹窗生命周期 | 关闭弹窗后清理未保存输入、校验错误与表单交互状态；重开同一对象使用已保存资料，新增弹窗恢复合法默认值，不保留已放弃输入。**切换编辑对象后必须重置表单、分类类型冻结状态、分组归属只读展示与焦点**，不得残留上一个对象的值；六类弹窗按适用字段验证，不为无必填字段的备注弹窗伪造校验错误 |
| 未知枚举与依赖未加载 | 遇到未知枚举值按统一规则安全展示，并**禁用基于该值的写操作**，未知 `UsageStatus` 不默认映射为 `Unused` 或放行类型修改；合法响应恢复后按真实值解除相应保护。依赖集合（分类、分组）未加载完成前禁用相应写入口；未知枚举成功响应与读取未完成是两个独立防御分支。**取值域的边界（S1-D32）**：`UsageStatus` 由「是否存在下级」在查询内派生、集合封闭，服务端对该值的未登记取值按严格解析失败（整条列表查询返回平台统一错误），因此真实后端不会返回「含未知 `UsageStatus` 的成功响应」；本行的未知分支对 `UsageStatus` 属**防御性展示**（同时兜住读取未完成与契约假数据），在组件层以契约形态数据验证，不声称真实后端可达。项目类型取自无存储约束的列，服务端对未登记取值返回空文案，页面按「未知类型」展示 |
| 错误展示 | 按平台错误边界处理：使用统一提示组件，不新增错误拦截器、不解析异常文本、不生成页面专用提示；微前端环境下已被宿主上报的接口错误不重复提示 |
| 只读边界 | 前端不判断操作权限。能进入页面即视为已获授权；权限不足由后端拒绝并经宿主提示 |

### 页面不提供的操作

- 物理删除（分类、分组、标准项目均不提供）。
- 分类、分组的业务 `Code` 字段；关联使用 Guid，不以名称作为关联键。
- 分组拖拽、改挂或任何修改所属分类的入口。
- 分页控件。
- 按 ID 取单条查询的独立入口（编辑回显使用列表数据）。
- 展示或维护医院院内项目编码、院内项目名称或任何项目对照信息。
- 标准项目的使用情况（按 S1-D21 已同步至 SRS「标准医疗项目管理」的范围延期，MVP 阶段不展示也不返回；分类与分组的使用情况仍按 S1-D21 展示）。

### 界面边界

页面布局、控件类型、菜单位置与视觉样式已按 SRS 授权通过 A2 确定，不得减少规约定义的业务能力、查询条件、状态提示或权限边界。正式实现沿用该布局与交互，接入真实 API、身份、校验及失败恢复，不上线模拟数据、内存 store 或方案切换器；原型确认不等于正式实现或宿主验收通过。

## API 与组件

### 依赖的公共契约

页面通过本子应用已有的 API Client 上下文访问后端，不自行创建适配器或 Client 实例。本阶段涉及的接口：

| 接口 | 用途 |
|---|---|
| `CreateMedicalStandardCategory`、`UpdateMedicalStandardCategory`、`EnableMedicalStandardCategory`、`DisableMedicalStandardCategory` | 分类维护 |
| `CreateMedicalStandardGroup`、`UpdateMedicalStandardGroup`、`EnableMedicalStandardGroup`、`DisableMedicalStandardGroup` | 分组维护 |
| `CreateMedicalStandardItem`、`ChangeMedicalStandardItemRemark`、`EnableMedicalStandardItem`、`DisableMedicalStandardItem` | 标准项目维护 |
| `QueryMedicalStandardCategoryList`、`QueryMedicalStandardGroupList`、`QueryMedicalStandardItemList` | 列表查询、筛选与「使用情况」派生值 |

`QueryEffectiveMedicalStandardCatalog` **本阶段不被页面消费**：该查询属 F01 要求的后端能力，交付后端与契约，其页面消费方在阶段 2 及以后建立，因此不进入前端矩阵的页面级用例。见 [后端设计](../Server/design.md) 的「本阶段查询的对外暴露范围」。

客户端生成范围按本模块 12 个写命令、3 个列表查询及有效目录查询的已确认契约逐项核对 path/operationId；有效目录只核对生成契约，不增加页面调用。排除 F02、后续阶段、`/auth/login` 及目录物理删除操作；生成包公开入口、稳定 OpenAPI 来源和锁文件排除规则由 C27 验证，包及子应用构建检查由 C29 验证。客户端未生成某操作不证明服务端未暴露该操作，服务端公开面由后端独立取证，不执行真实删除来做负向验证。

这些接口当前**尚未在后端暴露**：阶段 0 基线显示后端只有 16 个写接口（其中本模块 12 个）且全部因语句解析问题不可用，20 个查询全部未生成。因此 API Client 需在阶段 1 后端契约稳定后按本模块范围重生成。

### 生成契约的修正

本模块 ReadModel 与请求契约的修正如下，重生成 API Client 后必须逐项核对（见[阶段设计](../design.md)的「ReadModel 契约修正」及 S1-D26）：

| 类别 | 内容 | 核对点 |
|---|---|---|
| 修复生成退化 | `ItemType` 改为 `MedicalItemType`；层级集合改为嵌套 ReadModel 类型 | 生成结果中不再是 `object` |
| 有意改变契约 | 三个 List ReadModel 与有效目录层级内明细的 `Remark` 改为可空；分类与分组 List ReadModel 新增 `UsageStatus` | 可空性一致；`UsageStatus` 为数字枚举，固定 `Unused=0`、`InUse=1`，不得颠倒或按字符串处理；层级明细的 `Remark` 也已可空 |
| 编辑与关联契约 | 分类、分组无业务 `Code`，以 Guid 关联；更新分组 Request 不暴露 `CategoryId`；保存提交完整可编辑资料 | 分类含 `ItemType/Name/Remark`；分组含 `Name/Remark`；项目修改仅含 `Remark`（均另含必要目标标识）；实际请求不得省略 `Remark` 或以同值为由跳过提交 |
| 操作信息契约 | 有效目录明细返回 `OperId/OperTime`，不再返回 `LastUpdatedTime` | 生成类型与映射使用已确认的操作人、操作时间字段 |

**页面展示的「当前有效」列**不在 UML/SRS 的展示清单内，属本阶段经确认新增的派生呈现（S1-D16），其口径为「项目自身、所属分组、所属分类均启用（业务规则 5）」，不可用时以悬浮说明给出原因。该项不改变后端查询契约。

分类与分组编辑、完整保存的最终规则见阶段决策 S1-D26。现有统计设计没有分类、分组快照，按当前目录归类；本阶段不新增快照或其他统计字段。

### 组件与职责划分

按"可独立测试"的粒度拆分，页面只做编排：

| 单元 | 职责 |
|---|---|
| 页面容器 | 路由入口、数据加载编排、选中范围与筛选状态、弹窗开关 |
| 目录单元 | 树的构建与渲染、节点标题与状态标签、节点上下文操作的分发 |
| 目录节点操作规则 | 按节点类型决定可用操作集合（纯函数，可独立测试） |
| 项目列表单元 | 筛选条、表格列定义、行操作、空态与加载态 |
| 维护弹窗单元 | 新增/编辑分类、新增/编辑分组、新增项目、修改备注各自的表单与校验反馈 |
| 冻结与派生判断 | 分类是否存在分组对应的 `ItemType` 冻结判断、当前有效的派生判断（纯函数，可独立测试）；分组归属恒定不可改，名称与备注不依赖使用情况冻结 |
| 契约适配 | 请求参数组织、响应解包、可空归一、DTO 到视图模型映射 |

拆分理由：本阶段的业务规则多于对标实现（唯一性、上级有效性、字段冻结、启停幂等、派生有效），把规则判断与渲染分离后，前端测试矩阵的用例才能落到具体单元上独立验证。

### 适配与组件约定

- 本地文本筛选采用字面包含匹配：筛选输入去除首尾空白后与字段统一小写比较；空串或纯空白撤销该条件，`%`、`_` 为普通字符，不支持通配符。多个条件按与关系组合。不承诺与数据库排序规则完全等价，也不向 API 提交空筛选。初次加载和写后重载不带筛选条件，取得完整分类、分组和项目集合后再计算本地可见结果。

- 适配层负责请求参数、响应解包、可空归一与映射；不在 JSX 中散落日期解析、枚举兼容或空值猜测。
- 业务判断使用生成枚举；`UsageStatus` 固定 `Unused=0`（未使用）、`InUse=1`（已使用）。未知枚举按统一规则安全展示；加载或刷新失败的「未知」属于前端读取状态，不新增业务枚举值，也不得默认映射为 `Unused`。
- **枚举中文来源（S1-D32）**：展示文案按「查询行内的随行文案 → 枚举元数据接口 → 本地兜底文案」取值，前者是服务端枚举 `Description` 的唯一来源投影；页面只按数值做业务判断。表单可选项与筛选项取枚举元数据接口（按枚举名缓存的静态表，与组织范围无关），接口不可用或返回空集合时用本地兜底文案保持可维护。兜底文案与后端枚举 `Description` 同名同值，不构成第二份业务事实；项目类型的取值域、取值域判定与兜底文案位于跨页面共享模块 `src/shared/medicalItemType.ts`（本页适配层按既有名字转发），使用情况的对应事实只服务本页、留在本页适配层。适配层把缺失、空串与纯空白的随行文案统一归一为「无文案」，且按取值域判定兜底（越界、`NaN`、`undefined` 与字符串下标一律显示未知，不渲染空文本、也不伪造成已知文案）。树节点、范围文案与列表「类型」列只拿得到枚举数值，其中列表「类型」列优先取行内随行文案。
- 请求必填字段不得用空字符串、零或非空断言伪造。
- **`Remark` 的可空语义**：`null` 与空字符串可在展示层统一为空，但表单保留原始值及主动清空意图，不用展示值覆盖原始值。未改时发送原值，包括原 `null`、`""`、`" 原文 "`；主动清空发送显式 `null`，非空新输入原样发送，不做 `trim()`；新建未填写时显式发送 `null`。仅区分原值与清空语义，不据字段是否修改禁用保存或跳过同值提交。表单、适配层与实际序列化请求均须保留 `Remark`，不得以缺失或 `undefined` 表示未改。C52 从真实表单验证原值提交，C57 分别验证组件表单链路和适配契约，包含分类、分组、项目三类新增表单未填备注时显式 `Remark: null`；C1/C8/C14 各以代表性 Host 路径核对实际请求，不重复全部组合。
