## 3. 参照项目的实际写法

`SpecimenPackage.cs`、`Application.cs`、`ApproveApplicationCommand.cs` 三个样本一致：

```csharp
/// <summary>
/// 样本包
/// </summary>
public partial class SpecimenPackage : Dy.Core.Abstractions.Domain.Entity
{
    /// <summary>
    /// ID
    /// </summary>
    public partial Guid Id { get; set; }

    /// <summary>
    /// 发起组织编码。
    /// </summary>
    public partial string InitiatorOrganizationCode { get; set; }

    /// <summary>
    /// 发起方申请单号；与发起方完整路径共同构成创建幂等身份，创建时必填。
    /// </summary>
    public string ApplicationNo { get; set; } = string.Empty;
```

**口径**：
1. 属性 summary 是**一句名词短语**，点明业务概念即可；简单字段就是「主键。」「平台申请单号。」
2. **只在存在不明显约束时**，在同一句后**用分号追加一个分句**（来源、幂等身份、创建时必填、页面值与 Token 值的区别等）。
3. **不把类级规则重复抄到每个属性上**。
4. `<summary>` 内**不用 `<para>`/`<list>`** 结构。

规范第 3 节首句即「注释服务于契约和维护风险，**不以成员数量或形式完整制造无意义文字**」；第 1 节完成闸门包含「必需 XML 注释缺失、与实现不一致或只复述名称」。参照项目按此口径执行：简单属性保持简短，**不算复述名称**。

## 4. 本仓库的偏差（改写前状态，已完成收敛）

改写前的写法是**散文式论述 + 把类级规则复制到每个属性**，典型如：

- 实体 `OperTime`：每个实体重复「该列在表结构层面由数据库当前时间写入，应用层命令携带的操作时间只用于领域事件，两者时钟不同源」
- 实体 `IsValid`：每个实体重复「停用是软删除手段，数据保留可再启用…不级联改写下级」
- Dto `Remark`：重复「整份提交，传 null 表示清空备注，内容相同仍会保存并刷新操作字段」
- 类型级 summary 写成 150-208 字的段落式论述

这违反规范首句的取向：把同一个约束在 N 个成员上各写一遍，属于「以形式完整制造无意义文字」。

## 5. 改写口径

| 内容 | 归属 |
|---|---|
| 该成员是什么业务概念 | `<summary>`，一句名词短语 |
| 该成员自身的不明显约束（来源、幂等、必填时机、可空语义、取值域） | 同一 `summary` 句内分号追加，或该成员自己的 `<summary>` 第二句 |
| 类级/聚合级规则（软删除语义、唯一性范围、时钟来源、事务口径等） | **类型级 `<summary>` 或 `<remarks>`，只写一次**；成员级不重复 |
| 方法参数与返回（行数语义、空值语义、排序） | `<param>` / `<returns>`，保持具体但简短 |
| 可预期异常 | `<exception>`，说明触发条件 |

同时移除 `<summary>` 内的 `<para>`/`<list>` 结构。

**关于 `<inheritdoc/>` 的实际生效方式（实测）**：C# 编译器**不会**把 inheritdoc 展开成文本，而是在生成的 XML 里**原样写入 `<inheritdoc/>`**（`-p:GenerateDocumentationFile=true` 后 `Dy.MedicalRecognition.Repository.xml` 中该方法条目内容就是 `<inheritdoc/>` 一行）。展开由 IDE / 文档工具在使用时完成，前提是**被继承程序集的 XML 文档与程序集同目录**。本仓库默认未开启 `GenerateDocumentationFile`（`Directory.Build.props` 未设置），所以：

- 规范第 2 节「接口实现可用 `inheritdoc`，但成员仍必须保留 XML 文档节点」**已满足**（节点存在，`CS1591` 不触发）；
- 但要让 IDE/工具真正展开出文本，需要在 `Directory.Build.props` 开启 `GenerateDocumentationFile`。开启后会把 332 条 `CS1591`（全部为阶段 2 的 `Mutual*` 成员与 `.g.cs`/`ReadModels` 生成物）变成构建警告，需要同时决定 baseline/`NoWarn` 口径。**属构建配置变更，本轮未自行改动。**
