## 10. 阶段 7 横向治理与发布收口

1. **跨模块一致性核对**：患者信息脱敏、页面数据权限、可信组织范围校验在全部页面与接口上的一致性；发现不一致时按最小修复处理，不做重构。
2. **排除项回归确认**：逐条确认 SRS 的排除项与设计约束中的不建设内容未被实现。
3. **发布前全量联调与证据收口**：宿主链路全量回归、各阶段证据汇总、残余风险登记、阶段入口表收口。
4. **本阶段不新增业务功能、不做重构式治理。**
5. **不单设代码审查阶段**：代码审查按需在各业务阶段内进行，结论写入该阶段根 `testReport.md`；本阶段只做跨模块一致性、排除项回归与发布收口三类事。
6. **发布收口判定**（开始时冻结，执行中不得放宽）：冻结本轮矩阵版本与分母（本阶段新增用例 + 各阶段现行矩阵非干净条目的过堂清单；既有 `Passed` 条目的复用按阶段、按验证面分项登记复用条件，收口报告分类列出复用/失效/重测项）；非干净条目按三出口定级——补证据转 `Passed`、经范围确认不适用于本轮的转 `N/A`、属本轮范围但不可构造或环境受限的保持原状态并登记 `AcceptedRisk`（定级残余）；只把 `Passed`、经范围确认的 `N/A` 与已定级残余计入完成，存在未定级的 `Blocked`/`NotRun`/`PendingRetest` 即不构成干净轮次；发布结论只输出 `Ready`/`ReadyWithAcceptedResiduals`/`NotReady`（`Ready` 无残余，`ReadyWithAcceptedResiduals` 残余全部已定级接受）；收口前核对宿主全链路回归、上游依赖与外部服务健康、测试数据余量、端口与进程边界、起始提交与工作区快照。判定条件全文见 [总体计划设计](design.md) 4.9。
