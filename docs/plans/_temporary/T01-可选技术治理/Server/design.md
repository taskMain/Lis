# 可选技术治理后端设计

设计状态：已确认。整体边界见[阶段设计](../design.md)。

## 组织路径参数

涉及 `server/Dy.MedicalRecognition.Application/Validation/OrganizationPath.cs` 及同目录 `OrganizationPathResolver.cs`。

保留 `OrganizationPath` 的九个字段、顺序、类型和访问范围。`FromScope` 与 Resolver 的所有构造处使用完整命名参数，每个参数独立成行；按医共体、医院、院区组织字段，显式对应各层的实例标识、名称和业务编码。

`FromScope` 继续使用 IAM 范围中的实例标识，缺失标识转换为 `Guid.Empty`，缺失名称或编码转换为空字符串。按提交编码解析的两处构造继续将实例标识置为 `Guid.Empty`，不改变校验、取名和缺失层级的规则。无需新增承载类型或公共辅助方法。

## 编码规范化语义

| 位置与用途 | `null`、空字符串、纯空白 | 带首尾空白的有效编码 | 处理决定 |
|---|---|---|---|
| `MedicalRecognitionReportQueryAppService.Citation.cs` 中的查询参数处理 | 空字符串 | 去除首尾空白 | 保留局部 `NormalizeCode`；证件号码继续在此基础上转换为大写 |
| `OrganizationPathResolver.cs` 中的编码收集与校验 | `null` | 去除首尾空白 | 保留局部 `NormalizeCode`；必需层缺失继续按该层文案拒绝，非必需层继续允许缺失 |

上表描述私有方法本身的转换规则。引用详情入口先执行 `MedicalRecognitionRequestValidator.Validate(request)`；`RecognitionCitationDetailRequest` 的证件类型与证件号码均受 `Required`、`NonEmpty` 校验，缺失、空串和纯空白在规范化与数据读取前被拒绝。

公共入口分别验证无效输入拒绝且参数与候选读取均为零，以及有效输入去除首尾空白、证件号码大写后的仓储参数。查询侧私有 `NormalizeCode` 的 `null` 转空字符串分支使用源码静态证据；不绕过请求校验、不使用反射调用，也不新增测试专用生产入口。现有测试已经表达同一行为时直接复用；仅为缺少的可观察边界补充测试。

## 生产注释范围

检索 `server` 中手写生产 C# 文件，排除测试、生成代码、第三方代码、`bin` 和 `obj`。登记临时计划编号、审查编号、整改批次及仅指向临时任务的说明；人工逐条判断命中内容，不能只按正则删除整行。

保留注释中的业务规则、边界、错误原因、顺序和 XML 文档节点。仅有临时编号的括号可以删除；以计划引用代替说明的注释改写为独立可理解的业务或技术说明。API 路径、业务编码、错误码、标准编号和测试标识不属于清理对象。文件清单在实施前报告，实际清理数量在根报告登记。

清理对象还包括以设计文档章节号或行号代替说明的注释（如「根 design.md 6.3」「第 42 行」）。理由是该类引用把注释的可读性寄托在外部编号上：设计文档改版后编号即失效，注释随之失去依据，读者也无法据注释本身判断规则。此类注释按被引章节的实际规则改写成自足说明；指向项目规范的章节引用若在规范中可解析，可保留。

全部改动属于手写源码；不生成代码，不修改实体、Repository/SQL、HTTP/OpenAPI、数据库、事务、事件或外部调用。现有组织路径与查询测试为主要基线；本阶段后端矩阵不需要真实数据库或真实 WorkUnit。前端宿主验收仍通过真实后端链路检查组织范围，见[前端矩阵](../Client/testPlan.md)。前端与其样式文件按同一范围与规则处理。
