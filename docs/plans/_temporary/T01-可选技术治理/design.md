## 现状与证据边界

- `HostSessionProvider.tsx` 保存 React 状态，`hostSession.ts` 另存 `latestSession`。Provider 会忽略身份事件后迟到的初始结果，但共享模块仍直接接收该结果。现有身份切换测试只断言 Provider 中的账号显示；需增加覆盖共享快照和命令式读取的失败测试。
- `OrganizationPath` 的构造目前包括 `FromScope` 和 Resolver 中两处显式构造。实施前重新检索全部调用，包括目标类型推断的 `new(...)`。
- 查询侧 `NormalizeCode` 将缺失值转换为空字符串；Resolver 将缺失或空白值转换为 `null`。两者按业务用途保留。
- 历史治理记录中的注释数量只作为检索线索。本阶段按当前手写生产文件重新登记位置与数量，不把历史数量作为验收分母。
- 上述内容为源码检查依据，尚未取得本阶段运行证据。

1. 设计确认与实施授权取得后，按端级任务开始代码工作；当前设计已确认，实施已完成（验收清单全部勾选），阶段收口状态：`Complete`（2026-10-27 负责人明确批准；完成确认不等于发布批准）。
2. 会话问题先取得准确失败测试；命名参数调整先取得等价行为基线；注释清理使用静态证据。不得为治理两处同名方法而统一其空值规则。
3. 改动既有 symbol 前按 GitNexus 规范核对索引并完成 upstream impact，完成后执行适用的 `detect-changes`。文档阶段不重建索引。
4. 两端矩阵、规定的全量测试、构建、静态检查、真实宿主验收和差异检查均应取得实际结果；历史测试数字不作为本阶段通过证据。
5. SDK 公开行为与设计前提冲突、组织身份或提交校验语义需要变化、需要修改共享宿主或出现范围外业务修改时，暂停受影响任务并说明影响。
6. 各受影响阶段的对应治理完成并取得适用验证结果后，按下表及时同步长期有效事实，不等待全部治理结束。正式文档不得引用临时目录；临时目录删除另行确认。
