# 可选技术治理前端测试计划

矩阵版本：2026-10-27 修订稿。设计依据：[前端设计](design.md)。本文件只记录场景和预期，结果写入[阶段测试报告](../testReport.md)。

## 范围与环境

自动化测试沿用现有 Vitest 与 React Testing Library。受控宿主适配器仅控制事件和 Promise 完成顺序，不代替真实登录、身份与组织权限验证。用例隔离模块状态，避免依赖执行顺序；时序测试不使用固定等待。

真实环境按 [Test Environment](../../../../../.agents/instructions/test-environment.md) 在执行时核实，当前计划不复制端口、身份或凭据。浏览器验收遵循 [Testing](../../../../../.agents/instructions/testing.md)。需要可正常切换的两个工作身份，并盘点各自可访问的组织与业务数据；现有页面数据不足时按正常页面或允许的接口准备，不直接修改数据库。

## 验证矩阵

| 编号 | 能力 | 前置与操作 | 可观察预期 | 层级 |
|---|---|---|---|---|
| C01 | 初始化与同步回放 | 分别控制宿主立即回放、无回放后读取完成；挂载 Provider 和直接快照消费者 | 初始化期间不显示伪造身份；初次有效结果到达后三种入口字段一致；无订阅循环 | 前端自动化 |
| C02 | 迟到初始读取 | 发起旧身份读取，广播新身份，再释放旧结果 | Context、外部钩子、命令式值及读取返回值均不恢复旧身份；先取得准确失败证据 | 前端自动化 |
| C03 | 多次读取顺序 | 同代次多消费者同时初始化；核对在途复用；若入口允许并行读取则反序完成 | 初始化请求正确复用；旧读取不覆盖较新已接受结果，不按版本字符串排序 | 前端自动化 |
| C04 | 多订阅者生命周期 | 同时挂载多个消费者，重复渲染，依次卸载 | 一条底层宿主订阅；单个卸载不影响其他消费者；重复快照不产生多余发布；最后卸载释放一次 | 前端自动化 |
| C05 | 状态与读取失败 | 分别广播 refreshing、anonymous、initializing、error；分别使有效初读同步抛出和异步拒绝；包括 SDK 自身的 AbortError；另在宿主新事件后拒绝旧请求 | 宿主状态按既有映射清除或保留字段；有效读取失败使命令式值为 null，测试边界从共享钩子和 Provider 捕获同一原始失败，显式读取保留原始拒绝；SDK 错误不被当作正常取消；旧请求失败不清除新身份；后续有效宿主事件清除失败；内部初始化无未处理 rejection | 前端自动化 |
| C06 | 卸载、重新挂载与 StrictMode | 旧请求未结束时释放最后消费者，检查命令式值，再重新挂载；分别在新身份到达前后完成或拒绝旧请求；观察内部初始化和显式读取 | 卸载后命令式值为 null；新代次只接受本代结果；旧代次显式读取以模块自身 AbortError 结束，内部初始化消费该取消且无未处理 rejection；旧结果与旧失败均不进入新代次；无订阅泄漏 | 前端自动化 |
| C07 | 页面与提交复核一致性 | 保持旧渲染闭包，广播新身份，立即触发既有提交复核；检查直接消费钩子的页面 | 命令式读取立即使用新版本；旧范围提交按既有规则拒绝或要求重新选择；请求不携带旧组织范围 | 前端自动化、消费回归 |
| C08 | 真实宿主身份与范围链路 | 从真实登录页和菜单进入；检查账号、范围条及不同会话入口的代表页面；通过宿主切换工作身份并重新操作；对不携带组织字段的请求，核对实际凭据为当前工作身份并记录服务端授权范围的响应依据 | 页头、范围、项目或金额页面、报告及统计请求使用当前身份（请求不携带组织字段时经令牌承载工作身份，服务端按该身份的授权范围返回）；响应与页面展示的范围、请求提交的范围条件一致；切换后重新打开页面按新身份重新读取；旧范围不被继续提交；匿名后旧身份字段清除；DOM、Console、Network 与响应符合预期 | 真实宿主 |
| C09 | 前端注释清理 | 对已核定手写生产文件逐项检查临时引用并复查差异 | 临时编号清理完整，业务与技术说明保留，注释批次无业务语句变化，剩余命中有分类依据 | 静态、人工检查 |
| C10 | 前端全量验证 | 执行子应用全部测试、lint 与 build | 完成实际检查；新增失败、跳过及测试数量变化有归因，影响范围内无未处理回归 | 自动化、静态、构建 |

C08“真实宿主身份与范围链路”不要求在真实宿主制造无法稳定控制的响应乱序，相关顺序由 C02“迟到初始读取”、C03“多次读取顺序”及 C06“卸载、重新挂载与 StrictMode”提供确定性证据。宿主验收仍需检查真实身份变化和业务请求；「旧范围不被继续提交」若无法在真实宿主取得可判红证据，按项目规则登记为未覆盖面与残余风险，不按通过记录。
