# 可选技术治理前端设计

设计状态：已确认。范围见[阶段设计](../design.md)，验证见[前端测试计划](testPlan.md)。

## 职责与入口

`hostSession.ts` 负责唯一的应用内会话快照、宿主订阅及异步读取顺序。`HostSessionProvider.tsx` 从共享快照取得 Context 值，移除其独立的 `useState` 和初始读取流程。`HostSessionContext.tsx` 保留现有消费入口与 Provider 外立即失败的行为。

保留 `useHostSession()`、`useHostSessionSnapshot()` 和 `readCurrentHostSession()` 三种消费方式；它们读取同一份已接受快照。Provider 首次尚无快照时使用稳定的 `INITIAL_HOST_SESSION`；外部快照钩子与命令式读取继续返回 `null`，由现有使用方处理不可用状态。

不修改页面路由、菜单、字段、筛选、API Client、Token 管理或宿主身份操作。业务页面和提交范围校验作为直接影响验证对象，默认无需修改其生产文件。

## 会话更新规则

1. 来源仍为已安装 `@dy/micro-sdk` 的 `MicroSDK.auth.getSession()` 与 `MicroSDK.auth.subscribe()`。实施时核对公开声明与订阅回放行为，不修改 SDK 或宿主源码。
2. 共享模块集中执行快照转换与发布；先更新命令式读取值，再通知 React 订阅者。快照未变化时保持对象引用稳定，避免重复渲染；比较字段覆盖 `HostSession` 的全部字段。
3. 使用应用内生命周期代次、读取序号和事件修订计数判断异步结果是否仍然有效。`sessionVersion` 作为宿主提供的不透明字符串保留，不按数字或字典顺序比较新旧。
4. 每次读取记录所属代次及启动时的事件修订。读取期间收到宿主事件后，该读取结果失效；失效结果不发布，也不作为 `readHostSession()` 的旧身份返回值。已有更新快照时返回当前快照。
5. 同代次的初始化读取复用在途请求；确需存在多个读取请求时，只接受最新启动且未被事件取代的结果。旧请求不得覆盖较新请求。
6. 全部消费者释放后使当前代次失效。该代次的迟到响应不更新下一代快照，也不返回下一代身份；该读取按下节规定的生命周期取消结束。同代次读取被更新事件或请求取代时，有有效快照则返回当前快照，无有效快照则同样取消。
7. 初始化、匿名和错误快照清除身份与组织字段；已认证与刷新中的快照保留宿主实际提供的字段。SDK 读取失败按下节处理，不转换为空列表或伪造身份。

## 读取取消与失败处理

- `readHostSession()` 保留 `Promise<HostSession>` 返回类型。共享模块为自身判定的读取失效创建 `DOMException`，名称为 `AbortError`，并把该对象登记在模块自身的取消集合中，同时导出按归属判定的识别函数供调用端使用。只将模块自身产生的失效视为正常取消，不按错误名称或消息吞掉 SDK 原始错误。取消结果可以在底层请求最终完成或拒绝时产生，无需主动中止 SDK 请求。
- 内部初始化入口必须为读取安装成功和拒绝处理，禁止保留无拒绝处理的 `void readHostSession()`。模块自身的正常取消只结束旧读取，不发布错误、不影响新代次，也不产生未处理的 Promise rejection。显式调用 `readHostSession()` 的位置负责处理其拒绝，测试必须覆盖取消结果。
- 有效读取发生同步异常或 Promise 拒绝时，保留原始失败值；共享模块清空可用身份快照，保存该失败并通知订阅者，显式读取以同一失败值拒绝。同步异常也进入同一 Promise 失败流程。失败记录独立于身份字段，能够表示任意拒绝值；不将其构造成宿主 `status: 'error'` 快照。
- `useHostSessionSnapshot()` 的 React 快照读取在存在有效失败记录时直接抛出原始失败值；Provider 使用相同钩子，因此 Context 使用方遵循同一行为。`readCurrentHostSession()` 在失败后返回 `null`，提交复核按既有不可用规则阻止旧身份提交。订阅通知本身不负责抛出该失败。
应用入口在 `HostSessionProvider` **上方**提供一个最小错误边界，同时覆盖 Provider 之下直接使用该钩子的消费者。边界必须高于抛错点：Provider 自身在渲染期调用会话钩子，包在其 children 内部捕获不到该错误。

- 有效读取失败时除保留原始失败值外：清除可信身份、阻止业务操作、显示明确的不可操作状态并给出恢复入口。状态文案为「会话不可用」，说明页面已停止操作，主操作是「重新载入」；文案不臆断被捕获错误的成因，因为该边界同时覆盖 Provider 之下任意子树的渲染错误。
- 原始失败值只作为边界捕获结果保留，不进入界面文案、不转换为正常会话、不接入仅处理 HTTP 响应的 Kiota 错误通道，也不新增通用错误上报体系。
- 恢复使用应用现有能力：重新载入整页后由应用初始化重新读取当前会话；再次失败仍回到不可操作状态，不自动无限重试，也不恢复旧身份。
- 自动化测试用与生产入口一致的组件包含关系验证不可操作状态与恢复入口，并通过渲染入口的 `onCaughtError` 取原始失败值；边界组件不为测试保留额外观测口，测试也不新增生产页面不存在的显式订阅者。
- 失败提交前使用与成功结果相同的代次、读取序号和事件修订校验。已失效请求的失败不清除新快照、不保存至新代次；返回当前有效快照或生命周期取消的规则与成功结果一致。后续有效宿主快照清除失败记录；最后释放时同时清除失败记录和身份缓存。
- 宿主正常广播的 `status: 'error'` 仍按 `toHostSession` 清除身份字段，与 SDK 读取拒绝分别验证。初始读取失败不自动重复请求；仍有订阅者时，有效宿主事件可以清除失败；全部消费者释放后，恢复由重新挂载后的初始化触发。

## 订阅与生命周期

- 所有消费入口共用一条底层宿主订阅。第一个订阅者到来时先建立宿主订阅，再根据是否已取得回放快照决定初始读取。
- React 订阅函数使用模块级稳定引用；适配现有 `subscribeHostSession` 签名，将其回调接入同一快照通知，不再为每个消费组件重复建立宿主订阅。
- 同步订阅回放必须能够正确通知首个订阅者，不能因回放发生在订阅建立过程中而重复建立订阅。
- 单个组件卸载只移除自己的监听；最后一个订阅者释放时才取消宿主订阅、使在途读取失效并清空缓存。下一次挂载重新读取当前宿主身份。
- React StrictMode 的订阅、释放及重新订阅使用相同规则，旧代次响应不能进入新代次。卸载后命令式读取返回 `null`。
- 当前已挂载期间，在宿主事件回调执行完毕后，命令式读取立即获得新快照；页面渲染通过 `useSyncExternalStore` 读取相同快照。Context 不再独立接受初始读取结果。

## 实施与确认

会话时序属于行为修复，必须先获得准确失败证据。订阅复用与 Provider 整理须保持既有加载、身份清除和提交复核行为。受控测试事件用于验证异步顺序，真实身份、页面请求和宿主错误仍由真实宿主验收证明。

若公开 SDK 行为无法支持上述顺序或错误处理要求，只暂停受影响的会话任务，记录具体差异后修订设计。
