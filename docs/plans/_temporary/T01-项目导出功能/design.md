## 目标与范围

- 目标：「互认项目」「互认项目金额维护」「本院区互认项目金额」三个管理端页面各新增导出能力，按当前服务端查询条件生成 Excel 工作簿并经浏览器保存。可验收结果：三页从宿主菜单进入后可一键导出合法 `.xlsx` 文件，列集与取值符合设计，空数据按业务拒绝提示，三页导出交互款式一致。
- 纳入：后端三个导出端点（ClosedXML 生成、查询契约分部扩展、手工导出控制器）；API Client 累计重生成；三页导出按钮、适配层导出函数与共享下载模块；同步正式阶段文档节点（004、005、SRS、UML2、总体计划对应表述）。
- 排除：CSV/PDF 等 Excel 之外的格式（同阶段 6 排除口径）；互认统计导出的业务行为、端点与列集不变（其前端下载模块按 T01-D9 迁移归并，仅文件路径、引用与契约错误文案泛化变化）；按配置状态页签或金额状态下拉裁剪导出；分页；患者信息导出；角色权限模型；任何数据库写入与迁移。
- 依据：SRS「用户界面」通用界面要求 1（页面的可见、查询、操作、下钻和导出能力受外部权限系统菜单授权以及可信组织、医院、院区上下文控制）与通用界面要求 4（页面布局、控件类型由界面设计确定，不得减少业务能力）；阶段 6 导出先例（S6-D5 十万行封顶、S6-D7 ClosedXML 集中入库、S6-D8 POST + 条件体与 File 流响应及零记录业务拒绝）；UML `5-RecognitionStatisticsUiQuery.wsd` 的导出形态（POST + 全部查询条件体、不使用页面分页、导出文件读模型、零记录不生成文件）；UML `2-MedicalRecognitionConfigurationUiQuery.wsd`（三个导出查询形态随批次 5 登记）。导出能力为 F02/F10 的需求范围新增，SRS 与 UML2 的对应表述随批次 5 同步，本设计是其在交付前的事实载体。
- 前置：阶段 2（004）与阶段 3（005）已完成规定收口，三个页面与三个列表查询入口已交付；ClosedXML 已在 `Directory.Packages.props` 集中声明并在 Application 工程引用（阶段 6 批次落地）。导出入口与三个端点的菜单、接口授权由权限系统负责，本项目不另建角色授权模型（承接通用界面要求 1，与 S2-D1、S3-D2 同口径）。
- 端：跨端。无新表、无迁移、无写用例。

## 设计

**导出范围与口径。** 导出承载页面可产生的服务端查询条件：互认项目导出为组织（必填，须等于服务端可信当前组织）加可选关键字；平台金额导出为组织、医院、院区（必填）加可选关键字；本院区金额导出为院区（必填）加可选关键字，组织与医院由可信上下文解析。互认配置列表查询契约中的可选 `ConfigurationStatus` 由页面页签本地裁剪、不驱动服务端查询（S2-D21），导出请求不设该字段、取数时该参数恒为空；两个金额查询契约保留的可选 `StandardProjectCode` 因新页面不再使用而不承载（S3-D26）。金额状态下拉是纯本地裁剪条件，导出不受其影响；导出按发起时刻的服务端数据重新查询组装，不是页面数据快照。行集、排序与对应列表查询同一语句同一口径（项目类型、分类名称、分组名称、标准项目名称逐级升序，名称相同按分类、分组、项目与配置标识兜底）；互认项目导出因此同时包含启用与停用配置，金额导出行集含未配置金额行。导出与页签档位解耦是已登记的交互口径（接受与否随设计确认一并确认）：在「停用」页签下导出得到含启用配置的全量文件，页面不另设提示文案。

**列集。** 两套列集，序号为导出行序（1..N），列名与顺序如下，三个页面不再有其他列：

- 互认项目：序号、项目类型、分类、分组、标准项目编码、标准项目名称、可互认时间（天）、互认配置状态、当前不可用原因。
- 两个金额页共用：序号、项目类型、分类、分组、标准项目编码、标准项目名称、当前金额、金额状态、互认配置状态、当前不可用原因。

取值口径：项目类型与互认配置状态取服务端读模型的枚举中文文本字段（`ItemTypeText`、`ConfigurationStatusText`），枚举中文文本为空时该单元格输出空、不伪造类型名；当前金额写数值、未配置行单元格留空，金额状态由应用层按金额是否已配置输出「已配置 / 未配置」；可互认时间写数值（单位天）；当前不可用原因为空时输出空。参考表的「是否对码」不取用——三页行集本身即已建立互认配置的项目（行集由互认配置驱动），该列没有业务含义；组织、医院、院区名称不进列集——每次导出的范围单一，SRS 的三级名称展示要求由页面页头或范围选择器承载（S3-D23），不构成对导出列集的要求。

**文件与响应。** 单工作表 `.xlsx`，工作表名与页面名称一致；表头行加粗、冻结首行、列宽按内容适配。文件名为「页面名称 + 生成时间（`yyyyMMddHHmmss`）+ `.xlsx`」，三个页面名称分别为「互认项目」「互认项目金额维护」「本院区互认项目金额」。端点为 POST + 条件体，控制器返回禁止缓存的文件流；生成端（Kiota）只透出字节体、不透出响应头，下载名由前端按同一命名格式在发起时给定，响应头中的文件名不作前端权威来源，两个时刻允许秒级差异；页面名称为固定中文字面量，不引入文件名特殊字符处理。

**防御口径。** 当前条件下无记录时业务拒绝「当前条件下无可导出数据」，不生成空文件、不扩大查询范围；取回行数超过 100000 行时业务拒绝并提示缩小查询条件。上限校验时点在取回之后，防御的是文件组装与响应传输面；列表查询自身的不分页全量读取面已由阶段 2、阶段 3 接受（S2-D7、S3-D8），本阶段不改变该面。导出的内存组装与响应时长风险按 T01-D8 登记为拟接受风险（随设计确认一并确认）。

**契约与分层。** 三个专用导出 Request，不复用列表查询 Request——列表请求中页面不使用的可选字段（`ConfigurationStatus`、`StandardProjectCode`）不进入导出契约，从形状上排除「导出受页面状态档位影响」的误读。查询契约以分部文件扩展（既有 `.Statistics.cs` 分部先例，新增 `.Export.cs`）；三个导出入口为应用层方法并以 `NonAction` 声明排除框架自动端点暴露，由手工导出控制器 `RecognitionExportController`（路由前缀 `api/v1/recognition-export`）的三个 POST 动作承载（阶段 6 导出控制器先例，路由带版本前缀以避开框架按接口名自动推导的端点前缀）。取数复用既有两条列表查询仓储方法——本院区金额导出与对应列表查询相同，经可信范围解析后复用平台金额的仓储方法（互认项目导出的配置状态参数恒为空），零新增 SQL 语句、零新表、零迁移。应用层以 ClosedXML 在内存组装工作簿属于查询链上的数据转换，不实现外部文件系统、HTTP 或消息协议适配（阶段 6 同款实现已交付）。

**零写入。** 导出全程无数据库写入、无事件登记、无事务声明、不留存文件副本；范围校验失败、防御拒绝与组装异常均整次失败，不留任何副作用。

**前端交互。** 三页版面基线：查询区行为关键字输入框加「金额状态」下拉（两个金额页同款，互认项目页无下拉）；列表上沿为配置状态页签行。三页导出按钮统一承载在配置状态页签行的右侧——互认项目页在该页页签行右侧扩展承载；两个金额页由共用列表视图组件在同一位置承载，三页按钮款式一致。导出按钮门控：范围未就绪时禁用、零请求——三页在可信上下文缺失的整页阻断态按钮不可达（互认项目页见阶段 2 Client 设计与用例 C1，两个金额页见 S3-D22）；平台页当前选定范围未完整时禁用；本院区页登录院区缺失时禁用（该页不整页阻断，按钮随空态禁用）。与既有写门控同口径，以下两态同样禁用导出、零请求：可信组织或可信范围已变化且页面尚未应用（互认项目页的组织变更提示态、平台页的待切换提示态——此时导出所取范围与页面展示不一致，互认项目页提交已应用组织会被服务端拒绝）；读取失败或写入后刷新失败（页面数据不可靠，恢复以重试为先）。导出在途时按钮进入 loading 并防重复；既有写门控不因导出改变，列表读取在途与仅行内编辑进行中（无范围变化）不限制导出（导出为只读链，不产生写冲突）。按钮为标准按钮语义与可访问名称，键盘焦点顺序随 DOM 顺序。点击后以已鉴权客户端请求导出端点：请求体按各自范围来源组装（互认项目页取宿主认证上下文当前组织，平台页取当前选定范围三值，本院区页取登录院区），关键字取已生效值；取得字节后经共享下载模块触发浏览器保存并在保存后释放对象地址；字节缺失或为 0 字节按契约错误抛出（零记录已在服务端拒绝，合法工作簿不会为空）。失败时结束 loading、保留已有列表与筛选，错误提示由宿主统一展示，页面不解析错误响应体。导出动作与条件不写入路由查询参数。
