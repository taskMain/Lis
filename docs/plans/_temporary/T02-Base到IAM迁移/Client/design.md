# T02 前端设计

总体范围及关键决策见 [阶段设计](../design.md)。

## 页面与交互

### 1. 会话接缝

- 唯一来源：`MicroSDK.auth.getSession()` 与 `subscribe` 的会话快照；对外暴露 `sessionVersion`、`userId`、`displayName`、`organizationId`、`hospitalId`、`campusId`。
- 订阅在组件卸载时释放；会话切换后丢弃旧请求响应，不把旧身份数据写入新状态。
- 匿名与初始化状态：不伪造范围、不发业务请求，页面进入既有阻断态。

### 2. 请求

- 业务后端适配器由 `MicroSDK.auth.createRequestAdapter({ baseUrl, targetAppCode })` 生成；`targetAppCode` 取本项目应用编码。
- 业务请求中的 `organizationCode`、`hospitalCode`、`branchCode` 一律为 IAM 组织业务编码；子应用会话仍提供组织实例 Id，但只用于组织目录读取，不进入业务字段。
- 鉴权失败交给宿主认证流程；子应用不跳转登录页、不解析令牌、不读取浏览器存储。

### 3. 范围选择器

- 新组件替换三页四处 `BaseScopeSelector`：选项来自 IAM 组织树与组织类型筛选，联动为医共体 → 医院 → 院区。
- 选中值为 IAM 组织业务编码（选项由后端范围查询按类型组装；会话组织实例 Id 只用于组织目录读取）；切换范围后清空旧结果、丢弃在途响应。
- 组织树读取失败或类型缺失时提示并可重试，不静默降级为空列表。

### 4. 页头范围条

- 三级名称由本项目范围查询返回（组织、医院、院区名称随范围下发），不直连外部目录。
- 名称缺失显示「未知」，不回退显示编码；单行省略与 Tooltip 表现保持既有口径。

### 5. 参数维护页（F11）

- 路由挂在互认平台管理端，菜单在宿主 IAM 登记；页面提供参数列表与编辑。
- 校验在提交前提示、保存时由后端判定；非法值不提交、不落库。
- 保存成功后刷新列表并提示生效；失败保留输入并显示具体原因。

### 6. 受影响的既有页面

| 页面 | 影响 |
| --- | --- |
| 标准项目目录维护 | 无范围选择器；仅身份与请求适配器变化 |
| 互认项目配置与金额维护（平台/本院） | 范围选择器、可信范围、写前复核、组织维度类型 |
| 报告管理与历史版本（平台/本院） | 可信医院与院区来源、页头范围条 |
| 在线互认与匹配 | 可信范围来源、配置错误提示 |
| 互认统计与导出 | 三处范围选择器、统计请求范围字段取值改为组织业务编码 |

## API 与组件

- 依赖本项目 API Client（Kiota）与宿主会话；不新增 Base 目录调用。
- 组织类型与名称统一经本项目后端范围查询，不直接调用 IAM 目录接口（已发布前端客户端未声明该能力）。
- 组件职责：会话模块只提供会话状态；范围选择器只产出选择值；页面负责装配请求与阻断态。
