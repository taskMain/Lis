# T02 阶段设计：Base 到 IAM 迁移

临时阶段，用于一次性的横向迁移工作；最终事实同步回正式阶段、SRS 与 UML 后由负责人确认删除本目录。

## 目标与范围

- **目标及可验收结果**：本项目在 IAM 基座（`http://183.224.180.166:35009`）完成真实登录与全量页面走查；业务数据以 IAM 组织业务编码存储与查询；三项平台参数由本应用维护；工程内不再存在 Base 认证、Base 目录与 Base 系统参数的任何运行时依赖（包、配置、令牌、调用）。
- **纳入范围**：
  1. 后端认证与身份改为 IAM（模块、配置、当前人、操作人）。
  2. 组织三层（医共体、医院、院区）改由 IAM 组织提供，含当前身份归属、平台入口选择列表与三层业务编码的取数。
  3. 业务键口径统一：4 张含组织维度列的表（报告、匹配记录、金额、互认项目）的 `*_code` 列保存 IAM 组织业务编码，相关实体、命令、查询、SqlMap 与接口契约沿用编码文本；迁移期新增的 uuid 实例列退出。
  4. 业务配置自管：`mrec_platform_parameter` 表、读取改造、维护接口与维护页面（新功能 F11）。
  5. 前端会话、请求适配器、范围选择器与页头范围条改造。
  6. 测试身份与应用登记：IAM 应用登记、两个测试账号加入目标院区组织。
  7. 文档同步：SRS、UML、工程规范与受影响阶段的阶段文档。
- **排除范围**：不重建工程、不改业务规则（除系统参数来源与非认证依赖清理）、不做字典维护、不改动其他业务系统、不执行生产部署与发布、不引入角色与接口级授权判定。
- **需求与领域模型依据**：`docs/需求规约SRS.md`（身份与组织来源、系统参数相关条款 112、322、1675、1701、1723、1747、2299；字典相关条款 1209、1561）、`docs/uml/` 五个模型文件、工程规范 `project-context.md` 与 `test-environment.md`。
- **前置依赖及当前确认状态**：阶段 7 已收口（发布结论 `ReadyWithAcceptedResiduals`）；IAM 服务与 IAM 基座可达；后端 897 项、前端 833 项基线在迁移前为绿；IAM 应用已建立；测试账号 `191617` 与 `lisadmin` 已在 IAM 存在，`191617` 登录与令牌签发已验证。

## 设计

### 1. 迁移后的目标形态

- 认证：宿主 IAM 登录 → 会话快照 → 子应用读会话 → 业务后端校验 IAM 令牌。
- 身份：后端当前人只来自 `ICurrentIamContext.RequireCurrent()`；操作人写 IAM `UserId`。
- 组织：可信组织/医院/院区的实例标识由会话组织的祖先链按组织类型解析，三层业务编码由同批目录读取的组织 `code` 取得；平台入口选择由 IAM 组织树与目录筛选得到。
- 配置：三项平台参数由本应用表维护，读取失败与非法值仍按配置错误拒绝。
- 数据：组织维度列保持文本编码列，值为 IAM 组织业务编码；不重建表，不回填历史行。

### 2. 身份与认证

- 后端：宿主以 `IamApronOpenApiModule` 接入（保留 Apron 与 Scalar/OpenAPI 直连）；配置节 `Iam`（Authority、`AllowHttp`、`ApplicationCode`、`ProfileTimeoutSeconds`）。移除 `Dy.Apron.Security` 与 `JwtSettings`，不自建登录或刷新端点。
- 当前人：`ICurrentIamContext` 提供 `UserId`、`SessionId`、`WorkIdentityId`、`TenantId`、`OrganizationId`。旧 `HttpRequestInfo` 的机构与科室字段在 IAM 适配下为空，机构相关判定一律不再读取该来源。
- 本人资料：确需姓名/组织名称时使用 `IIamCurrentProfileClient.GetAsync`；资料查询不作为所有认证接口的前置。
- 前端：`MicroSDK.auth.getSession/getUser/subscribe` 读取会话；`createRequestAdapter` 生成业务后端适配器；`AuthProvider`、`TokenManager`、`LoginUserManager` 全部退出。

### 3. 组织三层

- 类型编码按 `OrganizationType.Code` 分类：医共体 `CountyMedicalCommunity`、医院 `Hospital`、院区 `Branch`（科室 `Dept`、病区 `Ward` 本项目不用）。实际编码在实施批次核对后写入环境规范。
- 当前身份归属：取会话/上下文 `OrganizationId`，经目录批量读取取该节点及祖先链（每批最多 100 个 Id），按类型归类；缺失类别返回空并按业务规则拒绝，不按名称或树深度推断。
- 平台入口选择列表：按当前租户取组织树，先做范围过滤，再按批次读取组织详情与类型，按类型组装医共体 → 医院 → 院区联动。
- 名称：读取时按 Id 批量取名称，不在业务表冗余保存。
- 业务编码：目录批量读取结果中组织对象的 `code` 即业务编码；缺失时按空值处理，不生成兜底值、不建编码映射表。
- 提交编码校验：平台入口提交的三层编码需在租户组织树内比对存在、启用、类型与父子归属；该校验按请求调用组织树接口，不缓存，也不前置到认证链路。
- 组织 ID 不等于数据访问范围：保留既有"能访问接口即认定有权限"的判定，不用组织树推导数据权限。

### 4. 业务键与数据模型

| 变更 | 内容 |
| --- | --- |
| 列 | `organization_code/hospital_code/branch_code` 保持文本编码列，值为 IAM 组织业务编码；迁移期新增的 `*_id` uuid 列删除 |
| 实体与命令 | 属性保持 `string` 编码；请求与读模型同步为编码文本 |
| 索引 | 唯一键与范围索引均落在编码列，不需要重建 |
| 表集合 | 19 张 `mrec_` 表结构不变；不回填历史行 |
| 新增表 | `mrec_platform_parameter`（参数编码唯一、值、说明、启用、操作人与时间） |

表内不保存组织名称；读取时按编码解析名称，保持迁移前"名称随查询返回"的口径。

### 5. 业务配置自管

- 三项参数：`own_hospital_match_switch`、`own_hospital_exclude_hours`、`citation_detail_valid_hours`，均为平台级、无组织覆盖、无代码兜底默认值。
- 校验：开关仅接受 `0`/`1`；排除时长为非负整数小时；引用详情时长为正整数小时。非法或缺失按配置错误拒绝，并在维护入口阻止保存。
- 维护能力（F11）：参数列表与编辑；保存校验由后端执行；无权限体系二次判定。
- 生效时机：保存后对后续请求立即生效；不缓存跨请求旧值。

### 6. 前端改造

- 会话接缝统一为一个模块：提供 `sessionVersion`、`organizationId`、`hospitalId`、`campusId`、用户显示名，供页面与页头共用；订阅在卸载时释放。
- 范围选择器：新组件按租户取组织树、按类型联动，替换三页四处 `BaseScopeSelector`；选中值为组织业务编码。
- 页头范围条：三级名称由本项目范围查询返回，不直连外部目录。
- 请求：全部经宿主适配器，鉴权失败交给宿主认证流程，不在子应用内跳转登录页。

### 8. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 组织类型编码未核验 | 三层解析可能取不到类别 | 实施首批用目录读取核对实际编码，结果写入环境规范 |
| 前端 IAM 客户端缺目录能力 | 前端无法直接按类型筛选 | 组织类型与名称统一走后端范围查询 |
| 宿主子应用未登记 | 无法从 IAM 基座进入页面 | 实施批次先在基座登记并验证装载 |
| 参数表引入新写路径 | 可能绕过既有校验口径 | 保存与读取共用同一校验实现，缺失即拒绝 |
| 编码口径切换 | 历史行组织列为实例 Id 文本，按编码过滤不再命中 | 不回填；测试数据用现有 IAM 组织重建 |
| 提交编码校验依赖组织树接口 | 该校验入口受 IAM 组织树可用性影响 | 仅在校验入口调用，不前置到认证链路；接口不可用时按不可用拒绝，不用旧值放行 |

## 验收与停止条件

- **适用验证面及通过条件**：后端矩阵（`Server/design.md`）与前端矩阵（`Client/testPlan.md`）全部条目有实际证据或定级结论；真实宿主走查覆盖全部页面；工程内 Base 依赖静态扫描为零。
- **环境或数据依赖**：宿主、IAM、组织与账号取值见 [Test Environment](../../../.agents/instructions/test-environment.md)；表结构变更（删除迁移期新增的 uuid 列）由负责人执行。
- **负责人执行迁移或其他外部动作**：数据库重建与服务发布由负责人执行；本阶段不执行生产迁移。
- **超出授权或影响边界不明时的停止条件**：出现需改动其他业务系统、需改动 IAM 共享登记规则、或组织类型无法确认且影响三层解析时，暂停受影响范围并请求裁定。
