## 5. 认证与数据范围

第三方必须先按配套登录文档取得有效 Token，并在业务请求中携带 `Authorization: Bearer <access-token>`。

Token 用于确定当前调用方的组织、医院、院区、科室、用户和可访问的数据范围。本文所说的"组织、医院、院区路径"是这三个编码的组合；其中任一编码不同，都属于不同路径。除接口明确允许外，业务请求不得提交、伪造或覆盖 Token 已确定的调用方路径；请求只能提交参数表列出的目标方编码和其他业务字段。待补充：互认双方的调用权限划分（各侧可调用哪些写入与查询接口，双入口查询接口如何按 Token 范围返回数据）。

## 6. 通用约定

### 6.1 成功与失败

| 场景 | 当前口径 |
| ---- | -------- |
| 成功写入 | 待补充（返回业务号、受影响数量或结果对象） |
| 成功列表查询 | 待补充（返回 JSON 数组） |
| 成功详情查询 | 待补充（返回 JSON 对象；合法无匹配时的响应口径） |
| 未认证或 Token 无效 | 接口调用失败 |
| 请求格式错误 | 接口调用失败 |
| 字段校验、组织越权、状态不允许、业务规则失败 | 接口调用失败；调用方不得依赖固定错误 JSON 结构 |

失败响应由平台统一处理。待补充：本文是否保证固定的错误 JSON 结构；调用方应如何判断处理结果和排查问题。

各接口章节只列本接口特有的业务失败、空结果和重试规则。除非接口章节另有说明，统一按以下规则处理（按平台实际口径填写或删减）：

- Token 缺失、无效或过期，请求体无法绑定，字段类型错误，必填字段缺失、空白、超长或格式非法时，接口调用失败。
- Token 缺少组织、医院或院区信息，或这些编码在平台目录中不存在时，接口调用失败。请求超出当前 Token 的数据范围时，待补充（返回 JSON `null` 或调用失败的口径）。
- 查询条件合法但没有匹配数据时，列表接口返回 `[]`，对象型详情接口返回 JSON `null`；对象内部可选数据无值返回 `null`，集合无元素返回 `[]`。参数、状态或业务规则不满足时，接口返回失败响应。
- 只读查询可以重试；写接口只有在章节明确声明幂等时才能按指定业务键重试。状态不允许或业务条件不满足时，应先修正请求或业务状态，不要盲目重试。

### 6.2 必填、条件字段与枚举

- "是"表示必填；"业务必填"表示业务调用必须提交；"条件"表示由业务状态或枚举决定是否必填。
- 参数表按 JSON 字段逐项列示。一个表格行只描述一个字段，不使用"字段 A / 字段 B"、复合类型或多个字段共用示例的缩写方式。
- 响应参数表中的"可为空"表示该字段是否允许返回 `null`；数组子字段使用 `数组字段名[].子字段名` 形式逐项列示。
- 字符串应去除首尾空格，不得使用空字符串代替缺失值。
- 枚举必须传本文列出的整数值，不传枚举名称。
- 请求 JSON 只能提交各接口参数表列出的字段；Token 已确定的调用方字段即使与响应字段同名，也不得放入请求体。
- 必填业务时间必须传真实发生时间，不得使用默认或占位时间。

### 6.3 幂等规则

按各写接口逐个说明幂等键与重复调用行为。待接口清单确定后填写，格式参照：

- 接口 N（接口名称）：按"待补充"幂等。相同幂等键的重复返回待补充。
- 查询接口只读，可以安全重试。
- 其余状态变更接口是否保证重复调用安全，逐个声明。

### 6.4 常用枚举

| 枚举 | 值 |
| ---- | -- |
| 待补充 | 待补充 |

## 8. 业务推送与回调接口

> 若互认业务存在平台向第三方推送通知的需求，按下述结构编写；若无推送需求，本节注明"本文无业务推送"。待确认。

## 9. 数据安全与使用要求

1. 生产环境使用部署方提供的 HTTPS 地址；Token、患者证件号、电话、诊断和报告文件不得写入普通日志、截图或异常追踪文本。
2. 仅提交各接口参数表列出的字段，不提交平台内部主键、存储路径、下载 URL 或未约定的扩展字段。
3. 患者和临床敏感字段按最小必要原则传输和保存；报告文件使用私有存储，不写入公共缓存。
4. 第三方应保护访问 Token 和刷新令牌，不在前端公开环境、共享日志或工单中传播。
5. 待补充：业务角色字段的提交要求（如人员业务标识与姓名成对提交，不得用 Token 当前调用人替代业务角色）。
