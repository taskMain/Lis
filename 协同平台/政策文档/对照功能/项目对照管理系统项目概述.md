## 简介

### 目的

本文档用于概述项目对照管理系统的建设背景、业务目标、范围边界、典型场景和产品功能，帮助业务方、实施方、开发团队、测试团队和外部接入系统厂商理解系统整体定位。

详细业务规则、字段属性、接口规则、流程和验收标准以《项目对照管理系统需求文档.md》为准。

### 项目背景

检验中心协同平台、影像诊断中心系统和检查检验结果互认业务都需要处理医疗机构本地项目与平台标准项目之间的关系。不同医疗机构通常使用各自的本地项目明细编码和项目明细名称，平台无法直接使用机构本地编码完成统一流转、查询和互认判断。

当前业务中主要存在以下问题：

* **机构项目明细编码不统一**：不同机构的 HIS、LIS、RIS、PACS 维护的项目明细编码和名称不一致，需要统一转换为平台标准项目明细编码。
* **标准项目目录需要统一维护**：平台需要维护一套可供协同和结果互认共同使用的标准项目目录，并支持按分类、分组、明细组织。
* **业务适用范围需要明确**：同一个平台标准项目明细可能用于协同、结果互认，也可能仅作为目录预维护数据，需要通过业务属性区分。
* **有效性判断需要统一**：项目是否当前有效，不只取决于平台标准项目明细自身，还取决于所属标准项目分类和标准项目分组是否启用。
* **机构对照关系需要清晰管理**：机构项目明细编码需要对照到平台标准项目明细编码，并通过启用、停用、唯一性和权限规则避免错误解析或越权访问。
* **对外接口边界需要明确**：外部接入系统需要查询标准目录、解析项目对照、查询有效对照，并可按规则新增或停用机构对照；平台标准目录维护仍由平台功能完成。

### 建设目标

建设项目对照管理系统，统一维护平台标准项目目录和机构项目对照关系，为检验中心协同平台、影像诊断中心系统和检查检验结果互认业务提供稳定的项目编码转换能力。

| 目标 | 说明 |
| --- | --- |
| 建立统一标准项目目录 | 通过标准项目分类、标准项目分组、平台标准项目明细三层结构组织平台标准项目 |
| 管理机构项目对照 | 建立机构项目明细编码到平台标准项目明细编码的映射关系 |
| 支持协同业务 | 为检验中心协同平台和影像诊断中心系统提供协同场景下的项目解析能力 |
| 支持结果互认业务 | 为检查检验结果互认业务提供项目解析和目录参考能力 |
| 支持外部系统查询和维护 | 提供标准项目目录查询、机构有效对照查询、机构对照新增和停用能力 |
| 控制业务边界 | 不保存申请、报告、患者、就诊、样本、影像等业务数据，不承担医学细分规则判断 |

最终效果：

* 平台形成统一的标准项目目录，目录按分类、分组、明细维护。
* 机构本地项目明细可对照到平台标准项目明细。
* 外部接入系统可按机构编码、业务场景和机构项目明细编码批量解析平台标准项目明细编码。
* 标准项目目录和机构项目对照可通过启停用、权限和唯一性规则控制有效范围。
* 当前版本的功能边界、对外接口范围和不支持内容清晰可控。

### 范围与边界

#### 做什么

| 模块 | 说明 |
| --- | --- |
| 标准项目分类维护 | 平台运营人员维护标准项目目录第一层分类，例如检验专业、放射影像专业、超声影像专业 |
| 标准项目分组维护 | 平台运营人员维护标准项目目录第二层分组，例如生化常规检验、腹部彩超、影像常用项目；示例不构成固定枚举 |
| 平台标准项目明细维护 | 平台运营人员维护平台标准项目明细编码、名称、支持协同、支持结果互认、启停用和备注 |
| 标准项目目录查询 | 外部接入系统一次性查询当前有效标准项目明细目录，可按业务范围和标准项目分类名称筛选 |
| 当前有效标准项目目录导出 | 平台功能支持按业务范围和标准项目分类名称导出当前有效标准项目明细目录 |
| 机构项目对照维护 | 平台运营人员或机构用户维护机构项目明细编码与平台标准项目明细编码的对照关系 |
| 机构项目对照查询 | 外部接入系统查询授权机构下的当前有效对照 |
| 项目对照解析 | 外部接入系统按机构编码、业务场景和机构项目明细编码列表，批量解析平台标准项目明细 |
| 机构对照新增接口 | 外部接入系统批量新增机构项目对照 |
| 机构对照停用接口 | 外部接入系统批量停用机构项目对照 |

#### 不做什么

| 约束 | 说明 |
| --- | --- |
| 不保存业务申请和报告数据 | 不保存检验申请、影像申请、互认查询记录、报告、患者、就诊、样本或影像数据 |
| 不改写历史业务数据 | 项目对照关系变更只影响变更后发生的解析、目录查询和对照查询 |
| 不维护医学细分规则 | 不维护样本类型、报告子项、套餐拆分、检查部位、检查方法、增强方式、左右侧等医学细分规则 |
| 不提供标准项目目录对外维护接口 | 标准项目分类、分组、明细的新增、修改、启用、停用只通过平台功能操作 |
| 不提供机构对照修改能力 | 调整对照通过停用原对照并新增新对照完成 |
| 不提供机构对照对外启用接口 | 机构对照启用仅通过平台功能逐条操作 |
| 不提供查询停用对照的对外接口 | 对外机构对照查询只返回当前有效对照 |
| 不提供对照关系物理删除 | 删除诉求通过停用实现 |
| 不提供对外文件导出接口 | 当前仅平台功能支持当前有效标准项目目录导出 |
| 不记录字段级变更内容 | 当前版本只记录基础留痕字段，不提供字段级变更记录或独立操作记录查询 |
| 不规定接口通用技术细节 | 本文档不定义 HTTP 方法、状态码、数据库表结构、索引、事务等技术实现细节 |

#### 边界条件

| 项目 | 说明 |
| --- | --- |
| 标准项目目录结构 | 采用标准项目分类 -> 标准项目分组 -> 平台标准项目明细三层结构 |
| 对照目标 | 机构项目对照只建立到平台标准项目明细，不建立到分类或分组 |
| 当前有效标准项目明细 | 所属标准项目分类启用、所属标准项目分组启用，且平台标准项目明细自身启用 |
| 当前有效对照 | 对照自身启用，且对照到的标准项目明细为当前有效标准项目明细 |
| 对照唯一性 | 同一机构下，一个机构项目明细编码只能存在一条启用状态对照 |
| 多对一对照 | 同一机构下，允许多个机构项目明细编码对照到同一个平台标准项目明细编码，但这些机构项目明细应可视为同一平台标准项目明细 |
| 业务场景 | 项目对照解析接口的业务场景取值为协同、结果互认 |
| 适用业务范围 | 平台标准项目明细通过支持协同、支持结果互认表达是否可用于对应业务场景 |
| 互认查询类别 | 标准项目分类上的目录参考属性，取值为检验项目或检查项目，不作为对照解析接口的输入、输出或解析判断条件 |
| 对外查询范围 | 外部接入系统只能访问授权机构范围内的数据 |
| 生效时间 | 标准项目目录和机构项目对照的新增、修改、启用、停用保存后立即生效，不支持预约生效和到期自动失效 |

### 典型业务场景

#### 场景一：平台运营人员维护标准项目目录

平台运营人员先维护标准项目分类，再维护分类下的标准项目分组，最后维护平台标准项目明细。平台标准项目明细需要配置平台标准项目明细编码、名称、是否支持协同、是否支持结果互认、启停用状态和备注。

适用情况：

* 平台需要维护统一标准目录，供协同和结果互认共同使用。
* 需要按专业、分组和明细组织目录，便于平台维护、查询展示和导出归类。
* 新增支持结果互认的平台标准项目明细时，需要所属分类已维护互认查询类别。

#### 场景二：平台运营人员或机构用户维护机构项目对照

维护人员为机构本地项目明细建立对照关系，将机构项目明细编码对照到平台标准项目明细编码。机构用户只能维护本机构对照，平台运营人员按权限维护机构对照。

适用情况：

* 机构需要将本地 HIS、LIS、RIS 或 PACS 中的项目明细转换为平台统一项目明细。
* 机构项目上线、调整或重新对照时，需要新增或停用对照。
* 当前版本不提供对照修改，调整对照时停用原对照并新增新对照。

#### 场景三：外部接入系统解析项目对照

外部接入系统传入机构编码、业务场景和机构项目明细编码列表。系统校验机构授权和请求明细后，按机构项目明细编码逐条查找启用对照，并结合标准项目分类、分组、明细启用状态及业务场景支持属性返回解析结果。

适用情况：

* 检验中心协同平台或影像诊断中心系统创建协同申请前，需要获取平台标准项目明细编码。
* 检查检验结果互认业务查询近期可互认记录前，需要完成机构项目明细编码到平台标准项目明细编码的转换。
* 一次业务请求可能包含多个机构项目明细编码，需要批量解析并逐条返回是否解析成功和失败原因。

#### 场景四：外部接入系统查询当前有效标准项目目录

外部接入系统按业务范围查询当前有效标准项目明细目录。业务范围可选择全部、协同、结果互认，并可按标准项目分类名称筛选。

适用情况：

* 外部系统需要获取平台当前可用的标准项目明细目录。
* 接入方需要按协同或结果互认场景进行项目选择、核对或本地同步。
* 结果互认业务需要参考标准项目分类上的互认查询类别。

#### 场景五：外部接入系统查询当前有效对照

外部接入系统传入授权机构编码，查询该机构下当前有效的机构项目对照列表。查询结果用于核对机构本地项目与平台标准项目明细之间的当前有效关系。

适用情况：

* 外部接入系统需要了解本机构当前可用对照。
* 接入方需要核对本地项目明细编码、机构项目明细名称、平台标准项目明细编码和平台标准项目明细名称。
* 外部接口不返回停用对照。

#### 场景六：平台标准项目明细停用后处理对照

平台运营人员停用标准项目分类、标准项目分组或平台标准项目明细后，相关机构启用对照仍保留，但不再属于当前有效对照。后续解析会按失败返回，维护人员需要停用原对照并新增指向新平台标准项目明细的对照。

适用情况：

* 原平台标准项目明细不再作为有效标准项目使用。
* 机构项目需要切换到新的平台标准项目明细。
* 平台需要保留对照记录，不自动迁移既有机构对照。

### 术语说明

| 术语 | 说明 |
| --- | --- |
| 项目对照管理系统 | 独立负责平台标准项目目录维护和机构项目对照管理的系统 |
| 平台标准项目目录 | 平台统一维护的标准项目目录，包含标准项目分类、标准项目分组和平台标准项目明细 |
| 标准项目分类 | 平台标准项目目录的第一层，用于按业务专业归类 |
| 标准项目分组 | 平台标准项目目录的第二层，隶属于标准项目分类，用于目录展示和维护分组 |
| 平台标准项目明细 | 平台标准项目目录的第三层，也是机构项目对照的目标对象 |
| 平台标准项目明细编码 | 平台标准项目明细的唯一编码，是外部接入系统进行项目流转或互认查询时使用的标准项目编码 |
| 机构项目明细编码 | 机构本地 HIS、LIS、RIS 或 PACS 中用于表示项目明细的编码 |
| 机构项目明细名称 | 机构本地项目明细名称，仅用于人工核对、展示和追溯 |
| 机构项目对照 | 机构项目明细编码与平台标准项目明细编码之间的映射关系 |
| 当前有效标准项目明细 | 所属标准项目分类启用、所属标准项目分组启用，且平台标准项目明细自身启用 |
| 当前有效对照 | 对照自身启用，且对照到的标准项目明细为当前有效标准项目明细 |
| 业务场景 | 调用项目对照解析接口时声明的使用场景，取值为协同、结果互认 |
| 适用业务范围 | 平台标准项目明细是否可用于协同、结果互认的业务属性 |
| 互认查询类别 | 标准项目分类上的目录属性，用于结果互认业务参考，取值为检验项目或检查项目 |
| 对照解析 | 按机构编码、业务场景和机构项目明细编码列表，将机构项目明细编码转换为平台标准项目明细编码 |
| 批量解析 | 对照解析接口一次请求传入多条机构项目明细编码，并按机构项目明细编码逐条返回解析结果 |
| 批量新增/停用 | 对外接口支持批量新增、批量停用机构项目对照，采用明细级失败规则 |
| 授权机构范围 | 外部接入系统可访问的机构编码范围 |
| 平台功能 | 平台内提供给平台运营人员和机构用户使用的页面功能，不包含对外接口 |
| 平台运营人员 | 平台运营方的管理员用户，负责标准项目目录和机构项目对照维护 |
| 机构用户 | 经权限系统授权的平台机构用户，可在本机构权限范围内查询、新增、启用、停用本机构对照关系 |
| 外部接入系统 | 调用本系统对外接口的第三方系统，包括检验中心协同平台、影像诊断中心系统、检查检验结果互认系统及相关 HIS、LIS、RIS、PACS |

## 整体说明

### 产品总体效果

项目对照管理系统建成后，平台应形成一套统一的标准项目目录，并支持各机构维护本机构项目明细编码与平台标准项目明细编码之间的对照关系。

外部接入系统可通过标准项目目录查询接口获取当前有效标准项目明细目录，通过项目对照解析接口将机构项目明细编码转换为平台标准项目明细编码，通过机构对照查询接口获取授权机构下的当前有效对照。

系统通过分类、分组、明细三级启停用规则，业务场景支持属性，机构权限范围和对照唯一性规则，保证项目解析、目录查询和对照查询的结果符合当前业务范围。

### 产品功能概览

| 功能 | 说明 |
| --- | --- |
| 标准项目分类管理 | 平台运营人员维护标准项目分类名称、互认查询类别、启停用和备注 |
| 标准项目分组管理 | 平台运营人员维护分类下的标准项目分组、启停用和备注 |
| 平台标准项目明细管理 | 平台运营人员维护平台标准项目明细编码、名称、支持协同、支持结果互认、启停用和备注 |
| 当前有效标准项目目录查询 | 外部接入系统按业务范围和标准项目分类名称查询当前有效标准项目明细 |
| 当前有效标准项目目录导出 | 平台功能按业务范围和标准项目分类名称导出当前有效标准项目明细目录 |
| 机构项目对照管理 | 平台运营人员或机构用户维护机构项目明细编码与平台标准项目明细编码的对照关系 |
| 当前有效机构对照查询 | 外部接入系统查询授权机构下当前有效机构项目对照 |
| 项目对照解析 | 外部接入系统按机构编码、业务场景和机构项目明细编码列表批量解析平台标准项目明细 |
| 机构对照批量新增 | 外部接入系统批量新增机构项目对照，成功明细生效，失败明细返回失败原因 |
| 机构对照批量停用 | 外部接入系统批量停用机构项目对照，成功明细生效，失败明细返回失败原因 |
