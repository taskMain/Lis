## P0 级（严重 — 必须改）

### P0-1 "具体由接口设计文档定义"系统性放错位置
**来源**: 维度6-#P0-1 | **分类**: 🔧 可直改

**位置**: PRD 2.3.3/2.4.3/2.5.3/3.3.3/3.4.3/3.5.3（6处"不支持范围"）+ Spec REQ-0003/0004/0005/0010/0011/0012（6处"业务规则"）

**问题**: 这句话不是"不支持范围"也不是"业务规则"，是文档分工边界声明。放错会导致读者误解。

**建议**: PRD 从各"不支持范围"移除，统一放入各接口节"接口设计"表格下方注释。Spec 从各"业务规则"移除，放入对外接口汇总或各 REQ 表末尾。

---

### P0-2 Spec 批量接口异常流程完全空白
**来源**: 维度3-#P0-2 | **分类**: 🔧 可直改

**位置**: Spec REQ-PCM-0005 / 0012 异常流程

**问题**: 两个批量接口异常流程写"—"。PRD 1.4.4 定义的 200 上限、同批同类型、全有或全无——全未以异常形式出现在 Spec。

**建议**: Spec 补三条：`超200条→拒绝`、`同批类型不一致→拒绝`、`任一条失败→整批不生效`。

---

### P0-3 Spec 异常流程遗漏"目标平台项目不存在"
**来源**: 维度3-#P0-1 | **分类**: 🔧 可直改

**位置**: Spec REQ-PCM-0002 / 0009 异常流程

**问题**: PRD 1.5.1 流程图有"校验目标项目存在→不存在拦截"，Spec 异常流程只列了"已停用"和"必填为空"，缺"不存在"。

**建议**: 补充：`目标平台项目不存在 → 拦截，提示"平台项目不存在"`。

---

### P0-4 编码唯一性范围表述不统一
**来源**: 维度2-#P0-2 | **分类**: 🔧 可直改

**问题**: 少数位置残留"平台内唯一"而非"检验项目范围内唯一"/"检查项目范围内唯一"。

**建议**: 全局搜索统一。

---

### P0-5 启用操作校验规则缺失
**来源**: 维度2-#P0-3 | **分类**: 🔧 可直改

**问题**: 启用对照时需校验"目标平台项目当前启用"，但 Spec 主事件流中未显式写出该校验。

**建议**: Spec REQ-0002/0009 启用事件流补校验步骤。

---

### P0-6 PRD"增删改查" vs Spec 实际能力不一致
**来源**: 维度3-#P0-3 | **分类**: 💬 需讨论

**位置**: PRD 2.1.2/3.1.2

**问题**: 标准项目目录功能入口写"增删改查"暗示支持物理删除。两文档正文只定义了新增/修改/启用/停用，无删除规则。如果真支持删除，被引用项目的对照会变悬空引用。

**建议**: 讨论决定——标准项目是否支持物理删除？如果支持，需定义"有启用对照时禁止删除"的约束。如果不支持，PRD 改为"新增、修改、启用、停用"。
