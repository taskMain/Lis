## P1 级（关键不一致，需优先处理）

### P1-1 🔧 平台页面批量启停用 — 两文档描述冲突
**来源**: A、B、C、D、G — 5 个智能体独立发现

**冲突**: PRD 1.3.6 表格标注平台页面"（逐条操作）"，仅支持逐条。Spec 批量操作规则写"平台页面只提供逐条操作和批量启停用"。

**建议**: 统一为逐条操作（与之前讨论结论"页面只做逐条，批量留给接口"一致），修改 Spec 删除"和批量启停用"。

---

### P1-2 🔧 "同批操作类型必须一致" — Spec 有，PRD 无
**来源**: A、B、C、E

**冲突**: Spec 通用规则有"同批操作类型必须一致"，PRD 2.5.2/3.5.2 缺失。

**建议**: 在 PRD 2.5.2 和 3.5.2 补充此约束。

---

### P1-3 🔧 Spec 权限表"增删改查"含"删" — 与"不支持物理删除"矛盾
**来源**: A、B、D

**冲突**: Spec 通用规则权限表写"增删改查、启停用"，但系统明确不支持物理删除。

**建议**: 改为"新增、修改、启用、停用"。

---

### P1-4 🔧 PRD 1.4 缺少"批量操作规则"子节
**来源**: A

**问题**: PRD 批量规则分散在 2.5.2/3.5.2 中，1.4 机构项目对照通用规则没有批量操作子节。导致引用"详见 1.4"时读者找不到对应的批量规则。

**建议**: 在 PRD 1.4 中新增 1.4.4 批量操作规则（与 Spec 对齐）。

---

### P1-5 🔧 孤儿对照 / 自助维护 / 批量操作 — 关键概念未收录术语表
**来源**: A

**问题**: PRD 1.1 术语表缺少"孤儿对照"、"机构自助维护"、"批量操作"、"机构编码"四个关键术语的定义。

**建议**: 补充到术语表。

---

### P1-6 🔧 2.5.3/3.5.3 不支持范围标"无" — 实际不支持物理删除
**来源**: E、D

**问题**: PRD 2.5.3 和 3.5.3 的"不支持范围"标注为"无"，但 2.5.2/3.5.2 明确写"不支持删除对照"。

**建议**: 改为"不包含对照关系的物理删除（删除需求通过停用实现）"。

---

### P1-7 🔧 Spec 缺少 PRD 1.4.1 第4~7条机构项目名称使用规则
**来源**: D

**问题**: PRD 1.4.1 共 7 条规则，Spec 通用规则只覆盖了前 3 条，缺少第4~7条（申请时优先使用当次名称、未提交时用对照表名称、名称不同编码相同不视为不同项目）。

**建议**: 补充到 Spec 通用规则。

---

### P1-8 💬 Spec 缺少"版本范围边界"章节
**来源**: D

**问题**: PRD 第4章（不包含清单和边界说明）在 Spec 中无对应。开发只看 Spec 时不知道"不包含导入""不包含独立运维追溯页面"等排除项。

**建议**: 在 Spec 中增加版本范围边界章节，或纳入整体说明。

---

### P1-9 🔧 PRD 流程图"记录留痕"作为独立步骤可能引起误解
**来源**: F

**问题**: PRD 1.5.1/1.5.3 流程图将"记录留痕"作为独立步骤节点，与 1.3.4"不做独立变更记录功能"可能产生歧义。

**建议**: 将"记录留痕"改为"审计字段自动更新"或归入保存节点。

---

### P1-10 🔧 PRD 流程图起始标注"运营人员"未覆盖机构用户
**来源**: F

**问题**: PRD 1.5.1 流程图起始节点写"运营人员填写对照信息"，未体现机构用户自助对照时"机构编码由登录身份自动带入"的场景。

**建议**: 改为"用户填写对照信息"，增加机构编码自动带入的说明。

---

### P1-11 🔧 PRD 5.2 描述存在冲突
**来源**: B

**问题**: PRD 5.2"仅平台页面提供的能力"列表与 1.3.6 接口表存在细微矛盾——5.2 列出的内容不应暗示接口完全没有查询功能。

**建议**: 核查 5.2 列表与 1.3.6 表的一致性，确保"仅页面提供"列表准确。

---

### P1-12 🔧 PRD 验收标准未覆盖机构用户自助维护的完整能力
**来源**: B

**问题**: PRD 2.2.7/3.2.8 验收标准部分条目只写了"可查看"，未体现新增、修改、启停用的自助维护能力。

**建议**: 补充验收标准，覆盖机构用户自助维护的完整操作。
