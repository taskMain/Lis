# 第四版需要内部确认的问题

## 1. 平台管理端全局查看的审计范围

已确认平台管理端授权用户可以查看平台下所有机构的申请、样本流转、报告状态、异常和危急值记录。

仍需内部确认：平台管理端全局查看时，哪些操作必须记录审计，以及审计记录需要细化到什么程度。

待确认范围包括：

1. 是否所有跨机构查询都需要记录审计。
2. 是否仅报告 PDF 下载、患者敏感信息查看、危急值查看等高敏操作需要重点审计。
3. 审计内容是否需要包含查询人、查询时间、查询条件、查看对象、下载对象、来源 IP、操作结果等字段。
4. 平台管理员是否默认具备报告 PDF 下载权限，还是需要单独授权。

## 2. 危急值上传后是否立即推送

已确认危急值上传能力与检验结果、报告上传能力合并为同一个接口。

仍需内部确认：如果上传内容中包含危急值，平台是否在上传后立即记录并推送危急值，同时报告本身仍进入待审核状态。

待确认原因：

1. 危急值通常要求及时通知，不宜等待报告审核后再推送。
2. 报告 PDF 和完整报告内容仍需经过审核后才能发布和推送。
3. 需要确认危急值推送与报告审核之间是否允许存在时间差。
4. 需要确认危急值后续如报告审核不通过或报告更正时，是否需要追加危急值更正或补充通知。

## 3. 报告撤回后已推送危急值是否需要撤回或作废通知

已确认危急值随报告上传，不提供独立危急值上传接口；危急值必须关联本次生成的报告版本，同时关联平台申请、样本条码和上传方信息。

仍需内部确认：报告版本被撤回后，如果该报告版本关联的危急值已经对外推送，平台是否需要按配置主动推送危急值撤回或作废通知。

待确认原因：

1. 危急值与报告版本存在关联关系，报告撤回后，原危急值是否仍可被外部系统视为有效需要明确。
2. 如果不主动推送撤回或作废通知，外部系统可能无法及时感知危急值关联报告已失效。
3. 如果需要主动推送，需要进一步确认推送内容中是否包含原危急值标识、原报告版本、撤回原因、撤回时间和当前有效状态。
4. 如果不需要主动推送，也需要明确平台是否仅保留撤回记录、危急值历史记录和查询追溯能力。
