# PRD 第四版修订设计说明

> 适用文档：`PRD_定稿4_修正版.md`
>
> 文档用途：记录本轮讨论确认的 PRD 修订设计，不直接修改原 PRD 正文。
>
> 状态：设计确认稿
>
> 日期：2026-05-25

---

## 1. 修订目标

本轮修订不扩大检验中心协同平台的系统范围，重点解决现有 PRD 中需求不明确、流程图与实际业务不一致、状态和规则不够明确的问题。

修订后的 PRD 应重点做到：

1. 移除原“配送单”模型，改为“送出记录”承载样本送出留痕。
2. 明确包、申请批次、送出记录三类对象的边界。
3. 明确样本主状态、逆流程、异常处理和报告版本规则。
4. 明确报告审核开关、重传、撤回、推送和危急值关联关系。
5. 同步调整接口清单、查询对象、业务配置、审计留痕和验收标准。

---

## 2. 核心模型调整

### 2.1 平台申请

平台申请仍以样本条码为核心业务粒度：

1. 一个平台申请只能对应一个样本条码。
2. 一个样本条码只能对应一个平台申请。
3. 一个平台申请可以包含多个检验项目。
4. 同一条码下可以产生多份报告。
5. 已取消申请的条码不允许再次创建新的平台申请。

### 2.2 包

包保留为独立功能，但不是必经流程。

包用于样本打包、按包送出、按包接收和历史追溯。包偏向样本层面的归集和操作辅助，不承载样本主状态。

### 2.3 申请批次

申请批次是可选的申请归集对象，用于分类、查询、管理和核对。

申请批次不是流转单据，不作为接收入口，不承载样本流转状态。未加入申请批次的申请，仍可正常送出、接收、检测、上传报告和查询。

### 2.4 送出记录

移除原“配送单”概念后，平台需要保留独立的送出记录。

送出记录不是配送单，也不作为新的流程单据。送出记录用于记录每次样本送出操作的留痕和样本快照，支持后续查询、撤回、接收闭环和追溯。

### 2.5 报告与报告版本

同一条码下允许多份报告。多份报告可来自多项目分批出报告、补充报告等场景。

每份报告可有多个报告版本。报告重传生成新版本，报告撤回使对应报告失效。历史版本全部保留，不允许物理删除。

## 3. 主流程设计

修订后的主流程应调整为：

```text
创建申请 -> 待送出 -> 可选打包/可选加入申请批次 -> 送出 -> 接收 -> 检测完成 -> 上传报告 -> 审核/发布 -> 查询/推送
```

主流程规则：

1. 创建申请成功后，样本直接进入“待送出”。
2. 打包不是必经流程。
3. 申请批次不是必经流程。
4. 送出是必经流程。
5. 接收方只允许接收已送出的样本。
6. 检测中是可选回传状态。
7. 如果未单独回传检测完成，报告上传成功时可自动将样本推进到检测完成。
8. 未接收样本不允许上传报告。

---

## 4. 样本状态、逆流程和异常处理

### 4.1 样本主状态

样本主状态精简为：

| 顺序 | 状态     | 说明 |
| ---- | -------- | ---- |
| 1 | 待送出 | 申请创建成功后，样本等待发起方确认送出 |
| 2 | 已送出 | 发起方已确认样本送出 |
| 3 | 已接收 | 接收方已确认接收样本 |
| 4 | 检测中 | 可选回传状态 |
| 5 | 检测完成 | 接收方已完成检测，可上传报告 |

“申请已创建”不再作为样本主状态，作为申请事件、申请状态或流转记录保留。

### 4.2 申请取消

1. “申请撤回”统一改为“申请取消”。
2. 申请创建成功后、样本未送出前，允许取消申请。
3. 送出撤回后样本回到待送出，也允许取消申请。
4. 申请取消后进入终止状态，不允许恢复。
5. 申请取消后，原样本条码不允许再次创建新的平台申请。
6. 如需重新送检，由机构本地系统生成新条码并重新创建平台申请。

### 4.3 送出撤回

1. 样本已送出但接收方尚未接收前，允许撤回送出。
2. 送出撤回支持整批撤回和部分撤回。
3. 已接收样本不允许撤回送出。
4. 未接收样本撤回后回到“待送出”。
5. 撤回送出需要记录撤回原因、撤回时间、操作人或调用系统、原送出记录。

### 4.4 样本退回

样本退回作为逆流程状态，不进入正常主链。

退回后是否复用原申请和原条码，由异常处理结果决定：

1. 如果只是漏送、包装问题、信息核对后可继续等情况，可以复用原申请和原条码，处理后重新送出。
2. 如果样本破损、不合格、需要重新采样，通常应由机构本地系统重新创建申请或重新提交新的样本条码。
3. 平台需要记录退回后的处理方式，包括重新送出、终止、重新创建申请或新条码等。

### 4.5 异常处理

接收异常支持两种处理方式：

1. 异常退回：不完成接收，登记异常并退回样本，样本不进入已接收。
2. 接收后异常处理：先完成接收，样本进入已接收，同时登记异常记录，后续由业务决定是否继续检测、补充说明或关闭异常。

异常记录独立于样本主状态，异常处理状态不混入样本主状态。

## 5. 包规则

### 5.1 包定位

包用于样本物理或业务打包、送出选择和历史追溯。包不同于申请批次：

1. 包偏向样本打包和送出、接收操作。
2. 申请批次偏向申请归集、分类、查询、管理和核对。

### 5.2 包状态

包状态只保留：

| 状态 | 说明 |
| ---- | ---- |
| 有效 | 可用于样本归集、送出选择、查询和追溯 |
| 已作废 | 因误建、打包错误等原因不再使用 |

包不承载样本流转状态。

### 5.3 包调整和作废

1. 包送出后仍允许调整包内样本。
2. 调整包内样本必须保留变更记录。
3. 包内样本调整不影响已形成的送出记录和送出快照。
4. 包作废后不允许恢复有效。
5. 已作废包不允许继续加入、移出或调整样本。
6. 包作废不影响已经形成的送出记录和送出快照。

---

## 6. 申请批次规则

### 6.1 申请批次定位

申请批次是可选申请归集对象，用于申请归集、分类、查询、管理和核对。

申请批次不作为接收入口，不承载样本流转状态。

### 6.2 申请批次状态

申请批次状态只保留：

| 状态 | 说明 |
| ---- | ---- |
| 未关闭 | 允许继续加入、移出或调整申请 |
| 已关闭 | 不再允许继续加入新的申请，保留查询和追溯 |

已关闭申请批次允许重新打开。重新打开不影响批次内申请和样本已有流转状态，也不影响历史送出记录和送出快照。

### 6.3 申请批次调整

1. 一个申请最多属于一个申请批次。
2. 申请送出后，仍允许调整申请批次归属。
3. 批次调整不影响样本当前主状态。
4. 批次调整不影响已形成的送出记录和送出快照。
5. 平台需要保留批次变更记录，包括调整前批次、调整后批次、调整时间、操作人或调用系统、调整原因。

---

## 7. 送出记录规则

### 7.1 送出方式

样本送出支持两种方式：

1. 按单个申请或样本条码送出。
2. 按包送出。

申请批次不作为送出入口，不成为流转单据。

### 7.2 送出记录内容

送出记录应记录：

1. 送出方式。
2. 本次送出的样本清单。
3. 送出时间。
4. 送出方。
5. 操作人或调用系统。
6. 备注或说明。
7. 后续撤回情况。

按包送出时，需要保存当时的样本快照。

### 7.3 送出记录状态

送出记录状态包括：

| 状态 | 说明 |
| ---- | ---- |
| 已送出 | 本次送出的样本尚未全部接收，也未全部撤回 |
| 部分撤回 | 本次送出中的部分样本已撤回 |
| 全部撤回 | 本次送出中的所有样本均已撤回 |
| 接收完成 | 本次送出中的所有样本都有接收侧处理结果 |

接收完成包括正常接收、接收异常退回或其他已定义的接收侧终止处理结果。

送出记录状态不替代样本主状态。

## 8. 报告、审核和版本规则

### 8.1 报告上传

1. 报告上传必须包含报告 PDF。
2. 没有报告 PDF，不允许生成正式报告版本。
3. 结构化检验结果非必传。
4. 如果上传方提供结构化检验结果，平台应接收、保存，并与报告版本、平台申请、样本条码关联。
5. 如果未提供结构化检验结果，不影响报告版本生成、审核、发布、查询、下载和推送。
6. 危急值如果存在，应随报告上传一并传入。

### 8.2 危急值关联

1. 危急值随报告上传，不提供独立危急值上传接口。
2. 危急值必须关联本次生成的报告版本。
3. 危急值同时关联平台申请、样本条码和上传方信息。
4. 危急值可以在没有结构化检验结果时上传。
5. 平台不自行计算危急值，也不维护危急值判断规则。

### 8.3 审核开关

审核开关由外部系统配置，本 PRD 不设计其配置功能。

审核功能启用时：

1. 报告上传后进入待审核。
2. 危急值随对应报告版本一起进入审核控制。
3. 审核通过后，报告和关联危急值才对外发布或推送。
4. 报告撤回提交后进入待审核，审核通过后撤回生效。
5. 撤回审核期间，原报告继续有效。

审核功能未启用时：

1. 报告上传成功后自动发布。
2. 关联危急值进入可推送状态。
3. 报告撤回提交后立即生效。

### 8.4 重传和撤回

1. 不再单独使用“报告更正”，更正场景统一走报告重传。
2. 重传可基于历史版本，也可直接上传新版本。
3. 每次重传生成新的报告版本。
4. 同一份报告不允许同时存在多个可被审核的待审核版本。
5. 重传生成新版本后，最新版本进入待审核，旧待审核版本标记为已重传作废。
6. 审核不通过版本重传后，旧版本保持审核不通过状态。
7. 已发布报告重传后，新版本审核期间旧版本继续有效。
8. 新版本审核通过并发布后，旧已发布版本标记为已替代。
9. 报告撤回生效后，如果没有新的有效版本，默认查询显示当前无有效报告。

### 8.5 默认查询

1. 报告默认查询只返回当前最新有效报告。
2. 已撤回报告不在默认报告查询结果中作为有效报告展示。
3. 已撤回报告仍保留在历史版本中。
4. 有权限的上传方、管理端或追溯查询用户，可以通过历史版本入口查看已撤回版本。

## 9. 推送规则

### 9.1 报告发布推送

报告发布后按配置推送。

报告重传新版本发布后，平台需要按配置推送最新有效报告，并体现该版本对旧版本的替代关系。

推送内容应能标识：

1. 平台申请单号。
2. 样本条码。
3. 报告标识。
4. 新报告版本。
5. 被替代的旧报告版本。
6. 替代生效时间。
7. 当前最新有效标识。

### 9.2 报告撤回推送

报告撤回审核通过后，或审核未启用时撤回立即生效后，平台需要按配置推送报告撤回事件。

报告撤回事件用于告知医院或厂商系统原报告已失效。

推送内容应能标识：

1. 平台申请单号。
2. 样本条码。
3. 报告标识。
4. 被撤回的报告版本。
5. 撤回原因。
6. 撤回生效时间。
7. 当前是否存在最新有效报告。

### 9.3 推送失败

1. 推送失败不影响平台内报告发布、报告撤回、报告替代等业务状态。
2. 平台需要记录推送失败原因、失败时间、目标地址、返回结果、推送内容摘要和重试情况。
3. 平台应支持查看推送失败记录。
4. 平台应支持人工补推或重新触发推送。
5. PRD 不写死自动重试次数、重试间隔和技术调度策略。

### 9.4 待内部确认项

报告撤回后，如果该报告版本关联的危急值已经对外推送，平台是否需要按配置主动推送危急值撤回或作废通知，已放入 `需要内部确认.md`，不作为本设计的已定规则。

## 10. 接口调整

### 10.1 删除配送单相关接口

删除原配送单相关接口：

1. 配送单创建接口。
2. 配送单送出接口。
3. 配送单撤回或取消接口。

### 10.2 新增申请批次相关接口

新增申请批次相关接口：

1. 申请批次创建接口。
2. 申请批次调整接口。
3. 申请批次关闭接口。
4. 申请批次重新打开接口。
5. 申请批次查询接口。

### 10.3 新增或调整送出相关接口

新增或调整送出相关接口：

1. 样本送出接口。
2. 送出撤回接口。
3. 送出记录查询接口。

### 10.4 接收和报告接口

1. 样本接收接口支持按条码、按包接收。
2. 样本接收接口不支持按申请批次接收。
3. 报告接口保留上传、审核结果查询、重传、撤回、查询和下载。
4. 危急值上传不单独成接口，随报告上传传入。
5. 接口幂等不写入 PRD 正文，后续接口设计细化。

## 11. 查询、配置和审计

### 11.1 业务运维明细查询

业务运维明细查询对象调整为：

1. 平台申请单号。
2. 机构申请单号。
3. 样本条码。
4. 包。
5. 申请批次。
6. 送出记录。
7. 接收记录。
8. 样本主状态和状态流转记录。
9. 异常记录和退回记录。
10. 报告、报告版本、审核记录。
11. 报告推送记录。
12. 危急值记录、危急值推送记录、危急值处理结果。

查询统计、报表、排行、趋势分析仍不纳入本 PRD。

### 11.2 业务配置

PRD 保留业务配置管理，至少包括：

1. 机构默认接收方配置。
2. 机构可提交目标范围配置。
3. 报告推送接收地址配置。
4. 危急值推送接收地址配置。

配置变更影响范围：

1. 机构默认接收方配置只影响变更后新创建的申请，不自动修改已创建申请。
2. 机构可提交目标范围配置影响变更后新创建申请或新提交动作的校验，不自动撤销历史申请。
3. 报告推送接收地址配置影响变更后发生的新推送、补推和重试。
4. 危急值推送接收地址配置影响变更后发生的新推送、补推和重试。
5. 平台需要保留配置变更记录。

### 11.3 费用状态和绿色通道

费用状态建议包括：

1. 已收费。
2. 未收费。
3. 无需收费。
4. 未知。

绿色通道信息建议包括：

1. 是否绿色通道：是或否。
2. 绿色通道原因或说明。

平台只接收、记录、展示和查询费用状态及绿色通道信息，不负责收费、退费、医保结算。

### 11.4 业务审计边界

PRD 需要写入业务动作留痕要求，但不设计用户、角色、菜单、权限和审计系统。

业务动作留痕至少应包含操作时间、操作人或调用系统、操作对象、操作结果。涉及原因的动作还应记录原因。

必须留痕的业务动作包括：

1. 创建申请、取消申请。
2. 创建、调整、作废包。
3. 创建、调整、关闭、重新打开申请批次。
4. 样本送出、送出撤回。
5. 样本接收、异常登记、退回、异常关闭。
6. 样本状态回传。
7. 报告上传、重传、撤回提交、审核、发布。
8. 报告查询下载。
9. 危急值记录、推送、处理结果回传。
10. 报告或危急值推送、补推或重试。
11. 管理端跨机构查看和高敏信息查看。

管理端跨机构查看和高敏信息审计粒度继续保留在内部确认项中。

## 12. 验收标准调整方向

验收标准需要同步调整：

1. 删除配送单相关验收。
2. 增加申请批次创建、调整、关闭、重新打开和查询验收。
3. 增加送出记录、送出撤回、送出快照和部分撤回验收。
4. 增加未送出不可接收的反向规则。
5. 增加未接收不可上传报告的反向规则。
6. 增加申请取消后不可恢复、条码不可复用的反向规则。
7. 增加包作废后不可恢复的反向规则。
8. 增加报告撤回后不作为有效报告展示的反向规则。
9. 增加报告重传新版本发布后旧版本已替代的验收。
10. 增加报告撤回推送事件和重传替代关系推送验收。
11. 增加推送失败可查询、可补推或重试的验收。
12. 增加业务动作留痕验收。

验收标准仍只描述功能完成程度，不写响应时间、并发量、吞吐量、容量、可用性百分比和性能压测指标。
