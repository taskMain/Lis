# 评审目标

本说明用于辅助业务方、产品方、开发方、测试方和外部系统对接方评审第六版需求规约，重点确认：

* 第六版是否准确承接第五版修订稿2中的有效业务范围。
* 申请、样本、报告、危急值、推送、权限和接口边界是否前后一致。
* 各模块验收标准是否可被开发实现、测试验证和业务验收。
* 不纳入当前版本的能力是否已经明确排除，避免后续设计和开发阶段产生范围偏差。

# 本版整理原则

| 原则 | 说明 |
| --- | --- |
| 以第五版修订稿2为准 | 第六版以第五版修订稿2作为业务规则依据，第四版仅用于补充背景和表达方式 |
| 不引入未确认能力 | 未在第五版修订稿2中形成明确依据的功能，不写入当前需求范围 |
| 业务对象分层表达 | 分别描述申请、样本轮次、送出记录、异常记录、报告版本、危急值记录和推送事件 |
| 状态由业务动作驱动 | 状态变化必须来自明确业务动作、接口回传或页面处理，不提供通用人工改状态能力 |
| 接口边界单独收口 | 主文档只定义接口能力和业务归属，字段、安全、错误码、幂等和失败处理进入接口设计阶段 |
| 验收标准可测 | 每个模块的验收标准应能转化为测试用例，避免使用无法判断结果的表述 |

# 与第五版相比的主要调整

| 调整项 | 第六版处理方式 |
| --- | --- |
| 文档结构 | 按软件需求规约格式重组为简介、整体说明、具体需求、非功能、接口和待配套设计确认事项 |
| 业务范围 | 保留申请、样本打包、送出、接收、状态、异常、报告、危急值、推送、通知、权限、项目目录和对照 |
| 状态体系 | 明确区分申请状态、样本主状态、送出记录状态、异常状态、报告状态、危急值处理状态和推送状态 |
| 样本打包 | 明确同一发起机构样本可入同一包，送出后包内样本锁定；空包不自动失效 |
| 样本接收 | 明确待接收清单、按样本接收、按包接收、异常接收、未到货和后续到货处理边界 |
| 异常处理 | 明确异常处理结果不直接等同于样本主状态，样本主状态由处理结果和后续业务动作共同驱动 |
| 报告管理 | 明确报告上传、审核、发布、重传、作废、当前有效报告和版本追溯规则 |
| 危急值管理 | 明确危急值只能随报告上传进入平台，不提供单独创建能力；平台记录内部处理留痕，不替代医院临床处置闭环 |
| 推送管理 | 将报告和危急值推送定义为平台形成的业务推送事件，不定义为外部系统主动调用接口 |
| 接口章节 | 汇总 I01-I11 对外接口，并列出当前版本不提供的接口能力 |
| 资料引用栏目 | 删除独立资料引用栏目，避免引用不存在或不作为当前依据的文档 |

# 重点业务确认项

| 编号 | 确认项 | 需要确认的结论 |
| --- | --- | --- |
| Q01 | 申请是否只通过发起机构外部接入系统创建 | 是否确认平台不提供正常业务下的人工补录申请页面 |
| Q02 | 终止申请的影响范围 | 是否确认终止申请后阻断后续样本流转、报告上传和推送，但保留既有历史记录 |
| Q03 | 费用状态和绿色通道 | 是否确认平台只接收和展示费用状态、绿色通道信息，不承担收费、退费和医保结算 |
| Q04 | 样本入包条件 | 是否确认当前版本仅要求同一发起机构样本入同一包，不额外要求同一接收方 |
| Q05 | 包送出后的锁定规则 | 是否确认包送出后不能调整包内样本，后续差异通过撤回、补送或重新送检处理 |
| Q06 | 样本未到货后的到货处理 | 是否确认未到货样本后续到货时可以由接收方按样本再次处理，并形成新的接收记录 |
| Q07 | 异常处理结果枚举 | 是否确认继续检测、退回样本、样本损毁、无法检测、运输丢失、关闭异常为当前版本支持的处理结果 |
| Q08 | 报告审核开关 | 是否确认审核开关开启时报告需审核后发布，关闭时报告上传后按规则直接发布 |
| Q09 | 报告作废边界 | 是否确认报告作废只能通过平台页面执行，不提供对外作废接口 |
| Q10 | 危急值来源 | 是否确认危急值只能随报告上传进入平台，不支持平台页面或外部接口单独创建危急值 |
| Q11 | 医院侧危急值回执 | 是否确认医院侧回执只记录医院侧确认或处理结果，不代表平台完成临床处置闭环 |
| Q12 | 内部通知 | 是否确认平台内部通知只进入申请详情时间线或业务列表提示，不建设独立待办中心 |

# 接口边界确认项

| 编号 | 确认项 | 需要确认的结论 |
| --- | --- | --- |
| I-Q01 | I01 创建申请 | 是否确认申请创建接口由发起机构外部接入系统调用 |
| I-Q02 | I02 终止申请 | 是否确认终止申请接口不产生面向外部机构的终止通知接口 |
| I-Q03 | I03 样本重新送检 | 是否确认重新送检必须基于已存在的异常记录发起 |
| I-Q04 | I05 创建包 | 是否确认创建包既可通过页面，也可通过发起机构外部接入系统接口 |
| I-Q05 | I07 待接收清单 | 是否确认接收方或上传方外部接入系统可查询待接收送出记录和样本明细 |
| I-Q06 | I08 样本接收确认 | 是否确认接收结果以样本为单位提交，支持正常接收、异常接收和未到货 |
| I-Q07 | I09 回传检测开始 | 是否确认检测中状态只能由接收方外部接入系统回传或后续检测流程触发 |
| I-Q08 | I10 上传报告（含重传） | 是否确认平台页面不提供人工上传报告能力 |
| I-Q09 | I11 危急值处理回执 | 是否确认该接口调用方为发起机构系统，具体字段和安全规则进入接口设计阶段 |
| I-Q10 | 推送能力 | 是否确认报告发布、危急值发布、报告作废、危急值失效和报告审核结果属于平台主动推送事件 |

# 状态与验收确认项

| 编号 | 确认项 | 需要确认的结论 |
| --- | --- | --- |
| S-Q01 | 状态命名 | 是否确认主文档中的状态名称可作为后续设计和测试用例的统一口径 |
| S-Q02 | 样本主状态 | 是否确认样本主状态不通过独立页面人工修改，只由业务动作驱动 |
| S-Q03 | 送出记录状态 | 是否确认送出记录状态独立于样本主状态，用于表达送出、撤回、补送和接收过程 |
| S-Q04 | 异常状态 | 是否确认异常记录状态独立于样本主状态，用于表达异常是否已处理 |
| S-Q05 | 报告状态 | 是否确认报告状态独立于申请状态和样本主状态，用于表达待审核、已发布、审核不通过、已作废等报告生命周期 |
| S-Q06 | 危急值处理状态 | 是否确认危急值处理状态只表达平台内部处理留痕和医院侧回执记录 |
| S-Q07 | 验收标准 | 是否确认 F01-F11 的验收标准可以分别转化为页面测试、接口测试、状态流转测试和权限相关测试 |

# 暂不纳入当前版本的范围

| 暂不纳入项 | 说明 |
| --- | --- |
| 独立待办中心 | 当前版本通过业务列表、详情和时间线承载提示 |
| 危急值超时提醒和升级提醒 | 当前版本不定义危急值时限管理和升级机制 |
| 运输轨迹管理 | 当前版本只记录样本送出、接收、异常和补送，不管理物流轨迹 |
| 业务数据导出接口 | 当前版本不提供申请列表、报告列表、异常记录等业务数据导出接口 |
| 平台人工上传报告 | 报告只能由上传方通过对外接口提交 |
| 报告审核和作废对外接口 | 报告审核、作废仅通过平台页面执行 |
| 危急值单独创建 | 危急值只能随报告上传进入平台 |
| 通用样本状态修改 | 样本主状态只能由业务动作驱动 |
| 收费、退费和医保结算 | 平台只接收费用状态和绿色通道信息，不承担结算能力 |
| 医院临床危急值闭环 | 平台记录危急值和回执，不替代医院内部临床处置流程 |
| 隐私保护、脱敏、敏感信息搜索和敏感信息导出规则 | 当前版本不定义相关规则 |
