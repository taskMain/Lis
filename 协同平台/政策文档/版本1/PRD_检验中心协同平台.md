# 检验中心协同平台 - 产品需求文档（PRD）

> 版本：v1.0 | 作者：产品团队 | 日期：2026-05-13
> 状态：草稿 | 密级：内部机密

---

## 1. 概述

### 1.1 背景与动机

**政策驱动**：国家卫健委2025年2月印发《紧密型县域医共体信息化功能指引》（国卫办规划函〔2025〕63号），明确要求建设"医学检验资源共享中心"，实现县域内检验数据互联互通与结果互认，规范"基层采样、物流转运、中心检测、实时查阅"的闭环服务模式。

**业务痛点**：当前县域医共体内各成员单位（县级医院、乡镇卫生院、村卫生室）普遍使用不同厂商、不同时期的HIS系统，检验数据分散在各自LIS中，形成严重的"信息孤岛"。患者重复检验、检验结果无法跨机构调阅、危急值通知不及时、质控管理各自为政等问题突出。

**产品定位**：检验中心协同平台是面向紧密型县域医共体的区域性检验业务协同管理系统，连接医共体内多家医疗机构的多套HIS系统，整合分散的LIS数据，实现检验申请、样本流转、结果发布、质控管理、危急值闭环等全流程的区域协同，最终达成检验结果互认、减少重复检验、提升基层服务能力的目标。

### 1.2 目标

**业务目标**：
- 实现医共体内检验业务全流程数字化协同，检验结果互认率达到90%以上
- 将基层送检样本的检验前TAT（周转时间）控制在4小时以内
- 危急值通报率达到100%，通报及时率达到95%以上
- 减少患者重复检验比例，降低区域整体检验成本15%以上

**用户目标**：
- **基层医生**：足不出院即可为患者申请检验项目，实时查看检验结果，接收危急值提醒
- **检验中心人员**：高效处理来自多机构的检验样本，统一管理质控数据，自动审核结果
- **患者**：在家门口完成采样，通过手机查询检验报告，享受与县级医院同质的检验服务
- **管理者**：全面掌握区域检验业务运行状况，基于数据驱动决策优化资源配置

**成功指标（KPI）**：

| 指标 | 基线值 | 目标值（上线6个月） | 目标值（上线12个月） |
|------|--------|-------------------|-------------------|
| 检验结果互认率 | <10% | ≥60% | ≥90% |
| 检验前TAT中位数 | 8-12小时 | ≤6小时 | ≤4小时 |
| 危急值通报及时率 | <70% | ≥90% | ≥95% |
| 患者重复检验率 | 25-35% | ≤20% | ≤12% |
| 样本条码识别率 | <85% | ≥95% | ≥98% |
| 报告查询线上化率 | <20% | ≥50% | ≥75% |

### 1.3 范围

**本期包含（Must + Should）**：
- 检验业务流程管理：检验申请、样本运输、样本核收、样本检验、结果审核、报告查询、报告打印、报告模板管理
- 质量与安全管控：危急值闭环管理、室内质控数据实时监控、室间质评数据上报
- 运营分析：工作量统计、阳性率分析、TAT分析、质控趋势分析
- 基础平台能力：患者主索引(EMPI)、检验项目标准化(LOINC)、用户权限管理、操作日志审计

**本期不包含（Won't Have）**：
- 区域影像（PACS）/心电/病理诊断中心的协同功能（属于不同资源共享中心，可二期扩展）
- AI辅助诊断、检验结果智能解读等高级智能化功能（需在数据积累后评估）
- 区域供应链管理和试剂耗材统一采购管理（属于HRP范畴）

## 2. 用户画像

### 2.1 角色定义

| 角色编号 | 角色名称 | 身份 | 核心目标 | 主要痛点 |
|----------|----------|------|----------|----------|
| P-001 | **基层医生** | 乡镇卫生院/社区卫生服务中心的全科医生或专科医生 | 为患者开具检验申请，及时获取检验结果用于临床诊疗 | 需让患者奔波至县级医院采样；检验结果纸质传递慢；危急值电话通知不及时 |
| P-002 | **采样护士** | 基层医疗机构的护理人员 | 按规范完成样本采集、打包和条码粘贴 | 手工填写申请单易出错；条码打印设备操作复杂；不合格样本经常被退回 |
| P-003 | **检验中心技师** | 县域检验中心的检验技师/医师 | 高效完成样本核收、上机检测、结果审核和报告发布 | 需手工录入来自多机构的申请信息；样本状态不透明；质控数据分散管理 |
| P-004 | **物流人员** | 负责样本转运的专职或兼职配送人员 | 按时、安全地将样本从基层转运至检验中心 | 手工登记交接单效率低；冷链状态无监控；样本丢失难以追溯 |
| P-005 | **质控管理员** | 检验中心的质量控制负责人 | 确保检验结果的准确性和可靠性，通过内外部质评 | 质控数据需从各仪器手工收集；失控处理无闭环追踪；室间质评数据汇总繁琐 |
| P-006 | **医共体管理者** | 县卫健委/医共体管委会的管理人员 | 全面掌握区域检验业务运行状况，优化资源配置 | 缺乏区域检验业务的全景数据；无法横向比较各机构检验质量；决策缺乏数据支撑 |
| P-007 | **患者/家属** | 在基层医疗机构就诊并接受检验服务的患者及其家属 | 方便快捷地完成检验、及时获取结果、减少重复检验 | 需多次往返医院；排队等候时间长；历史报告无处查询 |

## 4. 功能需求

### 4.1 功能清单

#### 4.1.1 业务流程管理模块

| 功能编号 | 功能名称 | 所属用户故事 | 功能描述 | 输入/输出/交互 |

## 6. 验收标准

### 6.1 F-001 跨机构电子检验申请

**AC-F001-01：正常申请流程**
```
Given 基层医生已在HIS工作站登录且有开单权限
  And 患者已在系统中建档
When 医生选择检验项目并提交申请
Then 系统在3秒内生成电子申请单
  And 申请单包含患者基本信息、临床诊断、检验项目集、申请机构/科室/医生
  And 系统分配唯一申请单号和条码
  And 申请单状态为"待采样"
  And 条码信息回传至HIS工作站可供打印
```

**AC-F001-02：必填项校验**
```
Given 基层医生在申请界面
When 医生未填写临床诊断或检验项目为空时提交申请
Then 系统阻止提交
  And 高亮显示未填写的必填项
  And 提示"请填写临床诊断"或"请至少选择一项检验项目"
```

**AC-F001-03：重复申请提醒**
```
Given 患者48小时内已在同一机构申请过相同检验项目
When 医生再次提交相同申请
Then 系统弹出提醒窗口"该患者48小时内已申请过此项目，是否继续？"
  And 显示历史申请时间和结果状态
  And 医生可选择"继续申请"或"查看历史结果"
```

### 6.2 F-002 样本标签打印与采集管理

**AC-F002-01：条码标签自动生成**
```
Given 电子申请单已成功创建
When 申请单状态流转至"待采样"
Then 系统自动触发条码标签打印任务
  And 标签包含：申请单号条码、患者姓名、性别、年龄、检验项目、采集要求、样本类型
  And 条码支持Code 128或QR Code格式，可被标准扫描设备识别
```

**AC-F002-02：采集确认**
```
Given 采样护士已完成样本采集
  And 条码标签已粘贴于样本容器
When 护士使用PDA/扫码枪扫描样本条码
Then 系统识别样本并更新状态为"已采集"
  And 记录采集时间、采集护士工号
  And 检验中心可实时查看该样本状态变更
```

**AC-F002-03：采集指引展示**
```
Given 采样护士查看申请单详情
Then 系统显示该检验项目的采集要求
 包括：样本类型（血清/血浆/全血/尿液等）、采集容器颜色/规格、采集量、采集时间要求、特殊注意事项
  And 如有多个项目，显示合并采集建议
```

```
Then 系统自动匹配电子申请单
```

**AC-F004-02：不合格样本处理**

**AC-F004-03：申请单缺失处理**
```
Given 扫描样本条码后系统未找到匹配申请单
When 核收人员选择"申请单缺失"标记
Then 系统记录该异常样本信息
  And 自动向申请机构发送"申请单补录"通知
```

### 6.6 F-006 结果审核与人工干预

**AC-F006-01：自动审核通过**
```

When 规则引擎执行判断
```

**AC-F006-02：人工审核触发**
```
Given 检验结果触发至少一条异常规则
When 规则引擎执行判断
Then 系统将该结果标记为"待人工审核"
  And 在审核工作队列中高亮显示
  And 展示触发规则的具体说明
```

**AC-F006-03：人工审核操作**
```

Then 结果状态变更为"已审核（人工）"
  And 记录审核医师工号和审核时间
  And 触发报告发布流程
When 医师判断结果需复检并点击"申请复检"

  And 状态变更为"待复检"

```

## 7. 假设与约束

### 7.1 假设

- **政策环境**：国家紧密型县域医共体建设政策在目标区域持续推行，医共体组织架构已理顺
- **成员单位配合**：医共体内各医疗机构愿意配合系统进行接口改造和数据对接
- **网络基础设施**：县域医共体内各医疗机构之间具备稳定可靠的网络连接（专网或VPN）
- **硬件设备**：检验中心具备或愿意采购条码扫描设备、PDA、自助打印终端等配套硬件
- **人员培训**：各机构关键用户（医生、护士、技师）能够接受并适应新的工作流程
- **数据质量**：各成员单位HIS中的患者基本信息和检验项目数据质量基本可接受
- **标准编码**：区域内能够推进检验项目的LOINC编码映射工作
- **物流保障**：县域内具备专业的样本物流转运能力或可由第三方物流承接

### 7.2 约束

- **技术约束**：
  - 平台架构需预留与后续影像、心电、病理等资源共享中心的扩展接口
  - 需兼容现有主流HIS厂商（卫宁、东软、创业慧康等）的接口规范
  - 患者端需同时支持微信小程序和Web浏览器访问

- **业务约束**：
  - 检验项目范围以区域内常规检验项目为主，特殊项目（如基因检测）暂不支持
  - 危急值项目和界限需与医务科协商确定，并在系统上线前完成配置
  - 检验结果互认需遵循国家和省级卫生健康行政部门发布的互认规则

- **时间约束**：
  - MVP版本需在医共体建设验收前完成上线（通常为合同签订后4-5个月）

- **合规约束**：
  - 系统需满足网络安全等级保护三级要求
  - 医疗数据管理需符合《健康医疗数据安全管理办法》
  - 系统功能和流程需符合ISO 15189医学实验室认可标准

### 7.3 风险

| 风险编号 | 风险描述 | 影响 | 概率 | 缓解措施 |
|----------|----------|------|------|----------|
| R-001 | 成员单位HIS接口改造不配合或进度延迟 | 高 | 中 | 合同中明确接口改造条款，预留缓冲时间，提供技术支持和培训 |
| R-002 | 历史数据质量差导致EMPI匹配率低 | 高 | 高 | 提前进行数据质量评估，制定数据清洗方案，分阶段推进标准化 |
| R-003 | 基层人员操作不熟练导致流程阻塞 | 中 | 中 | 制定详细的操作手册，开展现场培训，设置系统操作引导 |
| R-004 | 网络不稳定导致数据传输中断 | 中 | 中 | 设计离线缓存和断点续传机制，重要数据本地备份 |
| R-005 | 检验结果互认涉及利益分配争议 | 高 | 低 | 配合医共体管委会制定利益分配方案，系统提供互认统计数据支撑 |
| R-006 | 等保测评不通过导致无法上线 | 高 | 低 | 设计阶段即引入安全要求，提前联系测评机构进行预评估 |
| R-007 | 样本物流不及时影响检验TAT | 中 | 中 | 与物流方签订SLA，系统设置超时预警，建立应急转运机制 |
