# 检验中心协同平台 — P0功能清单与HIS对接方案

> 版本：v1.0 | 日期：2026-05-13 | 状态：正式
>
> **定位**：本文档基于《检验中心协同平台PRD》的MoSCoW优先级，聚焦P0（Must Have）级别功能，明确平台边界、HIS厂商职责、以及Web应用形态下的功能设计。

---

## 1. 产品形态定义：Web应用

检验中心协同平台采用**纯Web应用**形态交付，所有功能通过浏览器访问，无需安装客户端软件。此形态的决定基于以下考量：

| 维度 | 设计决策 | 说明 |
|------|----------|------|
| **部署方式** | B/S架构，云端部署 | 平台统一部署于医共体数据中心或政务云，各成员单位通过浏览器接入 |
| **终端覆盖** | 桌面端为主，移动端为辅 | 桌面端面向医生工作站、检验技师、管理员；移动端面向物流人员和患者 |
| **浏览器兼容** | Chrome/Firefox/Edge 最新2个版本 | 基层医疗机构IT维护能力有限，优先保障主流现代浏览器 |
| **前端技术** | 响应式Web设计 | 适配不同分辨率显示器（医生工作站大屏、PDA平板、管理后台宽屏） |
| **打印能力** | 浏览器原生打印 + 打印插件 | 条码标签打印、报告打印通过浏览器调用本地打印机 |
| **集成方式** | API接口 + 回调/推送 | 平台不以iframe或弹窗方式嵌入HIS工作站；HIS在原生工作站界面中发起业务操作，并通过RESTful API、回调接口、WebSocket与平台交互 |
| **患者端** | 微信小程序（内嵌H5） | 患者端以微信小程序为载体，内嵌平台H5页面 |

**Web应用形态下的交互约束**：
- 页面操作响应时间 ≤ 2秒（首屏加载 ≤ 3秒）
- 打印功能需兼容主流品牌条码打印机和激光打印机
- 支持平台内部页面的浏览器级通知；HIS工作站内通知由HIS接收平台推送后在其原生界面实现
- 所有页面操作支持键盘快捷键，方便医生高效操作
- 页面设计符合医疗行业操作习惯，核心流程操作步数 ≤ 5次点击

## 2. P0功能清单（Must Have）

### 2.1 功能总览

P0级别共 **17项核心功能**，按业务模块分为 **3大模块群**：

| 模块群 | 功能数量 | 核心目标 |
|--------|----------|----------|
| **A. 业务流程管理** | 8项 | 实现"申请→采样→转运→核收→检测→审核→报告"全流程数字化 |
| **B. 质量与安全管控** | 3项 | 保障检验结果准确性和患者安全，满足监管合规要求 |
| **C. 平台基础能力** | 6项 | 提供跨机构数据治理、安全管理和系统运行的基础支撑 |

### 2.2 A. 业务流程管理（8项）

此模块覆盖检验业务的全生命周期，是平台的核心业务流。

#### A-1. 跨机构电子检验申请（F-001）

| 属性 | 内容 |
|------|------|
| **功能编号** | F-001 |
| **功能名称** | 跨机构电子检验申请 |
| **业务价值** | ★★★★★ **业务流程起点**。没有此功能，区域检验协同无法启动。实现基层医生足不出院即可为患者申请区域检验项目，是"基层采样、中心检测"模式的入口。 |
| **核心用户** | 基层医生（P-001） |
| **业务入口** | HIS医生工作站原生医嘱/申请界面；平台通过API接收HIS提交的检验申请 |

**功能简述**：基层医生在HIS工作站原生界面开具检验医嘱时，HIS调用平台提供的申请接口，平台生成符合区域标准的电子申请单（E-order），包含患者信息、临床诊断、检验项目集、申请机构/科室/医生信息，并分配唯一申请单号和条码。

**P0必须包含的子功能**：
- 检验项目目录接口（供HIS在原生界面中检索与选择，支持按拼音/编码/分类检索）
- 申请单服务端必填项校验（患者信息、临床诊断、检验项目）
- 唯一申请单号+条码自动生成
- 重复申请提醒（48小时内同项目重复申请时提醒）
- 申请单状态管理（待采样→已采样→...）
- 申请单撤回（仅"待采样"状态允许撤回）

**平台 vs HIS分工**：
| 职责方 | 工作内容 |
|--------|----------|
| **平台** | 提供检验项目目录接口、申请单服务端校验规则、条码生成、状态管理、申请单查询接口 |
| **HIS厂商** | 在医生工作站原生界面实现检验申请入口和交互校验，调用平台API发送医嘱数据，接收平台返回的条码和确认信息 |

### 4.4 接口安全规范

| 安全机制 | 说明 |
|----------|------|
| **认证方式** | API Key + Bearer Token，每次请求Header携带 `Authorization: Bearer {token}` |
| **签名验证** | 平台向HIS推送数据时，使用HMAC-SHA256签名，HIS验证签名确保数据未被篡改 |
| **传输加密** | 所有接口强制使用HTTPS（TLS 1.2+），WebSocket使用WSS |
| **IP白名单** | HIS调用平台API需配置IP白名单，平台向HIS推送同样校验来源IP |
| **请求限流** | 每机构每分钟最多1000次请求，超出返回429状态码 |
| **数据脱敏** | 接口返回的患者身份信息按最小必要原则返回，敏感字段按需脱敏 |
| **日志审计** | 所有API调用记录完整日志（请求方、接口、时间、结果），保留不少于180天 |
