## 图1：条码流转主链

> 本图只表达条码从创建、审核、送出、接收、检测到报告的主流程。机构项目对照与项目识别详见图6；样本异常处理详见图3；接收方适配条码规则详见图2；推送与平台消息详见图5。

```mermaid
    G6{"是否作废当前有效报告？"}:::decision
    G7["报告状态=已作废<br>当前无有效报告"]:::process

    E2 --> F1
    E3 -.->|"异常已关闭或处理结果允许继续检测"| F1
    F1 -->|"是"| F2 --> G1
    F1 -->|"否/未回传"| G1
    G1 --> G2
    G2 -->|"否"| G3
    G2 -->|"是"| G4 --> G5 --> G6
    G6 -->|"否"| G5
    G6 -->|"是"| G7 --> G1

    T2["已送出未接收后到货拦截<br>不生成接收记录/接收结果"]:::terminal
    A9 -.->|"允许阶段"| T1
    A10 -.->|"允许阶段"| T1
    D1 -.->|"已送出未接收"| T1
    E4 -.->|"未到货待处理"| T1

    D6 -.-> N1
    G1 -.-> N1
```

**图1说明：**

1. 创建申请按一次接口调用整体成功或整体失败；任一条码创建校验、机构项目对照、协作关系或适配条码生成失败时，本次申请整体失败。
2. 平台不生成发起机构样本条码；平台只在接收方存在当前使用规则时生成接收方适配条码。
3. 补送仅适用于按包送出后，发现未纳入原包或原送出记录的漏送样本；补送不修改原包清单和原送出快照。
4. 接收按样本形成接收处理结果，不生成包级接收结果。
5. 检测开始回传是可选推进动作；未回传检测开始不影响符合条件时上传报告。
6. 条码终止后条码状态为已结束，样本主状态保持终止发生时状态，不回退、不删除历史记录。

## 图2：接收方适配条码规则与使用边界

```mermaid

    classDef page fill:#f3e5f5,stroke:#7b1fa2,stroke-width:1px
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef external fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    R1["平台运营页面<br>新增草稿规则"]:::page
    R2{"设为当前使用前校验"}:::decision
    R3["校验失败<br>保持草稿"]:::terminal
    R4{"该接收方已有当前使用规则？"}:::decision
    R5["旧当前使用规则归档"]:::process
    R6["新规则设为当前使用<br>同一接收方仅一条"]:::process
    R7["归档草稿或历史规则<br>不可恢复/不可再启用"]:::terminal

    R1 --> R2
    R2 -->|"失败"| R3
    R2 -->|"通过"| R4
    R4 -->|"是"| R5 --> R6

    A1["创建申请校验通过后<br>事务提交前"]:::process
    A2{"接收方存在当前使用规则？"}:::decision
    A3["不生成适配条码<br>按机构编码=接收方编码+发起机构编码+样本条码定位"]:::process
    A4["按规则版本和计数维度<br>生成适配条码"]:::process
    A5{"生成成功？"}:::decision
    A6["创建申请整体失败<br>不生成平台申请单和条码记录<br>不产生可用适配条码"]:::terminal
    A7["保存适配条码<br>同一接收方内唯一"]:::process

    A1 --> A2
    A2 -->|"否"| A3
    A2 -->|"是"| A4 --> A5
    A5 -->|"失败/冲突/容量不足"| A6
    A5 -->|"成功"| A7

    U1["接收方侧查询接口<br>可返回适配条码"]:::external
    U2["接收确认/异常登记/异常处理<br>检测开始/报告上传可用适配条码定位"]:::external
    U3["发起机构侧查询/推送/报告获取<br>不返回适配条码"]:::note
    U4["平台不打印<br>不维护模板/打印机/打印状态"]:::note
    U5["规则归档或替换<br>不影响历史适配条码继续使用"]:::note

    A7 --> U1 --> U2
    A7 -.-> U3
    A7 -.-> U4
    R5 -.-> U5
    R7 -.-> U5
```

**图2说明：**

1. 接收方适配条码规则管理是平台页面能力，不提供规则管理、规则查询或规则历史查询对外接口。
2. 接收方侧外部接入系统只使用已生成的接收方适配条码，不读取规则配置和规则版本。
3. 无当前使用规则或历史条码无接收方适配条码时，接收方侧仍按“发起机构编码+样本条码+机构编码=接收方编码”完成定位。
4. 报告状态查询接口无论发起机构侧或接收方侧均不返回接收方适配条码。
5. 已生成的接收方适配条码不可复用、不可人工修改；条码结束、报告作废、异常结束或流程结束均不释放适配条码。
6. 平台不负责接收方适配条码打印、贴管或上机识别流程。
7. 草稿规则设为当前使用时，如该接收方已有当前使用规则，平台将旧当前使用规则归档；如没有当前使用规则，则直接设为当前使用。

## 图3：样本异常处理分支

```mermaid
flowchart TD
    classDef source fill:#f3e5f5,stroke:#7b1fa2,stroke-width:1px
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    START(["样本异常处理"]) --> SRC{"异常来源"}:::decision
    SRC --> A["异常接收<br>实物存在但有问题"]:::source
    SRC --> B["未到货<br>送出记录有样本但实物未到"]:::source
    SRC --> C["已接收后异常登记<br>检测完成前"]:::source

    A --> A1{"处理结果"}:::decision
    A1 -->|"继续检测/关闭异常"| A2["解除阻断<br>继续后续流程"]:::process
    A1 -->|"退回/损毁/无法检测"| A3["条码状态=已结束<br>结束类型=样本无法继续检测<br>样本主状态保持已接收"]:::terminal

    B --> B1{"未到货后续结论"}:::decision
    B1 -->|"延迟到货"| B2["同一事务处理<br>先关闭原未到货异常<br>再追加正常/异常接收"]:::process
    B2 --> B3["样本主状态=已接收<br>形成最终接收结论"]:::process
    B1 -->|"未实际送出/送出登记错误"| B4["发起机构先样本级撤回<br>撤回成功后回到待送出<br>接收方再关闭未到货异常"]:::process
    B1 -->|"运输丢失"| B5["条码状态=已结束<br>结束类型=样本无法继续检测<br>样本主状态保持已送出"]:::terminal
    B -.-> B6["条码终止联动归档<br>非异常处理接口提交"]:::terminal
    B6 -.-> B7["后续到货拦截<br>不生成接收记录/接收结果<br>不进入异常处理"]:::terminal
    B -.-> B8["漏送但未纳入原包/原送出记录<br>另走补送或普通送出"]:::note

    C --> C1{"样本阶段"}:::decision
    C1 -->|"已接收"| C2{"处理结果"}:::decision
    C2 -->|"继续检测/关闭异常"| C3["解除阻断<br>继续检测"]:::process
    C2 -->|"退回/损毁/无法检测"| C4["条码状态=已结束<br>样本主状态保持已接收"]:::terminal
    C1 -->|"检测中"| C5{"处理结果"}:::decision
    C5 -->|"继续检测/关闭异常"| C6["解除阻断<br>继续检测"]:::process
    C5 -->|"无法检测"| C7["条码状态=已结束<br>样本主状态保持检测中"]:::terminal
    C1 -->|"检测完成/已有报告"| C8["不新增样本异常<br>转报告作废/再次上传/线下协商"]:::note
```

**图3说明：**

1. 未到货是临时接收处理结果，不属于最终接收结论；延迟到货后通过正常接收或异常接收形成最终接收结论。
2. 未到货因条码终止自动关闭归档时，不表示实物问题已解决，只表示条码结束后的业务归档。
3. 运输丢失仅适用于未到货且样本主状态为已送出的场景。
4. 导致条码结束的异常处理结果不改写样本主状态；条码是否可继续流转由条码状态控制。
5. 已检测完成或已有报告后发现问题，不再新增样本异常，按报告作废、再次上传或线下协商处理。
6. 待处理异常默认阻断检测开始、检测完成和报告上传。

## 图4：报告生命周期状态机

```mermaid
flowchart TD
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    A["报告上传<br>PDF+结构化结果均提交"]:::process
    B{"前置校验通过？"}:::decision
    C["拒绝上传"]:::terminal
    D["报告状态=已发布<br>成为当前有效报告"]:::process
    E{"是否作废当前有效报告？"}:::decision
    F["报告状态=已作废<br>当前无有效报告"]:::process
    G["再次上传成功<br>生成新报告版本"]:::process
    N1["已发布时不允许直接再次上传<br>必须先作废当前有效报告"]:::note
    N2["作废不恢复旧版本<br>发起机构不获取已作废报告详情"]:::note

    A --> B
    B -->|"否"| C
    B -->|"是"| D
    D --> E
    D -.-> N1
    E -->|"否"| D
    E -->|"是"| F
    F --> G --> D
    F -.-> N2
```

**图4说明：**

1. 当前版本不提供平台报告审核；报告上传成功即发布。
2. 报告作废不通过对外接口发起，由具备权限的接收方用户或平台运营人员通过平台页面操作。
3. 作废当前有效报告后，不自动恢复旧版本为当前有效报告。
4. 发起机构获取当前有效报告时，只获取当前已发布且未作废的报告；没有当前有效报告时不返回历史作废报告详情。
5. 最新报告版本为已发布时，不允许直接上传新报告，必须先作废当前有效报告。
6. 报告上传前置校验详见 PRD 1.7，本图不展开全部校验条件。
7. 报告状态查询中，发起机构侧可返回报告归属接收方机构编码；接收方侧按入参机构编码限定本接收方数据范围，不重复返回接收方机构编码。

## 图5：外部推送与平台消息边界

```mermaid
flowchart TD
    classDef trigger fill:#f3e5f5,stroke:#7b1fa2,stroke-width:1px

    P0 --> P1["按发起机构编码+推送类型<br>查找启用配置"]:::process
    P1 --> P2{"是否存在启用配置？"}:::decision
    P2 -->|"否"| P3["推送失败记录<br>未配置有效接口<br>不进入自动重试"]:::terminal

    P4 --> P5{"发送结果"}:::decision
    P5 -->|"成功"| P6["推送成功"]:::process

    T --> M0["平台消息<br>轻量消息中心"]:::process
    M0 --> M1["生成消息记录<br>支持列表、筛选、检索、已读/未读、跳转"]:::process
    M1 --> M2["不建设待办中心<br>不替代外部推送"]:::note
```

**图5说明：**

1. 当前版本外部推送类型包括：报告发布、报告作废、条码审核通过、条码审核不通过、条码终止、样本无法继续检测六类。
2. 当前版本外部推送对象仅为发起机构侧外部接入系统，接收方不是外部推送对象，也不维护推送接口配置。
3. 推送接口配置通过平台页面维护，不提供对外接口维护；配置修复后不自动补发历史失败推送。
4. 平台消息用于平台内提醒、查看和跳转，不承担外部系统集成职责，也不建设待办中心。

3. 创建申请接口不接收平台标准项目编码；平台按发起机构编码和机构项目编码匹配可用于创建申请的机构项目对照。
4. 接收方侧查询时，平台按接收方机构编码和平台标准项目编码反向匹配接收方机构项目编码和名称；未匹配不阻断样本查询、样本接收、异常处理、检测开始回传或报告上传。
5. 机构项目对照只做轻量维护留痕，不提供维护历史列表、变更前后差异、版本回滚、历史版本恢复或单独的对照维护日志管理页面。
6. 平台不识别、不解析、不拆分组合套餐；报告结构化结果中的明细结果项目不作为机构项目对照维护对象，不做报告子项标准化。
