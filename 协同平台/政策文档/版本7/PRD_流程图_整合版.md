## 条码流转主流程

> 本图只表达条码记录从创建到报告发布或结束的核心路径。创建校验支撑规则见《创建校验支撑规则图》；送出处理见《样本送出处理子流程》；接收与异常处理见《接收与异常处理子流程》；报告生命周期见《报告生命周期子流程》；推送与平台消息见《推送与平台消息边界图》。

```mermaid
flowchart TB
    classDef actor fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef platform fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    START([开始]):::platform
    A1["发起方提交创建申请<br>一次提交 1-N 条码"]:::actor
    P1{"协同平台创建校验是否通过？"}:::decision
    P2["协同平台创建申请单和条码记录<br>样本主状态=待送出"]:::platform
    P3{"协同平台判断是否需要条码审核？"}:::decision
    R1{"接收方条码审核结果"}:::decision
    P4["协同平台置条码状态=有效"]:::platform
    A2["发起方样本送出<br>按条码或按包"]:::actor
    P5["协同平台生成送出记录和送出快照<br>样本主状态=已送出"]:::platform
    R2{"接收方接收处理结果"}:::decision
    P6["协同平台接收后检测推进<br>可选回传检测开始；报告上传成功后检测完成"]:::platform
    R3["接收方报告上传"]:::actor
    P7{"协同平台判断报告上传成功？"}:::decision
    P8["当前有效报告发布<br>发起方可查询/获取"]:::terminal
    PR["报告上传拒绝<br>不生成报告版本"]:::terminal
    PF["创建整体失败<br>不生成平台申请单和条码记录"]:::terminal
    PE["条码状态=已结束"]:::terminal
    PI["后续到货拦截<br>不生成接收记录/接收结果"]:::terminal
    A3["发起方在允许阶段发起条码终止"]:::actor

    START --> A1 --> P1
    P1 -->|"否"| PF
    P1 -->|"是"| P2 --> P3
    P3 -->|"不需要审核"| P4
    P3 -->|"需要审核"| R1
    R1 -->|"通过/一键通过"| P4
    R1 -->|"不通过"| PE

    P4 --> A2 --> P5 --> R2
    R2 -->|"正常接收"| P6
    R2 -->|"异常接收且允许继续"| P6
    R2 -->|"异常导致无法继续检测"| PE
    R2 -->|"未到货待处理"| R2
    R2 -->|"未到货后确认运输丢失"| PE

    P6 --> R3 --> P7
    P7 -->|"否"| PR
    P7 -->|"是"| P8

    P2 -.->|"允许阶段"| A3
    P4 -.->|"允许阶段"| A3
    P5 -.->|"已送出未接收"| A3
    R2 -.->|"未到货待处理"| A3
    A3 -.-> PE
    PE -.->|"已送出未接收后到货"| PI

    N1["接收后检测推进说明：检测开始回传是可选状态推进动作；未回传检测开始不阻断符合条件时上传报告。"]:::note
    P6 -.-> N1
```

**《条码流转主流程》说明：**

1. 主流程只表达核心流转：创建申请、条码审核、送出、接收、检测推进、报告上传结果、当前有效报告发布，以及条码结束。
2. 创建申请按一次接口调用整体成功或整体失败；任一条码创建校验、院区协作关系、院区项目对照或接收方适配条码生成失败时，本次申请整体失败。
3. 按包送出、送出撤回、补送等送出细节不在主流程展开，见《样本送出处理子流程》。
4. 异常接收、未到货、运输丢失和异常导致无法继续检测等细节不在主流程展开，见《接收与异常处理子流程》。
5. 报告作废和作废后再次上传不在主流程展开，见《报告生命周期子流程》。
6. 外部推送和平台消息不改变主流程业务状态，见《推送与平台消息边界图》。

**建议继续展开的子流程节点：**

1. 创建校验支撑规则：院区协作关系、院区项目对照、接收方适配条码生成。
2. 样本送出处理：按条码送出、按包送出、撤回、补送。
3. 接收与异常处理：正常接收、异常接收、未到货、异常处理结果。
4. 报告生命周期：上传、发布、作废、再次上传。
5. 推送处理：外部配置系统 URL 查询、成功提交推送系统、未触发推送非阻断提示。

**需要进一步确认的问题：**

1. 主流程中的“接收后检测推进”是否需要在图名或节点文案中进一步强调“非独立状态”，以避免被误解为一个新的业务状态。
2. 《创建校验支撑规则图》和《院区项目对照与项目识别规则边界图》是否需要保留在本文档，还是移入单独的规则说明文档。

## 创建校验支撑规则图

> 本图不是独立业务流转，而是《条码流转主流程》“创建校验是否通过？”节点的支撑规则。所有结果都回到主流程的“创建继续”或“创建整体失败”。

```mermaid
flowchart TB
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef external fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    A["创建申请请求<br>发起医院/院区/科室<br>接收医院/院区<br>1-N 条码"]:::external
    B{"组织树与协作关系有效？"}:::decision
    C{"样本条码唯一性通过？"}:::decision
    D{"院区项目对照可用于创建？"}:::decision
    E{"接收院区存在当前使用适配条码规则？"}:::decision
    F["不生成接收方适配条码"]:::process
    G["生成接收方适配条码"]:::process
    H{"适配条码生成成功？"}:::decision
    I["创建继续<br>生成平台申请单和条码记录"]:::process
    X["创建整体失败<br>不生成平台申请单和条码记录"]:::terminal

    A --> B
    B -->|"否"| X
    B -->|"是"| C
    C -->|"否"| X
    C -->|"是"| D
    D -->|"否"| X
    D -->|"是"| E
    E -->|"否"| F --> I
    E -->|"是"| G --> H
    H -->|"否：失败/冲突/容量不足"| X
    H -->|"是"| I

    N1["院区项目对照：按发起医院+发起院区+院区项目编码匹配平台标准项目编码。"]:::note
    N2["接收方适配条码：按接收医院+接收院区当前使用规则生成；历史规则变化不回溯。"]:::note
    D -.-> N1
    G -.-> N2
```

**《创建校验支撑规则图》说明：**

1. 创建申请校验是主流程的前置节点，不单独形成业务流转。
2. 院区项目对照匹配失败、协作关系无效、条码唯一性不通过或适配条码生成失败，均回到主流程的“创建整体失败”。
3. 接收院区无当前使用适配条码规则时，创建申请可继续，但该条码记录不生成接收方适配条码。
4. 本图不展开院区项目对照维护过程和接收方适配条码规则维护过程。

## 样本送出处理子流程

> 本图展开《条码流转主流程》“样本送出”节点，最终回到主流程的“样本主状态=已送出”或“仍待送出/不再送出”。

```mermaid
flowchart TD
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef actor fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    A["有效条码<br>样本主状态=待送出"]:::process
    B{"送出方式"}:::decision
    C["按条码送出"]:::actor
    D["创建包"]:::actor
    E["调整未送出包<br>包内样本清单"]:::actor
    F["按包送出<br>锁定送出快照"]:::actor
    G["生成送出记录和送出快照<br>样本主状态=已送出"]:::process
    H{"送出后是否撤回？"}:::decision
    I["样本级送出撤回<br>符合条件回到待送出"]:::process
    J{"按包送出后是否漏送？"}:::decision
    K["补送<br>生成新送出记录<br>关联原包编码"]:::process
    L["进入主流程：待接收"]:::process
    X["不满足送出条件<br>仍待送出或条码已结束"]:::terminal

    A --> B
    B -->|"按条码"| C --> G
    B -->|"按包"| D --> E --> F --> G
    B -->|"条件不满足"| X
    G --> H
    H -->|"是"| I --> A
    H -->|"否"| J
    J -->|"是"| K --> L
    J -->|"否"| L

    N1["补送不修改原包清单和原送出快照。"]:::note
    K -.-> N1
```

**《样本送出处理子流程》说明：**

1. 待审核条码、已结束条码或不满足送出条件的条码不得送出。
2. 按包送出会锁定本次送出快照；后续补送生成新的送出记录，不回写原包清单。
3. 送出撤回只在符合 PRD 规则的阶段允许，撤回成功后回到主流程的待送出阶段。

## 接收与异常处理子流程

> 本图展开《条码流转主流程》“接收处理结果”节点，最终回到主流程的“接收后检测推进”“条码结束”“回到待送出”或“后续到货拦截”。

```mermaid
flowchart TD
    classDef source fill:#f3e5f5,stroke:#7b1fa2,stroke-width:1px
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    A["已送出样本<br>待接收"]:::process
    B{"接收处理结果"}:::decision
    C["正常接收<br>样本主状态=已接收"]:::process
    D["异常接收<br>样本主状态=已接收<br>生成异常记录"]:::source
    E["未到货<br>样本主状态保持已送出<br>生成未到货异常"]:::source
    F["回到主流程：接收后检测推进"]:::process

    A --> B
    B -->|"正常"| C --> F
    B -->|"异常"| D
    B -->|"未到货"| E

    D --> D1{"异常处理结果"}:::decision
    D1 -->|"继续检测/关闭异常"| F
    D1 -->|"退回/损毁/无法检测"| D2["条码状态=已结束<br>结束类型=样本无法继续检测<br>样本主状态保持已接收"]:::terminal

    E --> E1{"未到货后续结论"}:::decision
    E1 -->|"延迟到货"| E2["关闭未到货异常<br>追加正常/异常接收"]:::process
    E2 --> B
    E1 -->|"未实际送出/登记错误"| E3["发起方撤回成功<br>回到待送出"]:::process
    E1 -->|"运输丢失"| E4["条码状态=已结束<br>结束类型=样本无法继续检测<br>样本主状态保持已送出"]:::terminal
    E1 -->|"条码终止后到货"| E5["后续到货拦截<br>不生成接收记录/接收结果"]:::terminal

    N1["待处理异常默认阻断检测开始、检测完成和报告上传。"]:::note
    D -.-> N1
    E -.-> N1
```

**《接收与异常处理子流程》说明：**

1. 正常接收和允许继续检测的异常接收，回到主流程的“接收后检测推进”。
2. 异常处理导致无法继续检测、运输丢失或审核不通过等场景，回到主流程的“条码状态=已结束”。
3. 未到货延迟到货后，通过正常接收或异常接收形成最终接收结论。
4. 已送出未接收后条码终止，后续到货进入拦截，不生成接收记录或接收结果。

## 报告生命周期子流程

> 本图展开《条码流转主流程》“报告上传/当前有效报告发布”节点，最终回到主流程的“当前有效报告发布”“上传拒绝”或“当前无有效报告，可再次上传”。

```mermaid
flowchart TD
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef actor fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    A["接收方提交报告<br>PDF+结构化结果均必填"]:::actor
    B{"报告上传前置校验通过？"}:::decision
    C["拒绝上传<br>不生成报告版本"]:::terminal
    D["生成报告版本<br>报告状态=已发布<br>样本主状态=检测完成"]:::process
    E["当前有效报告<br>发起方可查询/获取"]:::process
    F{"是否作废当前有效报告？"}:::decision
    G["报告状态=已作废<br>当前无有效报告"]:::process
    H{"是否再次上传？"}:::decision

    A --> B
    B -->|"否"| C
    B -->|"是"| D --> E
    E --> F
    F -->|"否"| E
    F -->|"是"| G --> H
    H -->|"是"| A
    H -->|"否"| G

    N1["平台不提供报告审核；报告上传成功即发布。"]:::note
    N2["作废不恢复旧版本；发起方不获取已作废报告详情。"]:::note
    D -.-> N1
    G -.-> N2
```

**《报告生命周期子流程》说明：**

1. 报告上传成功即发布，并形成当前有效报告。
2. 当前有效报告作废后，当前无有效报告；作废不恢复历史旧版本。
3. 作废后可再次上传，成功后生成新的报告版本。
4. 主流程只展示“报告上传成功后当前有效报告发布”，作废和再次上传只在本子流程展开。

## 推送与平台消息边界图

> 本图展开各业务触发点后的通知处理。推送处理不改变主业务状态；推送接收 URL 缺失、配置不可用或查询失败时，回到主流程的结果仍为“主业务成功”。

```mermaid
flowchart TD
    classDef trigger fill:#f3e5f5,stroke:#7b1fa2,stroke-width:1px
    classDef process fill:#e8f5e9,stroke:#2e7d32,stroke-width:1px
    classDef decision fill:#fff8e1,stroke:#f57f17,stroke-width:2px
    classDef terminal fill:#ffebee,stroke:#c62828,stroke-width:2px
    classDef external fill:#e0f7fa,stroke:#00838f,stroke-width:1px
    classDef note fill:#eeeeee,stroke:#616161,stroke-width:1px

    T["业务触发点<br>报告发布/作废、条码审核通过/不通过<br>条码终止、样本无法继续检测"]:::trigger

    T --> P0["进入推送处理<br>组装候选通知内容"]:::process
    P0 --> P1["按组织编码+发起医院编码+发起院区编码+推送业务 key<br>查询外部配置系统"]:::external
    P1 --> P2{"取得推送接收 URL？"}:::decision
    P2 -->|"否：未配置/不可用/查询失败"| P3["不提交推送系统<br>向当前操作方返回非阻断提示"]:::terminal
    P2 -->|"是"| P4["向推送系统提交推送任务<br>包含业务通知内容和 URL"]:::external
    P4 --> P5["推送系统负责投递、重试、失败记录、补发、监控和回执"]:::external

    T --> M0["平台消息"]:::process
    M0 --> M1["按消息规则生成平台消息<br>支持列表、已读/未读和跳转"]:::process

    P3 --> R["回到主流程结果：主业务成功<br>推送未触发"]:::note
    P4 --> R2["回到主流程结果：主业务成功<br>推送任务已提交"]:::note
    M1 --> R3["平台消息不替代外部推送<br>不建设待办中心"]:::note
```

**《推送与平台消息边界图》说明：**

1. 当前版本外部推送类型包括：报告发布、报告作废、条码审核通过、条码审核不通过、条码终止、样本无法继续检测六类。
2. 当前版本外部推送对象仅为发起方侧外部接入系统，接收方不是外部推送对象。
3. 协同平台不维护推送接收 URL，不提供推送接收 URL 配置页面、缺失处理页面、启停管理、历史或回滚能力。
4. 推送接收 URL 由外部配置系统维护；协同平台只按业务 key 查询 URL。
5. 未取得推送接收 URL 时，不向推送系统提交该次推送任务，不影响主业务成功，只向当前操作方返回或展示非阻断提示。
6. 平台消息用于平台内提醒、查看和跳转，不承担外部系统集成职责，也不建设待办中心。

```mermaid
    M2{"平台标准项目是否当前有效？"}:::decision
    M3["不允许新增/修改/启用为有效对照"]:::terminal
    M4["保存院区项目对照<br>医院+院区+院区项目编码"]:::process

    S1 --> M2
    M1 --> M2
    M2 -->|"否/无法确认"| M3
    M2 -->|"是"| M4

    A1["创建申请<br>提交院区项目编码/名称"]:::external
    A2{"按发起医院+发起院区+院区项目编码<br>匹配可用于创建的对照？"}:::decision
    A3["回到创建校验：创建整体失败"]:::terminal
    A4["保存条码项目快照<br>发起院区项目+平台标准项目"]:::process
    A5["回到创建校验：创建继续"]:::process

    A1 --> A2
    M4 --> A2
    A2 -->|"否"| A3
    A2 -->|"是"| A4 --> A5

    R1["接收方侧查询样本/包/条码详情"]:::external
    R2{"按接收医院+接收院区+平台标准项目编码<br>反向匹配当前启用对照？"}:::decision
    R3["返回接收院区项目编码/名称<br>接收方项目对照状态=已匹配"]:::process
    R4["编码/名称为空<br>接收方项目对照状态=未匹配"]:::process
    R5["未匹配不阻断查询、接收、异常处理、检测开始或报告上传"]:::note

    A4 --> R1 --> R2
    R2 -->|"是"| R3
    R2 -->|"否"| R4 -.-> R5
```

**《院区项目对照与项目识别规则边界图》说明：**

1. 协同平台维护院区项目对照；平台标准项目目录由标准项目目录管理系统维护。
2. 创建申请接口不接收平台标准项目编码；平台按发起医院、发起院区和院区项目编码匹配可用于创建申请的院区项目对照。
3. 匹配失败回到创建校验的“创建整体失败”；匹配成功回到“创建继续”。
4. 接收方侧查询时，平台按接收医院、接收院区和平台标准项目编码反向匹配接收院区项目编码和名称。
5. 未匹配不阻断样本查询、样本接收、异常处理、检测开始回传或报告上传。
