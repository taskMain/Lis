# 报告全流程梳理

> 基于《检验中心协同平台需求文档》第五版修订稿2（已合并"上传"与"重传"概念）
>
> 日期：2026-05-29

---

## 一、核心原则（先记住这三条）

1. **平台不出报告** —— 报告内容由接收方（检验中心/实验室）生成，通过接口上传给平台。
2. **平台只做发布控制** —— 平台管理报告版本的可见性、有效性、审核流程，不参与报告内容生成或医学判断。
3. **上传是唯一动作** —— 外部系统只有一种方式提交报告：调用"上传报告"接口。首次上传生成 v1，再次上传生成 v2/v3...平台自动管理版本链。

---

## 二、报告生命周期总流程

### 阶段一：前置条件

报告上传之前，必须同时满足以下条件：

| 条件 | 说明 |
|------|------|
| 申请有效 | 申请状态不能是"已终止" |
| 样本已接收 | 当前流转轮次样本主状态为"已接收"或"检测中"或"检测完成" |
| 无阻断异常 | 不存在待处理的阻断性异常记录 |
| 上传方匹配 | 上传方必须是该申请对应的接收方机构或其授权系统 |
| 当前流转轮次 | 只能对当前流转轮次上传报告，历史轮次不允许 |

> 如果样本还在"待送出"或"已送出"状态，平台拒绝上传，不自动补记接收记录。

---

### 阶段二：上传报告（外部系统调用接口）

**接口**：`上传报告`（平台对外接口）

**调用方**：接收方的 LIS 系统或中间件系统

**提交内容**：

| 内容 | 是否必填 | 说明 |
|------|---------|------|
| 报告 PDF | **必填** | 未提交则上传失败 |
| 结构化检验结果 | 可选 | 有就保存展示，没有不影响版本生成 |
| 危急值信息 | 可选 | 有就随报告记录，发布后才对外推送 |
| 上传说明 | 有条件必填 | 申请下已有已发布报告或非终止原因已作废版本时，必填 |

**平台处理**：

```
上传请求到达
    ↓
前置校验全部通过？
    ├── 否 → 返回错误，不生成版本号，不推动样本状态
    ↓
    是
    ↓
生成报告版本号（v1 / v2 / v3...）
    ↓
当前流转轮次样本主状态 → 检测完成
    ↓
如含危急值 → 记录危急值（但不对外推送，等发布）
    ↓
按审核开关分流
```

---

### 阶段三：审核开关分流

平台有一个全局的"报告审核开关"（由外部配置系统管理）：

```
┌─────────────────┐
│  审核开关启用？  │
└────────┬────────┘
         │
    ┌────┴────┐
   是        否
    ↓         ↓
 待审核    自动已发布
    ↓         ↓
人工审核   触发推送
    ↓         ↓
通过/不通过  业务流程完成
```

| 审核开关状态 | 报告上传后的状态 | 后续动作 |
|-------------|-----------------|---------|
| **启用**（默认） | 待审核 | 接收方管理人员需在平台页面逐份审核 |
| **未启用** | 自动已发布 | 直接对发起机构可见，触发推送 |

> 审核开关从"启用"切到"未启用"，只影响**切换后新上传**的报告。切换前已经在"待审核"的报告，仍需人工审核。

---

### 阶段四：人工审核（审核开关启用时）

**操作入口**：平台页面 → 发布审核页签

**操作人**：接收方管理人员

**审核页面可查看**：
- 报告 PDF
- 关联的申请、样本、患者摘要、项目清单
- 上传方、上传时间
- 历史版本信息

**审核结果**：

| 结果 | 报告状态变化 | 后续可执行动作 |
|------|-------------|---------------|
| **审核通过** | 待审核 → 已发布 | 报告对发起机构可见，触发推送 |
| **审核不通过** | 待审核 → 审核不通过 | 外部系统可再次上传生成新版本；原版本保留历史，不可发布/查询/下载/推送 |

> 平台**不支持批量审核**、不支持反审核、不支持修改报告内容。

---

### 阶段五：发布后（报告已发布）

报告进入"已发布"状态后：

- 发起机构用户可在平台页面查询、查看、下载当前有效报告
- 触发"报告发布推送"通知发起机构
- 如含危急值，触发"危急值发布推送"

---

## 三、报告版本状态机

报告有 7 种状态：

```
┌──────────┐
│  待审核   │ ← 上传成功（审核开关启用）
└────┬─────┘
     │ 审核通过
     ↓
┌──────────┐     再次上传新版本     ┌──────────┐
│  已发布   │ ────────────────────→ │  已替代   │
└────┬─────┘  （原版本被替代）       └──────────┘
     │
     │ 作废
     ↓
┌──────────┐
│  已作废   │
└──────────┘
```

### 完整状态定义

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| **待审核** | 等待人工审核 | 审核开关启用时，上传成功 |
| **审核不通过** | 审核未通过，不可对外 | 人工审核选择"不通过" |
| **已废弃** | 被新版本替代的中间版本 | 待审核/审核不通过版本被再次上传的新版本替代 |
| **已失效** | 因终止申请退出处理范围 | 终止申请时，未发布的待审核/审核不通过版本 |
| **已发布** | 当前有效报告，对外可见 | 审核通过，或审核开关未启用时自动发布 |
| **已替代** | 原有效报告被新版本替代 | 新版本已发布后，原已发布版本 |
| **已作废** | 被人工作废，不再对外 | 接收方管理人员或平台运营人员发起作废 |

### 状态流转规则

```
上传
  → 待审核（审核开关启用）
  → 已发布（审核开关未启用）

待审核 ──审核通过──→ 已发布
待审核 ──审核不通过──→ 审核不通过

已发布 ──再次上传──→ [新版本待审核或已发布]，旧版本 → 已替代
已发布 ──作废──────→ 已作废

审核不通过 ──再次上传──→ 新版本生成，原版本 → 已废弃

任何未发布版本 ──终止申请──→ 已失效
当前有效报告 ──终止申请──────→ 已作废（联动）
```

> **已作废和已失效的区别**：已作废用于曾经发布过的版本；已失效用于从未发布过的版本（待审核、审核不通过）。

## 四、已发布报告出问题了怎么办？

| 场景 | 处理方式 | 操作人 |
|------|---------|--------|
| 报告内容有误 | 外部系统**再次上传**生成新版本替代 | 接收方/上传方系统 |
| 报告不应继续对外（如业务取消） | 在平台页面**作废**当前有效报告 | 接收方管理人员 |
| 平台发现风险需兜底 | 在平台页面**作废**当前有效报告 | 平台运营人员 |
| 审核不通过 | 外部系统**再次上传**生成新版本 | 接收方/上传方系统 |

### 再次上传 vs 作废 的对比

| | 再次上传（生成新版本） | 作废 |
|---|----------------------|------|
| **操作方** | 外部系统调用接口 | 平台页面人工操作 |
| **结果** | 新版本成为当前有效报告，旧版本→已替代 | 当前有效报告→已作废，申请暂无有效报告 |
| **后续** | 可继续上传新版本 | 非终止原因作废后可再次上传生成新版本；终止联动作废后不可再上传 |
| **样本状态** | 不变（仍为检测完成） | 不变（仍为检测完成） |

> **重要**：作废后**不自动恢复**历史版本。如需重新对外提供报告，必须再次上传生成新版本。

---

## 五、终止申请对报告的影响

```
终止申请生效
    ↓
当前有效报告 → 已作废（联动作废，原因=终止申请）
    ↓
未发布报告（待审核/审核不通过）→ 已失效
    ↓
已替代/已废弃/已作废历史版本 → 不受影响
    ↓
之后不允许继续上传报告
    ↓
如需继续检测 → 必须重新提交新申请
```

## 六、危急值与报告的关系

危急值**不独立存在**，它随报告版本一起上传：

```
报告上传（含危急值信息）
    ↓
报告未发布 → 危急值不对外推送
    ↓
报告发布 → 危急值进入当前有效范围，触发危急值发布推送
    ↓
报告被新版本替代 → 旧版本危急值退出当前有效范围，触发危急值失效通知
    ↓
报告被作废 → 关联危急值退出当前有效范围，触发危急值失效通知
```

> 平台不自动判断危急值，危急值是否存在、具体值、危急等级全部由上传方提供。

## 七、功能清单：平台页面 vs 对外接口

### 平台对外接口（外部系统调用）

| 接口 | 谁调用 | 功能 |
|------|--------|------|
| **上传报告** | 接收方/上传方（LIS/中间件） | 提交报告 PDF、可选结构化结果、可选危急值 |
| 回传检测开始 | 接收方 LIS（可选） | 通知平台样本进入检测中（非必须，可直接跳到检测完成） |

> 只有这两个接口与报告直接相关。**报告审核、报告作废不提供对外接口。**

### 平台页面功能（用户在浏览器操作）

| 功能 | 操作角色 | 功能说明 |
|------|---------|---------|
| **报告审核** | 接收方管理人员 | 逐份打开待审核报告，选择通过/不通过 |
| **报告作废** | 接收方管理人员、平台运营人员 | 对当前有效报告发起作废 |
| **报告查询/下载** | 发起机构用户 | 查看和下载当前有效报告 PDF |
| **版本追溯** | 接收方管理人员、平台运营人员 | 查看全部历史版本、替代关系、作废记录、审核记录 |
| **发布审核页签** | 接收方管理人员 | 查看待审核报告列表 |
| **危急值处理** | 有权限的接收方用户 | 查看危急值、标记处理状态（待处理→已处理） |

> 平台页面**不提供**：上传报告、出具报告、修改报告内容、批量审核、反审核、删除报告。

## 八、各角色在报告流程中的职责

| 角色 | 报告相关职责 |
|------|-------------|
| **外部系统（接收方 LIS/中间件）** | 生成报告 → 调用"上传报告"接口提交；审核不通过时再次上传 |
| **接收方管理人员** | 在平台页面审核待发布报告；必要时作废当前有效报告 |
| **接收方检验人员** | 处理危急值（平台内部闭环标记） |
| **发起机构用户** | 在平台页面查询、下载当前有效报告 |
| **平台运营人员** | 发现风险时兜底作废报告；查看版本追溯 |

## 九、常见疑问 FAQ

**Q1：报告上传失败会怎样？**
> 不生成版本号，不推动样本进入检测完成，返回错误原因给上传方。

**Q2：审核不通过后，原版本还能恢复吗？**
> 不能。审核不通过的版本保留历史记录，但不可发布/查询/下载/推送。外部系统需再次上传生成新版本。

**Q3：已发布报告发现错误，能修改吗？**
> 不能直接修改。两种方式：1）外部系统再次上传生成新版本替代；2）作废后重新上传。

**Q4：作废后能恢复吗？**
> 不能。作废后已作废版本不恢复有效。如需重新对外提供报告，必须再次上传生成新版本。

**Q5：终止申请后还能上传报告吗？**
> 不能。终止申请后不允许继续上传报告。如需继续检测，必须重新提交新申请。

**Q6：一个申请能有多个报告吗？**
> 一个申请只有一个报告业务对象，但可以有多个历史版本。任何时候最多只有一份当前有效报告。

**Q7：平台能基于 PDF 内容判断报告是否完整吗？**
> 不能。平台不解析 PDF 内容，不做项目级完成判断、漏报判断、重复覆盖判断。

**Q8：危急值怎么处理？**
> 危急值随报告版本上传，有效性跟随报告版本。报告发布→危急值可推送；报告替代/作废→危急值失效。危急值处理是平台内部轻量闭环（标记为已处理），不等同于医院侧已处理。

## 十、流程图速查（极简版）

```
样本已接收 + 申请有效 + 无阻断异常
    ↓
外部系统上传报告（PDF）
    ↓
生成版本号 → 样本状态=检测完成
    ↓
审核开关？
    ├── 启用 ──→ 待审核 ──→ 人工审核 ──→ 通过→已发布 / 不通过→审核不通过
    └── 禁用 ──→ 自动已发布
                      ↓
              发起机构可见 + 推送通知
```

```
已发布报告出问题的处理：
    ├── 内容错误 ──→ 外部系统再次上传（新版本替代）
    ├── 不应继续对外 ──→ 平台页面作废
    └── 审核不通过 ──→ 外部系统再次上传（新版本替代）
```
