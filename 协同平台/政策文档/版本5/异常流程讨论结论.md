> 说明：本文档记录对 PRD_第五版修订稿 中异常流程的逐一核对结论和修改方案。本文档为增量讨论记录，不覆盖源文档。

## 一、全局共识

### 1.1 样本主状态与异常状态职责分离

- **样本主状态**：只走正常流转主链（待送出 → 已送出 → 已接收 → 检测中 → 检测完成），不感知异常。
- **异常记录**：承载一切"不对劲"的情况——异常类型、处理状态（待处理/处理中/已关闭）、处理结果（继续检测/退回样本/终止处理/关闭异常）。阻断检测、驱动后续决策全部由异常记录负责。
- 样本主状态不新增异常相关状态，保持两边职责清晰。

### 1.2 送出记录即物流清单

- **送出记录**就是平台的物流凭证：记录了"谁、什么时候、把哪些样本、送往哪里"。
- 接收方以送出记录为核对依据，打开一条送出记录，看到待接收样本列表，逐项核对。
- 不需要单独创建"物流单"实体。
- **待办**：送出记录查询相关页面功能（接收方待接收清单等）后续专门讨论。

### 1.3 异常不终止申请

- 接收环节的异常（破损、漏送、条码不清等）不导致申请终止。
- 申请保持有效，机构可重新采样、重新送出，继续完成剩余流程。

## 二、接收异常流程 — 三分类模型

接收方核对送出记录中的样本清单，对每个样本给出处置结果：

| 接收结果 | 样本主状态变化 | 异常记录 | 适用场景 |
|----------|---------------|----------|----------|
| **正常接收** | 已送出 → 已接收 | 无 | 实物符合，确认接收 |
| **异常接收** | 已送出 → 已接收 | 有，未关闭则阻断检测 | 破损、条码不清、样本不符、容器问题等**实物存在但有问题** |
| **未到货** | **停留在已送出** | 有，标记为未到货 | 漏送：送出记录有但实物没有 |

### 2.1 正常接收

- 样本进入已接收，允许进入检测流程。
- 无异常记录。

### 2.2 异常接收

- 样本进入已接收，同时生成异常记录。
- 异常记录未关闭时，**阻断检测流程**（默认不允许进入检测中或检测完成）。
- 异常处理结果决定后续：
  - **继续检测**：允许样本继续进入检测流程。
  - **退回样本 + 终止处理**：样本终止流转，机构需重新采样并用新条码创建新申请。
- 异常记录内容包含：异常类型（破损/条码不清/样本不符/容器问题等）、异常描述、发现时间、处理状态、处理结果、处理意见。

### 2.3 未到货

- 样本**不进入已接收**，停留在"已送出"状态。
- 生成异常记录，标记为"未到货"。
- 语义正确：送方说送了且生成送出记录，接收方说没收到，交接未完成，样本卡在"已送出"。
- 后续处理：
  - 送方和接收方线下确认。
  - 如确已送出但丢失：走补送（1.4.8）或机构重新采样+新申请。
  - 如送方未实际送出：走送出撤回（1.4.7），样本回到待送出后重新送出。

## 三、与其他流程的联动

### 3.1 异常记录与检测阻断

- 异常接收的样本：异常记录状态为"待处理"或"处理中"时，默认不允许进入检测中或检测完成。
- 异常处理结果为"继续检测"或异常已关闭且未标记终止处理时，解除阻断。
- 处理结果为"退回样本"或"终止处理"时，永久阻断，不允许继续检测。

### 3.2 异常退回 ≠ 申请终止

- 本文讨论确认：接收异常不影响申请有效性。
- 申请终止是独立流程，由发起机构主动发起或异常处理结果"终止处理"联动触发。

### 3.3 申请终止 → 报告处置规则

结论：**系统自动执行，不依赖人工操作。**

| 报告状态 | 终止时的处置 | 说明 |
|----------|-------------|------|
| 已发布（当前有效） | 自动标记为 **已作废** | 作废原因记录为"申请终止"，触发来源标记为"申请终止联动"，与人工作废共用同一状态。不再对外查询、下载、推送。 |
| 待审核 | 自动标记为 **因申请终止失效** | 退出待处理范围，不再允许审核、发布、查询、下载或推送。 |
| 审核不通过 | 自动标记为 **因申请终止失效** | 退出待处理范围。 |
| 已替代 / 已重传作废 / 已作废 | 不再处理 | 已是历史版本，保持原状态。 |

关键规则：
- 申请终止生效后，关联报告处置**立即自动执行**，不留人工操作窗口。
- 已作废报告的作废原因分类中新增"申请终止"。
- 报告作废后不自动回退历史版本，该样本条码暂无当前有效报告。
- 如需重新对外提供报告，上传方必须重传生成新版本（与新申请配合使用）。

### 3.4 报告作废后的查询显示

结论：**区分场景文案**，不展示历史版本，不改变页面权限模型。

| 场景 | 报告查询页面显示 |
|------|-----------------|
| 从未上传过报告 | "暂无报告" |
| 普通作废（上传方/平台人员操作） | "暂无当前有效报告" |
| 申请终止导致报告作废 | "申请已终止，报告已作废" + 可展开查看作废原因和终止原因摘要 |
| 有当前有效报告 | 正常展示报告 |

规则：
- 历史报告的查看跳转到版本追溯入口，不在普通查询页面展示。
- 申请终止场景的文案让用户清楚"为什么会这样"即可，不需要展示历史报告缩略信息。
- 报告下载权限不受影响——已作废报告一律不可下载。### 3.5 异常处理记录追加规则

结论：**追加记录与首次处理记录字段要求不同。**

| | 首次处理记录 | 追加记录 |
|------|------|------|
| 处理结果 | **必填** | 不可选（沿用原处理结果） |
| 处理说明 | 可选 | **必填** |
| 处理人 | 必填 | 必填 |
| 处理时间 | 必填 | 必填 |

规则：
- 追加记录不改变原始处理结果，仅用于补充说明。
- 追加记录不可修改、不可删除。
- 样本异常处理（1.6）和危急值处理（1.10）统一适用此规则。
