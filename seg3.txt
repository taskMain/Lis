## 约束



1. 平台只接收上线后新产生并审核完成的检查、检验报告，不导入上线前历史报告。

2. 一份报告首次创建或追加后续完整版本时，均完整保存来源报告明细；只有当前组织内互认配置启用，且标准项目、所属分组和所属分类均启用的项目编码明细参与新的互认匹配。未提供编码，或明确提供但不存在、超出组织范围、停用或标准目录不可用的编码不阻止报告接收，但对应明细不参与互认。

3. 报告接收不按可互认时间筛选，但参与互认的项目必须同时满足互认配置、标准项目、所属分组和所属分类均启用；任一对象停用时只阻止新的匹配查询形成匹配项，不否定已经形成的匹配记录后续按 F05 保存真实处理事实的规则。

4. 跨院患者以证件类型和证件号码精确关联，并使用姓名、性别代码和出生日期进行一致性校验。平台不使用姓名相似度、电话或院内就诊卡进行替代匹配。

5. 报告上传、互认处理和引用结果涉及的医院业务科室和人员，由医院侧直接提供具体 ID 和名称；ID 使用 String，不要求对应主体存在于平台权限体系。

6. 必填的科室或人员字段必须同时提供 ID 和名称；可选字段的 ID 和名称必须同时有值或同时为空，不允许只提供其中一项。

7. 平台直接保存请求提供的具体 ID 和名称，不根据 ID 补查或覆盖名称。医院业务科室和人员 ID 在院区范围内唯一，同一 ID 在不同院区可以代表不同主体。

8. 每次完整报告提交或作废请求只处理一份报告。完整报告提交以一个请求同时提供完整结构化报告及 PDF，二者共同成功或共同失败；作废只提交来源报告单号、作废时间和作废原因。

9. 报告按可信调用身份中的组织、医院、院区、所调用报告类型能力和医院提供的报告单号唯一识别。医院不提交平台报告 ID 或组合报告业务标识，平台不使用患者、项目、报告内容或 PDF 判断报告身份。

10. 平台只按报告业务标识和生命周期状态处理完整提交，不比较完整内容或文件摘要，也不依据源端报告修改时间判断重传、版本顺序或内容是否变化。报告不存在时创建首个版本；报告存在且未作废时，每次成功完整提交均追加新版本，最后成功保存的版本为当前版本；报告已经作废时拒绝继续提交完整版本。

11. 后续完整版本形成后，原版本停止参与匹配查询、引用详情和新的引用；报告作废不形成内容版本且不物理删除，作废后不再返回为匹配或新的引用内容。

12. 每个互认项目只返回查询时点前、当前可互认时间内检查或检验时间最晚的一份有效报告；检查或检验时间相同时，优先选择报告时间较晚的一份；两者均相同时，在匹配数据及相关配置未变化的情况下稳定返回同一份报告。

13. 一份联合报告命中多个互认项目时，按一份完整报告分组返回；互认匹配、处理决定和引用事实仍按具体互认项目分别形成。

14. 每次非空匹配查询生成新的互认匹配记录 ID 和互认匹配项 ID；重试按新查询处理，不使用查询流水号、稳定匹配引用或幂等键恢复旧组。

15. 匹配查询、匹配返回、结构化内容展示、PDF 查看、影像入口访问和引用详情获取均不自动形成采纳或引用事实。

16. 互认处理结果必须来自医生明确反馈的采纳或不采纳，并完整覆盖互认匹配记录全部项目；首次保存后不得更正、撤销或删除。引用结果必须来自医院 HIS 已经成功写入本次病历的正向事实。平台不根据未反馈状态推断拒绝、忽略、采纳或引用。

17. 不采纳必须使用平台统一原因代码；选择其他原因时必须提供补充说明。各医院不得自行扩展或修改原因代码。

18. 预计节省金额在采纳处理结果成功保存时按接收组织、接收医院、接收院区的当前互认项目金额形成，不使用来源医院金额，不采集数量，不模拟按次、按部位、组合收费、医保结算或患者实际退费。

19. 提醒、采纳、不采纳、引用和预计节省金额分别使用已确认的业务时间归入统计期间，接口接收时间不得替代业务时间。

20. 医院管理员只能查看本院及有权院区的数据，平台管理员按授权查看组织范围内数据。MVP 不实现统计与导出场景的患者脱敏，统计页面和导出中的患者姓名、证件号码按业务原值展示。

21. 本院报告匹配由全局开关控制；开启后使用全局本院报告排除时长。两个参数均不设默认值。参数调整只影响后续查询，不倒改已有报告、互认处理、引用和统计事实。

22. 引用详情调用受全平台统一的引用详情有效时长控制，该参数不设默认值；该限制只控制重新获取引用详情，不控制医院已经合法取得并保存的数据、PDF 下载或引用结果提交。
