# Frontend Style

本文约束 MedicalRecognition React / TypeScript 日常实现。应用结构见 [Frontend Application](frontend-application.md)，API 契约见 [Frontend API Client](frontend-api-client.md)，测试见 [Testing Baseline](testing-baseline.md) 和 [Frontend Testing](frontend-testing.md)。

## 1. 强制规则

1. 使用当前 React、TypeScript、Ant Design 和构建配置支持的现代、类型安全写法，并与周围代码保持一致。
2. 不使用 `any`、双重断言、非空断言或伪造默认值掩盖契约问题；确有必要时限制范围并说明原因。
3. 生成模型在适配层转换为稳定视图模型，不把 Kiota 可空、序列化和内部类型扩散到 JSX 或公共组件 props。
4. 不夹带无关重构、格式化或视觉改版；只整理本轮触及且与目标直接相关的代码。
5. 复杂交互、适配和公共导出补充有业务价值的中文注释。

## 2. TypeScript 与实现

- 优先 `const`、解构、可选链、空值合并和清晰数组方法；不为语法短小牺牲可读性。
- `useMemo` / `useCallback` 只用于真实计算成本或稳定引用需求，不机械包裹。
- 复杂判断使用具名变量或函数，JSX 只保留可读展示和交互结构。
- 明确区分字段缺失、`undefined`、`null`、空字符串、空数组、未修改和主动清空。
- 同一枚举、状态文案和字段映射集中定义，不在多个组件复制魔法数字或中文。
- 异步操作具备 loading、禁用、防重复、失败恢复和最终状态处理。

## 3. 组件与状态

- 页面负责业务编排；业务组件负责独立区域；通用组件不包含具体业务、权限或组织规则。
- 状态贴近使用位置；跨区域共享稳定依赖时才提升或使用 Context。
- 同一事实只有一个权威状态源；筛选、分页、选择、详情和弹窗有明确重置规则。
- 不创建巨型万能组件，也不为一两行透传创建无语义包装层或 hook。
- 新增、编辑和更新等提交操作优先使用 `Modal`；`Drawer` 主要用于详情和只读辅助信息。
- Ant Design 6 的 Drawer 宽度使用数字型 `size`，不得继续使用已废弃 `width`。

## 4. 注释

以下内容应有中文注释：公开组件、hooks、Context、工具函数、关键类型、复杂适配、权限判断和路由业务边界。

实现内注释解释“为什么”和不可见约束，例如请求竞态、分页选择保留、表单联动、宿主兼容和不能简化的边界。不要逐行复述代码，不给简单 JSX、普通 `useState` 或显而易见赋值添加空注释。

## 5. UI 自检

- loading、空态、禁用、提交中和失败恢复是否完整。
- 表单必填、空白、长度、枚举、范围和条件必填是否与后端一致。
- Modal/Drawer 是否验证打开、取消、右上角关闭、遮罩恢复、焦点恢复和再次打开。
- 提交按钮是否绑定真实 loading 并防止重复请求。
- 文本、按钮、表格和弹窗是否在常用桌面视口溢出或遮挡。
- API 失败是否只恢复页面状态，并由宿主统一展示错误。
- 是否存在调试文本、console 输出、临时按钮、敏感信息或无关视觉漂移。
