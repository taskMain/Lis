# Testing

本文规定跨端联调、宿主页面验收和阶段测试报告。环境唯一来源是 [Test Environment](test-environment.md)，共同验证纪律见 [Testing Baseline](testing-baseline.md)，阶段文件组成见 [Planning And Evidence](planning-and-evidence.md)。

## 1. 强制闸门

1. 页面能力从真实宿主登录页和菜单进入，在同一链路核对页面、DOM、Console、Network、响应及最终业务状态。
2. 直接 HTTP、Scalar、本地直达子应用、隔离的前端自动化或后端测试不能替代真实宿主验收；控制工具的选择不改变该边界。
3. 使用实时环境和本轮证据，不沿用历史账号上下文、端口、PID、数据余量或外部服务健康状态。
4. 测试前盘点数据，不足时按允许方式准备；无法准备则记录 `Blocked` 或 `NotRun`，不把空列表或禁用按钮判为通过。
5. 阶段测试结果更新在阶段根 `testReport.md`，不在实现计划中代写验收结果。
6. App Goal 不是测试必选项，创建条件见 [Repository Safety](repository-safety.md#4-app-goal)。

## 2. 测试层级

| 验证面 | 能证明 | 不能替代 |
|---|---|---|
| 后端单元、领域、仓储和契约测试 | 对应后端行为 | 页面可用性 |
| API Client、前端 test/lint/build | 客户端自动化及静态结果 | 实际宿主集成 |
| Scalar / 直接 HTTP | 接口结果和受控数据准备 | 宿主页面操作 |
| 本地子应用直达 | 本地排查结果 | 宿主菜单与认证 |
| 宿主浏览器验收 | 已覆盖的真实集成链路 | 未执行的其他矩阵 |

按钮应验证弹层、校验、请求、响应、刷新和业务状态，不只检查可见或点击未报错。

## 3. 启动检查

1. 按任务读取相关阶段设计、实施、矩阵和已有报告，明确范围、分母、排除项、数据与停止条件，不读取无关端的文档。
2. 记录提交及工作区边界；代码测试按 GitNexus 规范核对索引，纯文档任务无需建立索引。
3. 按环境规范核对本轮登录主体、可信组织范围、浏览器或会话、权限、宿主菜单、本地资源来源。
4. 核对本阶段实际依赖的后端、前端、宿主、控制工具及外部服务；使用 CDP、测试辅助服务或公网接收链路时才核对这些设施。
5. 盘点正常、失败、状态变化、分页、空页回退及复测所需数据。
6. 缺少必要配置时只暂停相关矩阵，继续不依赖该配置的工作；可自行恢复时先恢复，超出授权或触发停止条件时再请求负责人。

## 4. 服务与进程

- 启动命令按 [Project Context](project-context.md) 中登记的真实工程配置执行；未创建工程时不虚构命令。
- 记录本轮启动进程的 PID、命令、工作目录、端口和日志。
- 端口占用先核对归属，不复用来源不明的进程，不关闭其他项目服务。
- 阶段需要本地测试辅助服务时，由执行者按授权启动、检查和关闭；公网穿透及外部服务只验证，不自行操作账号、客户端或配置。
- 结束时关闭本轮进程并核对结果；负责人要求保留时记录对象、原因和风险。具体安全边界见 Repository Safety。

## 5. 测试数据

1. 为核心用例记录前提状态、关键业务标识、现有数量及准备方式。
2. 按业务顺序准备上游状态，为失败、回退和复测保留数据。
3. 历史、已完成或作废数据只用于对应允许的业务路径。
4. 页面能够产生的数据优先通过宿主页面准备；外部系统职责且无页面入口时，按确认的接口准备。
5. 接口造数记录非敏感身份来源、组织范围、关键编号和结果，不替代被测页面操作。
6. 原则上不直接改库；确需写库先确认范围和风险。数据库行为验收必须经真实后端链路取证。

## 6. 平台错误与测试修复

平台错误边界以 [Frontend API Client](frontend-api-client.md#5-平台错误边界) 为准。失败测试记录原始状态、宿主反馈和页面恢复，不在子应用增加绕过框架的提示或兼容层。

不沿用其他项目的验收排除决定。网络失败、外部故障等验证范围由本项目阶段设计和风险确定，不默认逐页面重复故障注入，也不默认豁免共享错误路径。

一轮尽可能执行全部适用矩阵，普通问题集中记录后按根因和风险归批。流程完全阻断、公共契约整体不可用、无法产生下游数据或存在数据安全风险时提前中断。修复遵循 Testing Baseline，复用证据必须区分沿用、失效和重新执行项，不描述成一次新的完整干净轮次。

## 7. 测试报告

阶段根 `testReport.md` 至少包含：

1. 阶段、时间、轮次、矩阵版本、分母和执行会话。
2. 起始提交与工作区归属、适用的 GitNexus 状态。
3. 实际使用的进程、地址、命令、日志及收尾结果。
4. 实际非敏感账号标识、组织范围、菜单、浏览器及版本、Profile 或会话、控制工具和资源来源。
5. 数据准备、历史证据、静态证据与本轮运行证据的区分。
6. 实际验证命令、结果、页面与接口证据、最终业务状态。
7. 用例结果按 `NotRun / Passed / Failed / Blocked / PendingRetest / N/A` 统计；决策与责任标签单列。
8. 问题、负责人或责任边界、复测项、未覆盖面、残余风险及下一步。

真实运行后及时更新结果，阶段完成时再同步实施状态与总体计划。无运行证据不得用空白模板、计划或源码分析推导业务完成。

## 8. 文档一致性

通用流程只在本文维护；环境只在环境规范维护；阶段仅维护实际范围、矩阵、排除项与证据。不复制其他项目账号、token、端口、历史轮次或业务阶段内容。最终核对设计、实施和证据一致，不提前勾选或沿用过时状态。
