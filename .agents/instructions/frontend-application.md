# Frontend Application

本文约束 MedicalRecognition React 微前端的路由、可信上下文、页面、状态和交互边界。编码风格见 [Frontend Style](frontend-style.md)，API 边界见 [Frontend API Client](frontend-api-client.md)。

## 1. 分层

- 路由层只声明路由、懒加载、布局和页面入口，不发业务请求或转换字段。
- 页面读取路由和可信上下文，编排流程、加载数据并组合业务组件。
- 功能模块 `api.ts` 负责调用生成 Client、转换请求响应并返回稳定类型。
- 展示组件通过 props 接收视图模型，不直接理解 Kiota 模型。
- hooks 只抽取可复用状态流程或副作用；Context 只承载跨层稳定依赖和可信上下文。

## 2. 路由、菜单与权限

1. 路由与宿主菜单、页面用途、basename、权限和数据范围一致。
2. 管理员、院区可操作和只读入口使用明确路由；不通过隐藏按钮模拟不同权限页面。
3. 只读页面在 DOM、组件依赖和 Network 三个层面均不得具备写能力。
4. 前端可见性不能替代权限系统的菜单和接口授权；本项目不另建角色授权模型，后端仍校验可信组织归属和资源范围。宿主菜单缺失时按测试规范处理，不用本地直达宣告通过。
5. 新增或修改路由时在相邻位置注明页面用途、适用用户和数据范围。

## 3. 可信上下文

- 当前登录主体及其组织、医院、院区、科室和角色上下文只来自 MicroSDK、登录管理器或可信 Context；不要求本项目每个业务请求都具备科室上下文。
- 医院业务请求中的科室和人员 ID/名称是业务字段，不等于登录身份；按本项目 SRS/UML/CONTEXT 接收和保存，不从权限系统补查名称，也不把这些字段提升为可信调用范围。
- 不从 URL、Storage、表单、列表或缓存构造可信范围。
- current API 不提交当前医院/院区作为服务端可信范围；管理员维护对象和普通业务筛选必须明确区分。
- 上下文缺失时进入不可操作状态，不退化为全局查询或硬编码默认组织。
- 身份、组织、路由或业务视角变化时取消旧请求，并清理选择、缓存、详情和弹窗状态。
- token、密码、患者隐私和敏感配置不得进入 URL、Console、快照或业务缓存。

## 4. 状态和请求

- `useEffect` 依赖完整，不关闭 lint 来掩盖闭包、竞态或重复请求。
- 使用取消信号、请求序号或既有机制防止旧响应覆盖新筛选、新组织或新路由。
- 查询条件变化按设计复位分页；分页、排序、选择和详情有明确保留/清空策略。
- 公共元数据集中加载和缓存，不由多个组件重复请求。
- 提交防重复；失败后结束 loading、保留必要输入和弹窗，不误刷新、不误关闭、不提前更新业务状态。
- 查询失败不使用失败结果覆盖已有有效数据；必要时进入不可操作状态。

## 5. 列表、表单和弹层

- 表格 `rowKey` 稳定唯一，不使用数组索引。
- 面向用户的大列表使用后端分页，不一次拉取全部数据模拟分页。
- 跨页选择必须提供可见摘要、清空/仅看已选能力或在条件变化时安全清空，防止隐藏选择参与危险操作。
- 必填字符串校验缺失、空字符串和纯空白；空值、主动清空和未修改语义不得混淆。
- Modal/Drawer 验证打开、取消、关闭、销毁/保留策略、焦点和重开状态。
- 文件操作验证类型、大小、空文件、重复提交、文件名和失败恢复。

## 6. 错误与可访问性

- 平台 API 错误处理策略以 [Frontend API Client](frontend-api-client.md#5-平台错误边界) 为权威；本层只负责结束 loading、保留必要输入和已有有效数据、保持必要弹窗，以及避免误刷新或误报成功。
- 未发 API 的表单校验、可信上下文缺失和纯客户端文件校验可以本地提示。
- 未知枚举或依赖数据未加载时阻断相关写操作。
- 外部文本按文本渲染，不使用不受控 HTML；表单标签、按钮语义、键盘和焦点顺序完整。
