# Frontend API Client

本文约束 MedicalRecognition 的 OpenAPI、Kiota 生成包、公开入口和页面适配层。页面不得绕过本规范直接处理底层请求。

## 1. 契约与生成

1. 生成输入来自当前后端稳定 OpenAPI，不使用缓存、历史导出或来源不明 JSON。
2. 明确原始 OpenAPI、预处理脚本、稳定 OpenAPI 和 `kiota-lock.json` 的职责、来源和差异。
3. 同一客户端包按“已交付范围 + 本阶段稳定契约”累计生成，tag/path/operationId 选择须覆盖两者，保留已交付接口；不得只用本阶段范围替换该包的累计范围，也不提前生成后续功能。已暴露或已有生成骨架不等于已交付，持续排除 `/auth/login`。阶段文档中的“本模块生成”仅指本次纳入的稳定契约，均受本条累计规则约束。
4. 契约错误优先修复后端 OpenAPI；预处理规则只能做可重复的工具兼容与稳定化，禁止拼造分页等业务 Shape 来掩盖后端契约错误，不在页面长期猜测兼容。
5. 使用项目既有命令和配置；不手工修改原始/稳定 OpenAPI、`src/api`、`src/models` 等生成契约或生成目录。
6. 未改变契约、预处理或配置时不重复生成，避免无意义换行和大规模差异。
7. 生成前核对同一包已交付接口清单与本阶段稳定契约，生成后按累计范围检查入口、缺失文件、残留端点、无关路径和异常差异，确认已交付接口保留且未提前纳入后续功能；日志、临时文件和本机路径不提交。

## 2. 包与适配层

- 子应用只通过包公开入口和功能 `api.ts` 使用 Client，不依赖生成目录深层路径。
- 请求适配器、认证提供者和 Client 实例由现有 Context/依赖注入统一提供，页面不自行创建。
- 适配层负责请求参数、分页筛选、响应解包、可空归一化和 DTO 到视图模型映射。
- JSX 不散落日期解析、枚举兼容、`?? ''`、`?? []` 和多形态字段猜测。
- 不使用 `any`、双重断言、伪造必填值、字符串拼路径或底层 HTTP 绕过生成 Client。
- mock 返回真实契约形态，不能直接返回页面最终状态绕过适配逻辑。

## 3. 类型、分页与文件

- 明确区分缺失、`undefined`、`null`、空字符串、空数组和业务“无数据”。
- 请求必填字段不得用空字符串、零、空 Guid 或非空断言伪造。
- 日期保持后端时区和精度，展示层才格式化。
- 文件上传下载保留 multipart、binary、content type、文件名和错误边界，不退化为普通 JSON。
- 服务端分页公共请求统一为业务筛选加 `page: { pageIndex, pageSize }`，公共响应统一为 `items` 加 `page: { pageIndex, pageSize, totalCount }`；公共响应不得保留派生字段 `HasNext`，公共契约也不得暴露框架或数据库执行字段 `Pagination`、`SkipCount`、`PageCount`。
- `totalCount` 必须来自后端公共响应；适配层和页面不得补造、截断、字符串化、以零回退，也不得拉取全部数据模拟分页。
- Kiota TypeScript 将后端 `long` 生成为 `number` 时，功能适配层必须校验 `Number.isSafeInteger(totalCount) && totalCount >= 0`；校验失败按契约错误处理，不得继续渲染伪造分页状态。
- 分页参数错误服从第 5 节的平台错误边界；功能适配层和页面不得解析分页错误响应体、异常文本或字段路径来生成专用提示或兼容分支。

## 4. 枚举、组织与认证

- HTTP 保持数字枚举；OpenAPI 提供合法值和成员名称，数值与后端显式定义一致。
- 业务判断使用生成枚举，展示优先使用查询 DTO 的 `XxxText`，筛选表单使用集中缓存的枚举元数据。
- 未知枚举统一安全展示，并阻断依赖已知状态的写操作。
- current API 不提交当前医院/院区作为可信范围，除非接口明确为管理员选择业务对象或对外接口。
- token 和认证由既有适配器与宿主处理，功能适配层不读取、复制或改写。
- 数据范围问题不得通过前端过滤响应掩盖。

## 5. 平台错误边界

适配层不得：

- 新增错误拦截器、ResponseHandler、业务错误配置或页面专用异常对象。
- 解析 `msg/Msg`、`message/Message`、`detail/title`、`errors`、响应体或异常文本生成提示。
- 捕获后重构 `Error`、固定失败字符串，或覆盖/过滤 `MicroSDK.reportApiError`。

只允许处理资源释放、取消请求和已明确设计的非错误状态转换。后端已把外部副作用转为业务状态时，前端按正常响应展示该状态。

## 6. 验证

API Client 变化后至少执行包 typecheck/build，并按影响运行适配层和子应用 test/lint/build。同步检查 OpenAPI 来源、生成配置、锁文件、入口、枚举、nullable、分页、日期、文件以及 `/auth/login` 排除规则。页面行为变化继续执行宿主菜单验收。
